# ユースケースレビュー 004

対象: `spec/usecases/` 配下すべて

## 結果

対応が必要な問題は見つからなかった。

### トレーサビリティ

全 78 シナリオについて、実現するユースケース（またはその組み合わせ）が存在することを確認した。画面のみで完結するもの（ED-05 の編集モード切り替え、OR-02 の表示形式切り替え、DS-03 の文脈切り替えの一部）は、対応するユースケースを持たないことが妥当である旨を確認した。

### 命名

- ユースケース名にドメインの言葉のみを使っている。`〜Page` / `〜Screen` / `〜View` の語彙は含まれない
- 読み取りの合成はいずれも「ノート」「メンバー」「連携」「ジョブ」といったドメインの名詞を持つ。名詞なき合成（画面のデータ一式）はない
- `listMembers` / `listPendingInvitations` は寿命の異なる集合として分離済み

### DTO の完全性

- 入力 DTO はフィールド名・型・必須有無・バリデーションを持つ
- 出力 DTO はフィールド名と型を持ち、原始型のみで構成されている
- ワーカーから呼ばれるユースケースも、`jobId` と対象 ID を明示している

### アーキテクチャ適合性

- ビジネスルールの判定はすべてドメインの振る舞いまたはドメインサービスの呼び出しになっている。ユースケースは順序づけ、ポートの呼び出し、DTO への射影のみを行う
- 権限の判定は `WorkspaceAuthorization` / `NoteAccessPolicy` / `IdentityPolicy` / `MembershipPolicy` に委ねている
- トランザクション境界は `UnitOfWorkProvider.run` に限られ、イベントは `collectEvents` で同一トランザクションに載せている

### エラーの網羅

各ユースケースのエラーケース表が、対応するシナリオの異常系を覆っていることを確認した。存在を漏らさないための共通化（`NOTE_NOT_FOUND` / `INVALID_CREDENTIALS` / `USER_NOT_FOUND`）も一貫している。

### 単一責任

1 つのユースケースが独立した複数の操作を含んでいる箇所はない。`publishWorkspace` / `unpublishWorkspace` は対になる 1 操作として同じ節に記述しているが、実装は別の関数に分かれる。
