# ユースケースレビュー 001

対象: `spec/usecases/` 配下すべて

シナリオ ID を全 78 件と突き合わせた結果、ユースケースが存在しない操作が 4 群あった。

## 1. 書き出し（EX-01〜EX-04）のユースケースが存在しない

ノートを HTML / Markdown / PDF でダウンロードする操作が、どのドメインのユースケースにも定義されていない。`storage.md` の `issueDownloadUrl` は既にある保管ファイルの URL を返すだけで、本文から成果物を作る手順はどこにもない。`job.md` の `JobKind` には `pdfExport` と `bulkExport` があり、`conversion.md` の `MarkdownRenderer.toMarkdown` も定義されているのに、それらを呼ぶユースケースが欠けている。

**対応**: `usecases/note.md` に `exportNote`（即時の HTML / Markdown と PDF ジョブの登録）、`requestBulkExport`、`runNoteExport`、`runBulkExport` を追加する。閲覧者からのダウンロード（EX-04）は `exportNote` が共有トークンと通過証を受け取れるようにして賄う。

## 2. 一括操作（OR-09）の大半にユースケースがない

OR-09 は 6 種類の一括操作（タグ、公開ステータス、移動、バックアップ、ダウンロード、削除）を定義しているが、ユースケースがあるのはバックアップ（`requestBackup`）だけ。`job.md` の `JobKind` には `bulkMove` / `bulkVisibility` / `bulkTag` / `bulkDelete` が並んでいるのに、それらを登録・実行するユースケースがない。

**対応**: `usecases/note.md` に `requestBulkNoteOperation` と `runBulkNoteOperationItem` を追加する。

## 3. 一括アップロードの親ジョブを作るユースケースがない

`storage.md` の `storeUpload` は入力に `parentJobId` を取るが、この ID を発行する経路がどこにもない。IM-02（複数ファイルのまとめてアップロード）で、事前検証・件数と合計サイズの上限判定・親ジョブの登録を行う入口が欠けている。

**対応**: `usecases/storage.md` に `startBulkUpload` を追加し、`storeUpload` との関係を明記する。

## 4. サイトマップが公開ノートしか列挙しない

DS-06 は「公開ノートと公開ページを含むサイトマップを提供する」としており、ページ設計の E-01 も利用者の公開ページ（P-42）と公開ワークスペース（P-43）を含めると定めている。`note.md` の `listSitemapEntries` は公開ノートだけを返す。

**対応**: 利用者とワークスペースの公開ページを列挙する手段を追加する。`identity.md` と `workspace.md` にそれぞれ列挙のユースケースを置き、`listSitemapEntries` の責務をノートに限定する。
