# ユースケースレビュー 002

対象: `spec/usecases/` 配下すべて

## 1. `listNoteCalendar` の名前に画面の語彙が混入している

「カレンダー」は表示形式（OR-02）の名前であり、ドメインの言葉ではない。このユースケースが実際に返すのは「ノートが存在する月の一覧」と「指定期間の日ごとの作成件数」で、カレンダー表示以外からも使える。

**対応**: `countNotesByCreationDate` に改名し、出力の意味を名前に合わせる。

## 2. `listMembers` が名詞なき読み取り合成になっている

`listMembers` はメンバー一覧と保留中の招待一覧という、寿命も権限も異なる 2 つの集合を 1 つの応答にまとめている。これらを束ねる名詞は「メンバー管理画面」しかなく、束ねるのは画面の責務。招待の一覧は owner にしか返さないという分岐も、応答の形を利用者によって変えている。

**対応**: `listMembers` と `listPendingInvitations` に分割する。

## 3. `getNote` が返す `headings` の保持先がドメインに存在しない

`getNote` の処理フローは「見出しは保存時に算出して保持する」としているが、`Note` エンティティにも `NoteContent` にも見出しを保持するフィールドがない。`HtmlProcessor.process` は `headings` を返すものの、保存されないため取得時に再計算するしかない。

**対応**: `NoteContent` の `ready` に `headings` を持たせる。

## 4. `storeUpload` の `visibility` が処理フローに反映されていない

レビュー 001 の対応で `startBulkUpload` を追加した際に `storeUpload` の入力へ `visibility` を加えたが、処理フローには公開ステータスを適用する手順がない。IM-01 はアップロード時に公開ステータスを指定できると定めている。

**対応**: 処理フローに公開ステータスの適用を加え、本文が未生成のうちは公開できないという制約との関係を明記する。
