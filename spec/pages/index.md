# 画面構成

全シナリオを実現するために必要な画面を定義する。各画面には対応するシナリオ ID を添える。

**この文書はユースケース名を書かない**（意図的な記法）。画面とバックエンドの対応づけはシナリオ ID を鍵にして行い、`シナリオ ID → ユースケース` の対応は [usecases/*.md](../usecases/) の各ユースケースの「概要」が持つ。画面からユースケース名を直接名指しすると同じ対応が 2 か所に分かれ、ユースケースの分割・改名のたびに両方を直す必要が生じる。例外は、画面の状態が特定のユースケースの応答フィールドから直接決まる場合（P-15 の再試行の可否、P-23 の `awaitingIntegrationCount` など）で、そこだけは根拠として名指しする。

## 画面の分類

| 区分 | 説明 | 認証 |
| --- | --- | --- |
| 公開 | サインインなしで到達できる | 不要 |
| 認証 | サインイン / サインアップの流れ | 不要 |
| アプリ | サインイン後の作業空間 | 必須 |
| 設定 | アカウント・連携・ワークスペースの設定 | 必須 |

## 共通レイアウト

### L-01: アプリシェル

**目的**: サインイン後のすべての画面に共通する枠。**常設のナビゲーション（サイドバー）を持たない** — 常時提示するのは現在の文脈と処理状況だけで、行き先は 2 つのメニューとコマンドパレットが担う（[ADR 022](../adr/022-command-palette-navigation.md)）。

**機能**

- 上部バー: マーク、スコープトークン、コマンドパレットのトリガー、アップロード、アカウントメニュー。ナビゲーションの一覧を常駐させない
- スコープトークン: 現在の文脈（個人 / ワークスペース名）を常時表示する。**この構造で唯一の「今どこにいるか」の表示なので省略しない**。開くと次が並ぶ（WS-01, WS-02, DS-03, OR-08, ED-10）
  - 文脈の切り替え（個人 / 参加中ワークスペースを 20 件ずつ追加読込）とワークスペース作成
  - 現在の文脈の行き先: タグ管理、ゴミ箱。ワークスペース文脈ではさらにワークスペース設定とその公開ページ
  - 権限で使えない行き先は並べずに消す（ワークスペースの viewer にゴミ箱を出さない）
- コマンドパレット: 全文検索・絞り込み・移動と操作を 1 つの入口に統合する（OR-03〜OR-05, DS-03）。入口は `⌘K` / `Ctrl+K`、上部バーのトリガー、一覧の「絞り込み」チップ。入力欄には現在の文脈を固定表示し、検索も操作もその文脈に閉じることを示す。候補は「ノート → 絞り込み → 移動・操作」の順で並べる
- 処理ティッカー: 実行中ジョブが 1 件以上あるときだけ、中央カラム最上部に 1 行で現れる。件数・代表するファイル名・処理履歴への導線を出し、0 件では要素ごと消える（JB-01）
- アカウントメニュー: プロフィール、自分の公開ページ、処理履歴、設定、サインアウト（AC-07, AC-08, DS-01, JB-01）。処理履歴がここにあるのは `/jobs` が文脈を持たず実行者本人に紐づくためで、ティッカーは 0 件で消えるため恒久的な入口には数えない
- 下端操作バー: 操作の対象が「今開いているもの 1 つ」に定まる画面（P-11, P-12）と、一覧の選択モード（一括操作バー）でのみ現れる
- トースト: ジョブ完了・失敗・操作結果の通知

**到達性の規則**: **パレットにしか入口がない機能を作らない**。すべての機能は、パレット以外に最低 1 つの視覚的な導線（上部バーの 2 つのメニュー、一覧ツールバー、ティッカー、下端操作バー、空状態の CTA のいずれか）を持つ。

**読む画面の変形**: ノート詳細（P-11）とノート編集（P-12）では上部バーを最小化し（前の文脈へ戻る導線とパレットのトリガーのみ）、画面の操作を下端操作バーへ寄せる。P-11 の読む面には操作を置かず、P-12 だけは書式操作のバーを本文の直上に持つ。

**状態**

| 状態 | きっかけ |
| --- | --- |
| 通常 | サインイン済み |
| 文脈読み込み中 | 初回描画・文脈切り替え |
| 処理あり | 実行中ジョブが 1 件以上（ティッカーが現れる） |
| パレット表示中 | `⌘K` / トリガー / 絞り込みチップ（フォーカストラップと `Escape` を持つ） |
| 権限喪失 | 表示中ワークスペースから除名・削除された（個人文脈へ誘導） |
| オフライン | 通信断（保存が保留である旨を表示） |

### L-02: 公開レイアウト

**目的**: サインイン不要の画面に共通する枠。文脈を持たないため、スコープトークンもコマンドパレットも持たない。

**機能**

- ヘッダー: サービス名、公開検索への導線、サインイン / サインアップ
- サインイン済みで訪れた場合はアプリへ戻る導線を表示
- フッター: 利用規約、プライバシーポリシー

**読む画面の変形**: ノートの公開ページ（P-44）と共有リンクのノート（P-45）は、ヘッダーとフッターをそのままに、ダウンロードなどの操作を下端操作バーへ寄せる。本文の左右には何も置かない。

**状態**: 通常 / サインイン済み

### L-03: 認証レイアウト

**目的**: サインイン前の手続き（P-01〜P-06）に共通する枠。まだ文脈も利用者も定まっていないため、スコープトークン・パレット・フッターのいずれも持たない。

**機能**

- 最小のバー: マークのみ（押すとトップへ戻る）
- 中央 1 カラムに手続きのフォームだけを置く

**状態**: 通常

## 認証

### P-01: サインアップ

**目的**: 新規アカウントを作る。
**対応シナリオ**: AC-01, AC-03, WS-04

**機能**

- メールアドレス・パスワードの入力と強度表示
- 利用規約への同意
- 「Google で続ける」
- サインインへの導線
- 招待経由の場合は、招待元ワークスペース名とメールアドレスの初期値を表示

**状態**

| 状態 | きっかけ |
| --- | --- |
| 入力 | 初期表示 |
| 項目エラー | 形式不正・強度不足・未同意（入力中に検出） |
| 送信中 | 送信 |
| 送信完了 | 確認メール送信の案内を表示 |
| 招待経由の完了 | 招待されたメールアドレスのままサインアップ（確認を省いてサインインし、P-06 へ戻る） |
| 全体エラー | レート制限・通信エラー |

### P-02: サインイン

**目的**: 既存アカウントで認証する。
**対応シナリオ**: AC-03, AC-04

**機能**

- メールアドレス・パスワードの入力
- 「Google で続ける」
- パスワード再設定・サインアップへの導線
- 認証後は元の遷移先へ戻る

**状態**

| 状態 | きっかけ |
| --- | --- |
| 入力 | 初期表示 |
| 認証失敗 | 誤り（共通エラー文言） |
| 未確認 | メール未確認のアカウント（再送導線を表示） |
| 待機中 | 連続失敗（`THROTTLED`。待機秒数を示し、待てば再試行できることを案内する。解除方法の案内は出さない） |
| ロック中 | 連続失敗が上限に達した（`LOCKED`。解除時刻と、パスワード再設定による解除を案内する） |
| 送信中 / 成功 | 送信・遷移 |

待機とロックを別の状態として持つのは、示す次の一手が違うためである（待機は「待つ」、ロックは「パスワードを再設定する」）。エラーコードを 2 つに分けている理由は [presentation/index.md](../presentation/index.md) を正典とする。

### P-03: メール確認

**目的**: 確認リンクを処理する。
**対応シナリオ**: AC-02

**機能**: 確認結果の表示、確認メールの再送、サインインへの導線。「確認済み・サインインが必要」は、**確認を要求したブラウザーの印（確認待ち Cookie）が無い、または確認したトークンの持ち主と一致しない**場合に出る（セッションの発行は確認要求元のブラウザーに束縛される。[ADR 029](../adr/029-verification-session-binding.md)）。別のブラウザーで開いた場合が代表例だが、同じブラウザーでも Cookie を消した・プライベートウィンドウで開いた・確認待ち Cookie の寿命（`AuthTokenPurpose.ttlMs("email_verification")`）が尽きた場合に到達する

**状態**: 処理中 / 成功（アプリへ遷移）/ 確認済み・サインインが必要（サインインへ）/ 使用済み（サインインへ）/ 期限切れ（再送。サインインへの導線を再送フォームに従属させて添える）/ 無効（同上）/ 一時障害（再試行）

### P-04: パスワード再設定

**目的**: 再設定の申請と実行。
**対応シナリオ**: AC-05

**機能**

- 申請: メールアドレスの入力
- 実行: 新しいパスワードの入力（2 回）と強度表示

**状態**: 入力 / 送信中 / 申請完了（常に同一文言）/ 実行成功 / トークン無効・期限切れ（再申請へ）

### P-05: OAuth コールバック

**目的**: Google / OpenRouter の認可コードを処理し、元の操作へ戻す。
**対応シナリオ**: AC-03, IN-01, IN-04

**機能**: 処理中の表示と、完了後の遷移先の復元

**状態**: 処理中 / 成功（元の画面へ）/ キャンセル / 失敗（state 不一致・期限切れ・通信エラー）/ スコープ不足（再許可を促す）

### P-06: 招待の確認

**目的**: 招待を受け入れるか判断する。
**対応シナリオ**: WS-04

**機能**: ワークスペース名・説明・付与ロール・招待者・招待先メールアドレスの表示、参加 / 参加しない、未サインイン時の認証への誘導と復帰

**状態**: 表示 / 未サインイン / 期限切れ / 取り消し済み / 使用済み / 参加済み / ワークスペース削除済み / 別アカウントでの受諾確認 / 処理中 / 参加完了

受諾の確認は招待先と閲覧者のメールアドレスが**一致しないときだけ**挟む。一致するなら参加は 1 クリックである。リンクそのものを認可の根拠とする（[usecases/workspace.md](../usecases/workspace.md) の `acceptInvitation`）ため確認は拒否ではなく、別アカウントで参加しようとしていることを気づかせるためのものである。判定はサーバー側で済ませ、閲覧者自身のアドレスはクライアントへ渡さない。

## アプリ

### P-10: ノート一覧

**目的**: 現在の文脈のノートを一覧し、探し、まとめて操作する中心画面。
**対応シナリオ**: OR-01〜OR-10, OR-12, ED-09, DS-03, IM-04, IN-06, EX-02

**機能**

- 表示形式の切り替え（タイル / リスト / カレンダー）と並び順の変更
- 全文検索・タグ絞り込み・月絞り込みの**入口は L-01 のコマンドパレット**で、この画面は独立した検索ボックスを持たない。適用中の条件はチップ列に積まれ、チップがそのまま解除の入口になる。`sm` 未満ではチップ列に絞り込みの集約トリガー（ボトムシート）を置く。月絞り込みとカレンダー表示は**作成日時**（利用者のタイムゾーンで解決した範囲）を軸にする（更新日時が軸の P-41 の期間絞り込みとは基準が異なる）
- タグ管理（P-16）・ゴミ箱（P-14）・公開ページ（P-42 / P-43）へはスコープトークンのメニューから移る（L-01）。この画面はそれらの導線を重ねて持たない。公開タイムラインの表示自体もこの画面では担当しない
- ノートごとのインライン操作（タグ追加、公開ステータス表示、メニュー）。`sm` 以上ではホバーで現れ、`sm` 未満では常時表示する
- 選択モードと一括操作バー（タグ、公開ステータス、移動、バックアップ、ダウンロード、削除）。ワークスペースの viewer には「ダウンロード」のみを出す（他はいずれも editor 以上を要する。バックアップを含む理由は P-11 と同じ）
- 新規作成への導線は一覧ツールバーに置く（ED-01 の起点であり、パレット以外の唯一の視覚的な入口になるため）。アップロードは上部バーが常時露出させる。ファイルのドロップはこの画面で受け入れる

**状態**

| 状態 | きっかけ |
| --- | --- |
| 読み込み中 | 初回・文脈切り替え（一覧形状のスケルトン） |
| 一覧表示 | 取得完了 |
| 追加読み込み中 | スクロール到達 |
| 空（ノートなし） | 0 件（アップロード / 新規作成の導線と、コマンドパレットの使い方の案内を出す。初回サインイン後にパレットの存在を伝える唯一の場なので省略しない） |
| 空（絞り込み結果 0 件） | 条件に一致なし（条件解除の導線） |
| エラー | 取得失敗（再試行） |
| 選択モード | 選択開始（操作バーを表示） |
| 一括操作実行中 | 操作実行（進捗と件数） |
| 一括操作完了 | 成功 / 失敗の内訳を表示。対象から外れたノートがあれば、件数だけでなく**どれがなぜ外れたか**（権限がない / 本文が未生成 / 元ファイルがない）を挙げる（`skipped` の `{ noteId, reason }`） |
| 一括ダウンロード受付不可 | 一括ダウンロードが既に実行中（操作バーのダウンロードを選べない状態にし、完了後に再実行するよう案内する） |

所有文脈の混在に対応する画面状態は持たない。この画面は1つのsource scopeの一覧から選択し、ユースケースもsource ScopeKeyを必須にする。別scope・移動中・削除中のIDが直接要求に混ざった場合は存在を漏らさず個別の`notFound`として表示する。

### P-11: ノート詳細

**目的**: ノートの内容を読み、そのノートに対するすべての操作の起点になる。
**対応シナリオ**: OR-07, OR-11, OR-12, ED-07, ED-09, ED-11, SH-01〜SH-04, SH-08, IM-05, IM-06, IN-06, IN-07, EX-01, JB-02

**機能**

- 本文の描画（`styleMode` に従い、Shadow DOM で隔離）
- タイトルのインライン編集、タグの追加・削除
- 公開ステータスのバッジと共有パネル（リンク発行・コピー・パスワード・再発行・公開範囲の説明）
- メニュー: 編集、表示スタイル、移動、LLM で作り直す、元ファイルから再生成、Drive にバックアップ、ダウンロード、削除。「Drive にバックアップ」は編集側の操作（editor 以上）として扱い、ワークスペースの viewer には出さない（バックアップ記録はノートに紐づく共有状態で、どのメンバーの Drive から再生成の元ファイルを取るかを決めるため。[ADR 004](../adr/004-workspace-roles.md)）。viewer に残るのは「ダウンロード」と表示スタイルのみ
- 元ファイル情報（名前・形式・サイズ・バックアップ状態）
- 見出しの一覧（OR-11 の補助。**本文の直前に折りたたみとして置く**。左右の余白に柱を作らない構造なので、追従する目次レールは持たない）
- 外部参照の取り込み状況の表示。供給元は `getNote` の `references`（[usecases/note.md](../usecases/note.md)）で、**ノートを読める者すべてに、取り込みを実行したのが誰かによらず、ジョブの保持期間と無関係に出る**（[ADR 014](../adr/014-import-result-provenance.md)）。内訳は次の 4 つ
  - 取り込んだ参照リソースの一覧（`imported`）
  - 本文に埋め込んだ外部スタイルシートの件数と配布元（`inlinedStylesheets`）
  - 取り込めずに装飾が失われた外部スタイルシート（`unavailableStylesheets`）。リソースは元の URL のまま表示され続けるのに対し、スタイルシートは本文に埋め込めなかった時点で装飾そのものが失われるため、伝える内容が異なる。併せて「表示スタイル」で既定スタイルを当て直せることを案内する（ED-11）
  - まだ本文に外部 URL のまま残っている参照（`unresolved`）
- 上の各項目には理由（404・タイムアウト・拒否・上限による打ち切り）を添える。理由が引けない場合（一度も取り込みを試みていない、記録が消えている）は理由なしで件数と URL だけを示す。**理由の有無で表示が壊れない形にする** — 構造は本文が、理由は取得記録が供給する別々の経路だからである
- サニタイズで除去された CSS 宣言の表示（`removedCss`）。取り込んだスタイルシートも本文の一部として CSS の内容制約を受けるため、`position: fixed` / `sticky` / `@import` の除去が取り込み結果として報告される（[ADR 013](../adr/013-html-sanitization-policy.md)）。プロパティごとの件数に畳んだ形で届くので、そのまま分類ごとに表示する
- 移動後に旧文脈のアプリ内 URL を開いた場合は、新しい所属先の文脈の URL へ正規化（リダイレクト）する（OR-12）
- PDF のダウンロードは、サインインの有無によらず P-44 / P-45 とまったく同じチケット（署名付きの値）経路で行う。ダウンロードを要求した画面がそのまま進捗を表示し、完了後の受け取りまでを 1 つの経路で完結させる。この画面を離れたあとの受け取りは処理履歴（P-15）が引き受け、そちらはチケットではなくジョブの生成物から期限付き URL を発行する別経路になる（生成物そのものの保持期限まで有効）

**状態**

| 状態 | きっかけ |
| --- | --- |
| 読み込み中 | 遷移直後（本文形状のスケルトン） |
| 表示 | 取得完了 |
| 処理中 | 変換 / 再生成のジョブが実行中（進捗を表示し、完了で本文へ切り替え） |
| 要 LLM 連携 | LLM が必要だが未連携（連携への導線） |
| 変換失敗 | ジョブ失敗（理由と再試行 / LLM で作り直す）。LLM を使わない取り込みで LLM 必須形式だった場合もこの状態で、連携ではなく LLM を使う設定での作り直しを案内する。ゴミ箱への移動・除名・降格・退会・連携解除でジョブが取り消された場合は理由が「取り消し」になり、取り込み直しを案内する |
| 閲覧のみ | 編集権限なし（操作を非表示） |
| 見つかりません | 不在・削除済み・権限なし |
| 操作実行中 | タグ・公開設定・移動などの適用中（楽観的更新と失敗時の巻き戻し） |
| ダウンロード形式選択 | ダウンロード操作（HTML / Markdown / PDF）。HTML / Markdown は即座にダウンロードが始まる |
| ダウンロード生成中 | PDF を選択（画面内に進捗を表示）。進捗の照会と完了後のダウンロードは応答で受け取るチケット（署名付きの値）経由で行い、ノートが閲覧できなくなった時点で「見つかりません」になる |
| 生成に相乗り | 同じノートの PDF が既に生成中（新たな生成は始めず、実行中の生成の進捗表示に合流して同じ結果を受け取る）。保持期間内の生成物がある場合は生成せずにそのまま受け取る |

| ダウンロード不可 | 本文が空（処理中・要 LLM 連携） |

### P-15: 処理履歴

**目的**: 非同期ジョブの状況を確認し、再試行・キャンセルする。
**対応シナリオ**: JB-01〜JB-03, IM-03, EX-03, IN-06

**機能**

- 親ジョブの展開と子ジョブごとの結果
- 失敗理由の表示、再試行、失敗分のみの一括再試行
- 成功したジョブの申し送り（`notices`）の表示。現在の唯一の内容は「取り込み時に指定した公開ステータスを適用できなかった」（公開ハンドル／スラッグが未設定）で、設定への導線を添える。**取り込みの結果はここに出ない** — ノートに帰属する情報はノート詳細（P-11）が持つ（[ADR 014](../adr/014-import-result-provenance.md)）。親ジョブは申し送りを持たないため、一括アップロードで複数件が該当した場合は子を開いて確認する

- 生成物（PDF / ZIP）のダウンロードと期限切れ表示。ここでの受け取りはジョブに紐づく生成物から期限付き URL を発行する経路で、P-11 / P-44 / P-45 のチケット経路とは別（実行者本人の履歴なのでチケットを要さず、生成物そのものの保持期限まで受け取れる）

**状態**: 読み込み中 / 一覧 / 空 / エラー / 実行中あり（自動更新）/ 再試行中 / 組み立て中で再試行不可（一括ダウンロードの親ジョブが ZIP を組み立てている最中に「失敗した分だけ再試行」または子 1 件の再試行を選んだ場合。1 件も再試行されず、完了を待つよう案内する。組み立ては必ず終わるため、親が終端したあとは「再開」の経路で改めて再試行できる）/ 取り消された親で再試行不可（子だけを戻す先がないため、元の操作のやり直しに誘導する）/ 再開（完了・失敗として終わっていた親ジョブが、失敗分の一括再試行または子 1 件の再試行で実行中に戻り、進捗とキャンセルの導線が復活する）/ キャンセル確認 / 期限切れ

### P-25: アカウント削除

**目的**: アカウントと関連データを削除する。**この 1 画面だけが認証ガードの明示的な例外**である — 受理と同時にセッションが消えるため、認証ガードを掛けると進捗を読む画面自体へ到達できない。読み取り権限は削除 status ticket が持ち、`getAccountDeletionStatus` は ticket が名指す 1 件しか返さない。セッションが無い状態では他の導線を描かない（[ADR 047](../adr/047-deletion-status-ticket.md)）。例外は画面の到達性だけで、削除を受理するサーバー関数（`deleteAccountFn`）自体はセッションを要求する。
**対応シナリオ**: AC-09

**機能**: 削除されるもの / されないもの（ワークスペース所有のノートは削除されずそのワークスペースに残り、作成者は「退会した利用者」と表示される）の説明、メールアドレスによる確認入力、実行、削除処理中の進捗表示。要求受理後は即座にサインアウトし、複数workspaceのscope cleanupが完了するまで「削除処理中」とする。唯一のownerが見つかった場合は削除を中止し、再サインイン後に移譲を案内する

**状態**: 説明 / 確認入力 / 確認不一致 / 実行不可（唯一の owner であるワークスペースあり、譲渡・削除への導線）/ 実行中（サインアウト済み。status ticket で進捗を読む）/ 完了（同上）/ 進捗を追えない（status ticket の失効 — 発行から 30 分で、削除が長引けば正常系でも到達する — と無効では追い直せず、ticket を捨ててトップページへの導線だけを出す。進捗取得の一時障害では ticket を保ち、同じ ticket で追い直す導線を出す）

## 公開

### P-40: トップ

**目的**: サービスを知り、公開ノートを探し、利用を始める。
**対応シナリオ**: AC-01, DS-05

**機能**: サービスの説明、公開検索ボックス、サインアップ / サインインへの導線、サインイン済みのリダイレクト（`/` → P-10）。導線の出し分けの分岐は持たない — サインイン済みはリダイレクトでこの画面へ到達しないため

**状態**: 通常 のみ（サインイン済みはノート一覧へリダイレクトするため P-40 に到達しない。URL 割り当ての `/` の行と同じ）

### P-41: 公開検索

**目的**: すべての公開ノートを横断して探す。
**対応シナリオ**: DS-05

**機能**: キーワード検索（2 文字以上で有効）、タグ・期間の絞り込み、関連度順の結果（タイトル・抜粋・著者・更新日時・タグ）。期間は**更新日時**（結果に表示される日時と同じ軸）で絞り込む。閲覧者のタイムゾーンを持てない経路のため境界は UTC で解決する（作成日時が軸の P-10 の月絞り込みとは基準が異なる）

**状態**: 初期（未検索）/ 検索中 / 結果あり / 結果 0 件（条件緩和の提案）/ 検索語不足（1 文字。2 文字以上で検索できる旨を示す）/ レート制限 / エラー

### P-42: 利用者の公開ページ

**目的**: ある利用者の公開ノートを一覧する。
**対応シナリオ**: DS-01, DS-04

**機能**: プロフィールの表示、公開ノートの一覧、タグ絞り込み、ページ内検索

**状態**: 読み込み中 / 一覧 / 空（公開ノートなし）/ 見つかりません（不在・ハンドル変更後の旧 URL・削除済み）/ 本人閲覧（外部向け表示である旨のバナー）

### P-43: ワークスペースの公開ページ

**目的**: 公開ワークスペースの公開ノートを一覧する。
**対応シナリオ**: WS-09, DS-02

**機能**: ワークスペース情報の表示、公開ノートの一覧、タグ絞り込み、ページ内検索

**状態**: 読み込み中 / 一覧 / 空 / 見つかりません（非公開・削除済み・不在スラッグ）/ メンバー閲覧（外部向け表示である旨のバナー）

### P-44: ノートの公開ページ

**目的**: 公開ノートを誰でも読める形で提示する。
**対応シナリオ**: SH-07, DS-06, EX-04

**機能**: 本文の描画（Declarative Shadow DOM）、著者・ワークスペース・タグへのリンク、ダウンロード、メタ情報と構造化データの出力。編集権限を持つ利用者が開いた場合も編集導線は出さない（検索エンジン向けのページとしての意図的な設計。編集はアプリ内のノート詳細 P-11 から行う。SH-07）。編集導線を出す P-45 との違いはここにある

**状態**

| 状態 | きっかけ |
| --- | --- |
| 表示 | 取得完了 |
| 見つかりません | 非公開・限定公開に戻された（公開だったものを含む）／完全削除された／存在しない ID |
| 削除済み | 公開状態のままゴミ箱に入っている（インデックス削除を促す応答）。所有者が復元すれば同じ URL で再び読める |
| ダウンロード形式選択 | 「ダウンロード」を選択（HTML / Markdown / PDF）。HTML / Markdown は即座にダウンロードが始まる |
| ダウンロード生成中 | PDF を選択（画面内に進捗を表示。処理履歴への導線は出さない）。進捗の照会と完了後のダウンロードは応答で受け取るチケット（署名付きの値）経由で行い、ノートが閲覧できなくなった時点で「見つかりません」になる |
| 生成に相乗り | 同じノートの PDF が既に生成中（新たな生成は始めず、実行中の生成の進捗表示に合流して同じ結果を受け取る）。保持期間内の生成物がある場合は生成せずにそのまま受け取る |
| 受け取り期限切れ | チケットの有効期限切れ（期限切れである旨と、ダウンロード操作をやり直す導線。保持期間内の生成物が残っていれば生成し直さずに受け取れる） |
| ダウンロード失敗 | 生成エラー（理由と、ダウンロード操作のやり直しによる再試行の導線） |
| レート制限 | 短時間に繰り返しダウンロードを要求（EX-04） |

**「削除済み」を返す範囲を最小にしている理由**。公開を取り下げた URL にインデックス削除を促す応答を返すと、その ID を知る相手に「そのノートは存在したが今は取得できない」と伝えることになり、公開を取り下げた事実そのものが漏れる。共有リンク（P-45）では「無効・再発行済み・削除・非公開化」を区別せず一律に「見つかりません」とする**存在を漏らさない**原則を既に置いており、公開ページ側だけ区別を設けるのは一貫しない。そこで「削除済み」は、所有者がまだ公開を取り下げていない状態 — 公開のままゴミ箱に入っている場合 — に限る（[usecases/note.md](../usecases/note.md) の `getPublicNote`）。

**既知の限界**。完全削除されたノートの URL には「削除済み」を返せない（行そのものが消え、公開されていた事実を判定できないため）。検索エンジンからの削除は「見つかりません」の応答と、サイトマップ（E-01）から当該ノートが消えることに依存する。

### P-45: 共有リンクのノート

**目的**: 限定公開のノートをリンク保持者に提示する。
**対応シナリオ**: SH-05, SH-06, EX-04

**機能**: 本文の描画、ダウンロード、編集権限がある場合の編集導線、パスワード入力

**状態**

| 状態 | きっかけ |
| --- | --- |
| パスワード要求 | 保護あり・未通過（タイトルも本文も出さない） |
| パスワード誤り | 入力失敗（共通エラー） |
| レート制限 | パスワードの連続失敗、または短時間に繰り返すダウンロードの要求（EX-04） |
| 表示 | 通過またはパスワードなし |
| ダウンロード形式選択 | 「ダウンロード」を選択（HTML / Markdown / PDF）。HTML / Markdown は即座にダウンロードが始まる |
| ダウンロード生成中 | PDF を選択（画面内に進捗を表示。処理履歴への導線は出さない）。進捗の照会と完了後のダウンロードは応答で受け取るチケット（署名付きの値）経由で行い、ノートが閲覧できなくなった時点で「見つかりません」になる |
| 生成に相乗り | 同じノートの PDF が既に生成中（新たな生成は始めず、実行中の生成の進捗表示に合流して同じ結果を受け取る）。保持期間内の生成物がある場合は生成せずにそのまま受け取る |
| 受け取り期限切れ | チケットの有効期限切れ（期限切れである旨と、ダウンロード操作をやり直す導線。保持期間内の生成物が残っていれば生成し直さずに受け取れる） |
| ダウンロード失敗 | 生成エラー（理由と、ダウンロード操作のやり直しによる再試行の導線） |
| 見つかりません | 無効・再発行済み・削除・非公開化 |
| 権限保持者 | 編集権限があるサインイン済み利用者（編集導線を表示） |

**初回描画は必ず「パスワード要求」から始まる**。パスワードを通過した証（SharePass）は Cookie に置かず、クライアントが保持して要求ごとに明示的に載せる（Cookie に置くとブラウザが自動添付するアンビエントな資格情報になり、CSRF の対象になるため。正典は [presentation/index.md](../presentation/index.md)）。したがって保護ありの共有リンクは、通過済みであっても初回のサーバー描画では通過証を参照できず「パスワード要求」で描画され、クライアントが保持している通過証を載せて引き直したうえで「表示」に差し替わる。パスワードを設定していない共有リンクは通過証を要さないため、この遷移は起きず初回の描画から「表示」になる。

### E-01: 検索エンジン向けエンドポイント

画面ではないが、公開区分の成果物として必要になるもの。
**対応シナリオ**: DS-06

| パス | 内容 |
| --- | --- |
| `/sitemap.xml` | 公開ノート（P-44）、利用者の公開ページ（P-42）、公開ワークスペース（P-43）の一覧。件数に応じてサイトマップインデックスに分割する |
| `/robots.txt` | アプリ・設定・認証・共有リンク（`/s/:token`）をクロール対象から除外する |

各公開画面はタイトル・説明・代表画像・正規 URL のメタ情報を出力する。

読めなくなったノートの URL に対する応答は、次のとおり分ける（P-44 の状態表と同じ規則）。

| ノートの状態 | 応答 |
| --- | --- |
| 非公開・限定公開に戻された（公開だったものを含む） | 見つかりません（404 相当） |
| 公開状態のままゴミ箱に入っている | インデックス削除を促す応答（410 相当） |
| 完全削除後 | 見つかりません（404 相当。行が存在せず、公開されていた事実を判定できないため） |

既知の限界として、完全削除されたノートの URL には 410 を返せない。検索エンジンからの削除は 404 の応答と、サイトマップから当該ノートが消えることに依存する。
