# DB レビュー 003

対象: `spec/database/index.md`

## 結果

対応が必要な問題は見つからなかった。

### 永続化先の網羅

9 ドメインのエンティティとポートが必要とする保持先がすべて定義されている。

| エンティティ / 状態 | テーブル |
| --- | --- |
| User / Identity / Session / AuthToken / LoginAttempt | `users`, `identities`, `sessions`, `auth_tokens`, `login_attempts` |
| Workspace / Membership / Invitation | `workspaces`, `memberships`, `invitations` |
| StoredFile | `stored_files` |
| Note / NoteRevision | `notes`, `note_revisions` |
| Tag / TagAssignment | `tags`, `tag_assignments` |
| ExternalConnection / BackupRecord / OAuthFlowState | `external_connections`, `backup_records`, `oauth_flow_states` |
| Job | `jobs` |
| StorageQuota / LlmUsage | `storage_quotas`, `llm_usages` |
| 読み取りモデル | `note_search`, `note_search_fts` |

Conversion は永続状態を持たない。`SharePass` と各種の鍵はテーブルではなく設定・クライアント側で扱う旨を明記済み。

### 型と制約の整合

- 判別ユニオンはすべて「判別子の列 + その値のときだけ非 NULL の列」で表され、CHECK 制約で不整合な組み合わせを禁じている
- 値オブジェクトのバリデーション（長さ・範囲・列挙）に対応する CHECK が置かれている
- 集約ルートのテーブルはすべて `version` を持ち、不変のエンティティ（`note_revisions`, `tag_assignments`, `sessions`）は持たない

### 正規化

書き込みモデルに冗長な列はない。非正規化は `note_search` に閉じており、その根拠は [ADR 009](../../adr/009-read-models.md) に記録されている。

### 性能

主要な問い合わせに対応するインデックスがある。

| 問い合わせ | インデックス |
| --- | --- |
| 一覧の既定順・作成日順・タイトル順 | `note_search_owner_lifecycle_*_idx` |
| 全文検索・タグ絞り込み | `note_search_fts`（trigram） |
| 公開検索・公開ページ | `note_search_public_updated_idx` ほか |
| 共有リンクの解決 | `notes.share_token_hash` の UNIQUE |
| 期限切れの回収（セッション・トークン・生成物・ゴミ箱・ジョブ履歴） | 各テーブルの期限列の部分インデックス |
| 多重実行の抑止・実行中件数 | `jobs_target_active_idx`, `jobs_requester_active_idx` |
| owner の員数確認 | `memberships_workspace_role_idx` |
| タグの使用件数・最終使用日時 | `tag_assignments_tag_assigned_idx` |

### データ整合性

- 同一ドメイン内の親子には外部キーと `ON DELETE CASCADE` を張っている
- ドメインをまたぐ参照は外部キーを張らず、イベント駆動の後始末とし、参照先の不在を「対象が存在しない」として扱う方針を明記している
- 一意制約は、ドメインの不変条件（メールアドレス、ハンドル、スラッグ、`(provider, providerAccountId)`、`(workspace_id, user_id)`、`(scope, normalized)`、`(tag_id, note_id)`、`(note_id, source_file_id)`、`(user_id, provider)`）に 1 対 1 で対応している
