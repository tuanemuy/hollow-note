# DB レビュー 002

対象: `spec/database/index.md`

## 1. FTS5 の外部コンテンツ表が `note_search` の rowid に依存する点が明記されていない

`note_search_fts` は `content='note_search'`, `content_rowid='rowid'` で定義しているため、`note_search` が rowid を持つことが前提になる。`note_search` の主キーは `note_id`（text）なので、`WITHOUT ROWID` で作ると FTS が成立しない。実装者が主キーの型から `WITHOUT ROWID` を選ぶ余地がある。

**対応**: `note_search` を通常の rowid 表として作ること、および同期トリガーの内容を明記する。

## 2. `tag_assignments` に「最終使用日時」を引くためのインデックスがない

`TagQueryService.listWithUsage` は `lastUsedAt`（そのタグが最後に付与された時刻）を返し、`sort: "lastUsedDesc"` も提供する。現在のインデックスは `tag_assignments_tag_idx` (`tag_id`) のみで、タグごとの最大 `assigned_at` を求めるたびに該当行を全走査することになる。

**対応**: `(tag_id, assigned_at DESC)` の複合インデックスに置き換える。

## 3. `listPublicProfiles` の条件がドメインとユースケースで食い違う

`domains/identity.md` の `UserRepository.listPublicProfiles` は「`ActiveUser` かつ `handle` が設定されている利用者」を返すとしているが、`usecases/identity.md` の同名ユースケースは「公開ノートを 1 件以上持つもの」という条件を足している。後者は `users` テーブルだけでは判定できず、公開ノートの有無は読み取りモデル `note_search` にある。

**対応**: サイトマップに載せるのは公開ノートを持つ利用者に限るという要件を優先し、この列挙を `NoteQueryService` 側の責務に移す。`UserRepository.listPublicProfiles` は削除する。
