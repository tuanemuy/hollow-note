# 006. ノートの正データはサニタイズ済み HTML の 1 つとし、編集モードはその上の見え方とする

## ステータス

承認済み

## コンテキスト

idea.md では、あらゆる形式のファイルを HTML に変換して保存し、さらに 3 種類のエディタ（ビジュアル / HTML / WYSIWYG）で編集できるとされている。

編集モードごとに別の表現（Markdown、エディタ固有の JSON など）を正データとして持つと、モードを切り替えるたびに往復変換が必要になり、変換のたびに情報が失われる。とりわけ HTML ファイルをそのまま取り込むという要件とは相性が悪い。

## 決定

- ノートの本文はサニタイズ済みの HTML 断片 1 つだけを正データとして保持する
- 3 つの編集モードは、いずれもこの HTML を読み書きする別々の見え方にすぎない
  - ビジュアル: テキストノードのみを書き換える。構造・属性は保持される
  - HTML: ソースを直接書き換える
  - WYSIWYG: リッチテキストとして解釈して書き戻す。表現できない要素は失われうるため、事前に警告し、直前の版を保持する
- サニタイズは保存時に必ず行う。`script`、イベントハンドラー属性、危険なスキームの URL を除去し、除去した内容を利用者に提示する
- Markdown は入力形式であり出力形式でもあるが、保持はしない。取り込み時に HTML へ変換し、書き出し時に HTML から生成する
- 編集のたびに版を記録し、直近 20 版から復元できる

## 検討した代替案

### Markdown を正データにする

編集も差分も扱いやすいが、HTML ファイルをそのまま取り込むという中心的な要件を満たせない。装飾された HTML を Markdown に落とすと情報が失われる。不採用。

### エディタ固有の文書モデル（ProseMirror の JSON 等）を正データにする

WYSIWYG 編集は最も安定するが、任意の HTML を表現できず、取り込んだ HTML の構造が編集前から失われる。不採用。

### モードごとに別の表現を持ち、最後に使ったモードの表現を正とする

各モードの編集体験は最良になるが、「このノートの本文は何か」が状態依存になり、書き出し・検索・公開表示のすべてが分岐する。不採用。

## 影響

- サニタイズの規則を 1 か所に集約し、取り込み・編集・メディア挿入のすべてで同じ規則を適用する
- WYSIWYG モードは情報損失を伴いうるため、警告と「元に戻す」を必須の体験として設計する
- ビジュアルモードは要素の追加・削除ができないという制約を利用者に明示する
- 全文検索は HTML からテキストを抽出した結果に対して行う
- 書き出し（HTML / Markdown / PDF）はすべて同じ HTML を入力とする
- 版の保持により、再生成（IM-06 / IN-07）や WYSIWYG 保存で内容が失われても復旧できる
