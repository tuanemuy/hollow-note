# 028. 認証の応答は登録の有無で差を作らない — 内容・所要時間・エラー種別のすべてで

## コンテキスト

サインアップとサインインは「そのメールアドレスが登録済みか」を漏らしうる。漏れる経路は応答の内容だけではない。

1. サインアップの出力にはユーザー ID が含まれる。既登録メールで実在の ID を返すと、それ自体が存在の証拠になる
2. 未登録メール、およびパスワード認証手段を持たない利用者の経路は、パスワードハッシュの検証を実行せずに即座に失敗する。ハッシュ検証は数十ミリ秒かかるため、**応答時間で登録済みかどうかを列挙できる**
3. 一意性の予約ポートは衝突で `ConflictError` を投げる。直前の失敗が残した予約（TTL つき）や、同一メールの並行要求では、この衝突がそのまま応答へ透過する
4. 待機を求める応答（スロットル / ロック）には待機秒数と解除時刻を添える必要があるが、アプリケーション層のエラーが持つ構造化ペイロードは `fieldErrors` しかない

## 決定

### 応答の内容を揃える

サインアップは既登録メールでも未登録と同一の応答を返す。ユーザー ID は decoy を採番して返す。

### 一意性の強制はポート、列挙耐性はユースケース

一意性 directory は衝突で `ConflictError` を投げ続ける。これはポート契約として保持し、適合スイート（[ADR 026](./026-port-contract-and-conformance.md)）で検証する — アダプターを差し替えたときに一意性が守られていることの検証は必要である。ユースケース側がこれを捕捉し、既登録メール経路と同一の応答へ畳む。**列挙耐性はユースケース層の責務**とする。

### 所要時間を揃える

パスワード認証情報が無い経路でもダミーのハッシュ検証を実行して所要時間を揃える。ダミー検証はスロットル判定の**後**に置く — スロットル / ロックの応答は等時化しない。判定自体がメールの登録有無に依存せず発動するため、時間差は登録の有無を漏らさない。

ダミーのハッシュはハッシュ実装のインスタンスを鍵にした `WeakMap` に memo し、ハッシュ実装は DI でランタイム単位のシングルトンにする（要求ごとに生成すると、未認証の試行のたびに鍵導出が走り、等時化のためのコストが DoS 面になる）。

ダミー検証は**失敗しても必ず「不一致」を返す**契約とし、失敗時はキャッシュを空に戻して次回リトライできるようにする。等時化は best-effort な防御であって、認証判定の結果を変えてよい根拠にはならない。ここを守らないと、ハッシュ生成が一度失敗しただけで「未登録メールだけが 500 を返す」というより強いオラクルに反転し、しかも再起動まで直らない。

### 比較とパラメータのガード

トークンハッシュの比較は定数時間で行う。ドメインは framework-free なので、crypto プリミティブを使わず全バイトの XOR を蓄積する純関数として実装する。

保存済みハッシュから読み出したコストパラメータには上限ガードを置き、範囲外は検証失敗として扱う。DB の改竄や移行事故で 1 レコードから巨大なメモリー確保が起きるのを防ぐ、DB の内容を信頼しない多層防御である。

### 構造化データの運び方

待機秒数と解除時刻は `fieldErrors` に載せ、presentation はそこから表示を組む。セッションを発行しない経路のために、セッショントークンは `null` を許容する形にする。

## 検討した代替案

### 既登録メールにはそのままエラーを返す

利用者には最も親切で、実装も最短。しかしメールアドレスの登録有無が誰でも列挙できるようになる。本サービスは個人のノートを扱うため、在籍の露見そのものが被害になる。

### 一意性の衝突をポート側で握りつぶす

ユースケースの例外捕捉が要らなくなる。しかしポートの一意性契約が検証できなくなり、アダプター差し替えの検証対象を失う。層の責務としても、応答の見せ方は永続化ポートの関心ではない。

### 固定の待機時間で所要時間を揃える

実装は単純。しかし実測のばらつき（負荷、ハッシュコストの変更）に追随せず、閾値を跨いだ瞬間に差が復活する。ダミー検証は本物と同じ計算をするので、コストを変えても自動的に揃う。

### ダミーハッシュをモジュール変数に memo する

最も安い。しかし memo がハッシュ実装のインスタンスと無関係になるため、実装を差し替えても最初の 1 個が使い回される。さらに promise をそのまま置くと、生成が一度でも失敗したとき失敗した promise が恒久的に居座る。

## 影響

- 未登録メールの経路にもハッシュ 1 回分の CPU コストがかかる
- コストパラメータのガード値は、ハッシュコストを引き上げるときの連動更新点になる
- `fieldErrors` を「フィールドのエラー」以外にも使う軽い流用が入る。値は構造化データの取り出し元としてのみ使い、文字列として画面に出さない
- ユースケースに例外の捕捉が 1 か所増える。「例外は境界でだけ捕まえる」原則に対しては、応答同一化という明示的な保証を守るための限定的な捕捉と位置づける
- 等時化の失敗は応答に現れないため、ログの観測点が別途要る
