# 030. 認証状態を変える経路は POST に限り、サインアウトはフル遷移で行う

## コンテキスト

サインアウトは、サーバー側の行を消さず Cookie を破棄するだけでも成立してしまう操作である。しかし「サーバーの状態を変えない」ことは「安全に GET にしてよい」を意味しない。

- GET リンクで実装すると、`SameSite=Lax` はトップレベルの GET に Cookie を添えるため、外部サイトのリンクを踏ませるだけでログアウトを強制できる
- クライアントルーターは loader の取得結果をキャッシュしており、SPA 遷移ではそれが残る。サインアウト後に前の利用者のデータが画面に出うる。個別に無効化して回る方針は、キャッシュ全域の追跡が必要で漏れやすい

## 決定

- 認証状態を変える経路は、サーバーの行を変更しない場合でも JSON POST の server function とする。GET には置かない
- サインアウトはフル遷移（`window.location.assign`）で行い、ページごと破棄してルーターのキャッシュとメモリー上の状態を物理的に消す

## 検討した代替案

### サインアウトを GET リンクにする

最も単純で、JS なしでも動く。しかし外部リンクからのログアウト強制が成立する。

### SPA 遷移のまま、キャッシュを選択的に無効化する

遷移の体感は保てる。しかし「消し忘れたキャッシュ」は前の利用者のデータが漏れる形の欠陥であり、対象の列挙を人手で維持し続ける前提になる。ページを捨てれば列挙は不要になる。

### 認証済みルートの loader キャッシュを無効にする

残存の問題は消えるが、通常の閲覧のたびに再取得が発生し、キャッシュの利点を全経路で失う。

## 影響

- サインアウトだけ SPA 遷移でなくなる。認証境界の遷移としては許容する
- 前の利用者のデータが残る経路が構造的に消え、無効化対象の列挙が不要になる
- 認証状態を変える操作を追加するときは、サーバー側の書き込みの有無にかかわらず POST 経路として書く
