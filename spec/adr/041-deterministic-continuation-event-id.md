# 041. 継続イベントの ID は生成元から決定的に導出し、キーはターンごとに変える

## ステータス

承認済み

## コンテキスト

継続要求は「1 ターン処理して次を保存する」形で運ぶ（[ADR 040](./040-continuation-transport.md)）。保存時に採番した ID を使うと、ack のトランザクションで応答を失って再実行したときに継続チェーンが**2 本**走る。同じ仕事が二重に進み、以降のターンも枝分かれし続ける。

一方、決定的なキーには罠がある。cursor を持たない継続（削除そのものが対象を母集合から外していく形）は、次ページを表す継続が**現在処理中のイベントとまったく同じキー**になる。リレーはハンドラーの正常終了後に同じ行へ処理済みを書くので、「積んだばかりの次の継続」を直後の完了処理が消す。

## 前提

同じ id の再保存が先着行を残す no-op であること（[ADR 042](./042-outbox-save-id-collision.md)）。配送が at-least-once で、消費側が冪等であること。

## 決定

- 継続イベントは payload に**決定キー**（イベント種別・operation ID・phase・cursor の連結）を持ち、採番時にそのキーからイベント ID を導出する。キーを持たない draft は通常どおり採番する
- 導出は**採番者（アダプター）側の関心**なので、共有の関数を 1 つ置いて各アダプターが呼ぶ。ドメイン・ユースケースの署名は変えない
- **キーはターンごとに変わらなければならない。** 同じ phase を繰り返す継続には、ターンを識別する材料（cursor・ページ番号）をキーに含める。それが作れない継続（cursor を持たないもの）には決定キーを**持たせない**。冪等性はその処理自身の性質（削除は再実行しても終端が同じ）で担保する
- **1 つの継続イベントが 1 ターンを完全に記述する。** 再開位置はイベント自身が運ぶ。ヘッダー側の位置だけで再開すると、phase の最終ページを再配送されたときに位置が初期値へ戻っているため、その phase を先頭から開き直す
- **待ち合わせの再試行は自分自身を再発行しない。** 必須受領が揃うのを待つ終端処理は、受領を完成させうる各枝が「発行元名」をキーに載せて試行を積む。同一キーの上書きにならないので、配送中の行を消す競合が構造的に起きない。終端処理は冪等なので、複数の枝が積んでも害は無い

## 検討した代替案

### 保存時採番のまま、重複を消費側で吸収する

消費の重複排除だけで済む。しかしチェーンが 2 本走るという事実は残り、以降のターンが独立に進む。吸収できるのは同じイベントの重複であって、枝分かれではない。

### すべての継続に決定キーを与える

規則が単純になる。しかし cursor を持たない継続では、積んだ次のターンを直後の完了処理が消して**チェーンが止まる**。適用条件をキー設計の言葉で明示するほうが安全。

### 待ち合わせの終端処理が自分を再発行する（polling）

主体が 1 つで済む。しかし同一キーの再保存になるので、配送中の行を上書きして直後の完了処理に消される競合を踏む。

## 影響

- 応答喪失後の再実行が継続を増殖させない、という不変条件が両平面で成立する
- payload に運搬用の項目が 1 つ増える
- 継続を足すたびに「何をターン識別子にするか」の設計判断が要る。ここを誤ると、増殖ではなく**停止**の側に倒れる
- 決定キーを持たない継続は、再配送で系列が一時的に 2 本になりうる（いずれも同じ終端へ収束する）
