# 027. 投影世代は UoW 内で採番してドメインへ引数で渡し、route 版を運ぶ `note.moved` は移動サガが発行する

## コンテキスト

`note.created` のイベント payload は投影世代（`projectionRevision`）を、`note.moved` は route 版（`routeVersion`）を含む。どちらも読み取りモデルの購読者が「古いイベントで新しい状態を上書きしない」ために使う値である。

しかしこれらの採番者はドメインではない。投影世代は投影世代ストア、route 版は route ストアが採番する。一方でエンティティのファクトリとメソッドは自分でイベントのドラフトを組み立てる（ドメインがイベントの形の正本である）。値の供給経路が必要になる。

さらに「投影対象の状態を変える UoW は、正データの保存と同じトランザクションで投影世代を bump する」という規約がある。UoW のコンテキストに bump の経路がないと、コンテナ側のポートをコールバックの中から呼ぶことになり、同一トランザクション性が実バックエンドで保証されない（in-memory では実行文脈からトランザクションを拾えてしまうため、この欠陥は in-memory テストでは現れない）。

## 決定

- 採番した値は**ドメインメソッドの引数**として渡す。`Note.createBlank` / `createFromUpload` は `projectionRevision` を受け取り、ユースケースが UoW の中で採番して渡す。`routeVersion` を運ぶ `note.moved` はドメインメソッドの成果物ではなく（`Note.withOwner` はエンティティだけを返す）、route の切替を所有する移動サガが採番した版とともに発行する
- 投影世代ストアを scope の UoW コンテキストに載せる。bump は UoW の中からしか呼べない

## 検討した代替案

### ドメインが組み立てたドラフトを application 層で後から書き換える

ドメインのシグネチャは spec のままに保てる。しかしドラフトの不変性と「ドメインがイベントの形の正本」という原則が崩れ、イベントの最終形がドメインとユースケースの 2 か所に分かれる。

### 投影世代ストアをコンテナに置き、UoW のコールバックから呼ぶ

コンテキストの形を変えずに済む。しかし同一トランザクション性が型にも実装にも現れず、in-memory では通って実バックエンドで壊れる種類の欠陥になる。

### イベント payload から採番値を落とす

ドメインは純粋なまま、供給経路も要らない。しかし購読者が順序の逆転を検出できなくなり、読み取りモデルが古い状態に巻き戻る経路が開く。

## 影響

- イベント payload が spec どおりの形で型付けされ、ドメインは純粋関数のままでいられる
- UoW コンテキストの形が「同一トランザクションで行うべき操作」の契約になる。以降、投影対象を変えるユースケースはすべて同じ経路を通る
- ドメインのメソッド表に、spec には現れない引数（`projectionRevision`）が生成のファクトリ 2 つに増える
