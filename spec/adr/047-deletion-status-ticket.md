# 047. 削除の進捗チケットは presentation が署名し、application は操作 ID と状態だけを返す

## ステータス

承認済み

## コンテキスト

アカウント削除は要求の受理と同時にセッションを失効させるため、利用者は自分の削除の進捗を読む手段を失う。読ませるには「その 1 件だけを読める短命な資格」が要る。

これを application が作ると、application が署名鍵と transport の形（HTTP ヘッダー / Cookie / body）を知ることになり、「エラーは transport の関心を持たない」と同型の原則に反する。

同種の資格は既に別の経路にもある（[ADR 010](./010-anonymous-export-and-ticket.md) の署名チケット）ので、扱いを揃える必要がある。

## 前提

鍵を配備が供給できること（composition root がランタイムへ渡す形が既にあること）。進捗の読み取りが 1 件に閉じていること。

## 決定

- application は `{ 操作 ID, 状態 }` だけを返す。**チケットの発行と検証は presentation が担い、鍵は composition root が供給する。** SSR メタデータを運ぶ設定の器に秘密を混ぜず、presentation が環境変数を直読みもしない。未設定ならプロセス毎のランダム鍵へ落とす配備もありうる（その場合の失効を画面が説明する）
- **チケットの claims は操作 ID と期限だけ**とし、その 1 件の状態読み取り以外の権限を持たせない。表示の復元に主体の識別子が要る場合も、claims ではなくクライアント側の退避レコードに並べて持つ（権限を広げる材料を署名済みトークンへ入れない）
- Cookie ではなく応答 body で返し、クライアントが保持する。セッションを破棄した直後に、別の自動送信クレデンシャルを増やさない
- **進捗を読む画面は認証を要求できない。** 受理と同時にセッションが消える以上、認証ガードを掛けるとその画面自体へ到達できない。読み取りの権限はチケットが持つので、この 1 画面だけをガードの明示的な例外にし、セッションが無い状態では他の導線を描かない
- 失効の理由は「署名が合わない / 形が壊れている」と「期限切れ」に分ける（利用者に出す文言が違う）。期限の判定は**署名検証を通った後にだけ**行う（偽造が期限切れとして返らない）。恒久的な失効ではクライアント側の退避を捨てる（復元 → 即失敗の輪から抜けられるようにする）。HTTP ステータスの特例は増やさない — クライアントの振る舞いが変わらないため
- 退避は **best-effort** とする。ストレージが使えない環境（サイトデータを遮断した設定）では読み書きが例外を投げるので、受理の表示を退避より**先**に出し、退避の失敗は握り潰す。取り消せない操作が「失敗した」ように見えるほうが害が大きい
- 復元は「保存時の主体と今の主体が一致する」または「今のセッションが無い」ときだけ行う。前者は同じタブで別の利用者がサインインした場合の誤表示を防ぎ、後者は受理でセッションを失った当人の復帰経路そのものになる

## 検討した代替案

### application がチケットを発行する

層をまたぐ受け渡しが減る。しかし application が署名鍵と transport の形を知ることになり、配備ごとに違う運搬手段へ結び付く。

### チケットを Cookie で運ぶ

保持と送信をブラウザーに任せられる。しかしセッションを破棄した直後に自動送信されるクレデンシャルを増やすことになり、同種の資格の扱いとも不揃いになる。

### 進捗画面にも認証を要求する

ガードの例外を作らずに済む。しかし受理でセッションが消える以上、正常系の 1 手目で必ず弾かれる。

### claims に主体の識別子を入れる

復元の判定がチケットだけで完結する。しかし署名済みトークンは暗号化されていないので、クライアントから読める識別子が増える。判定が決めるのは「このタブの表示を復元してよいか」だけなので、権限を広げてまで入れる理由が無い。

## 影響

- 受理から完了表示までのあいだ、ルーターのキャッシュにはサインアウト済みのペイロードが残る（同じタブの同じ利用者しか見られず、離脱時のフル遷移で破棄される）
- この 1 経路だけが「ミューテーションのあとに必ずルーターを再基底化する」規律の例外になる。再基底化の役割は、完了表示に到達したあとのフル遷移が担う（[ADR 030](./030-auth-state-transition-transport.md)）
- 鍵が未設定の配備ではプロセス再起動でチケットが失効する。画面は「ページを閉じても削除は進む」ことを説明する
- 退避に失敗したことは利用者に見えない。リロードすると進捗を追えなくなるが、そのときの案内は失効時の表示が持つ
