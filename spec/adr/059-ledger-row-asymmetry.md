# 059. 台帳の DOM 行と ADP 行の非対称は、主張が本文に由来するときだけそろえる

## ステータス

承認済み

## コンテキスト

同じポートメソッドは `spec/inventory/domain.md` に DOM 行、`spec/inventory/adapter.md` に ADP 行を 1 行ずつ持つ。どちらも `spec/domains/` を生成元とする台帳なので、「実装されるべき振る舞いの要点」欄は本来同じことを言う。実際には片側にしか無い主張を持つ組がある。

「薄い側へ 1 句足してそろえる」を機械的に当てると、**本文（`spec/domains/*.md` の interface と説明段落）に書かれていない主張を台帳へ書き足す**組が出る。`ObjectStorage.put` の「既存 key は上書きする」がその例で、適合スイートは拘束しているが `spec/domains/storage.md` の `ObjectStorage` 節にその記述は無い。台帳は本文の生成物なので、書き足せば台帳が本文を追い越す。逆に ADP 行から落とせば、実装が担保している契約を spec から消すことになる（[ADR 046](./046-port-contract-divergence.md)）。

## 前提

`spec/inventory/*.md` が `spec/domains/` からの生成物であり、台帳が本文に無い主張を持たないこと。

## 決定

片側にしか無い主張について、**その主張が本文に由来するか**で決める。

- **由来するなら薄い側へ 1 句足す。** interface の型や説明段落が既に言っていることを、台帳の片側だけが落としている場合がこれに当たる（戻り値の型が書いている「未知の key では null を返す」、アダプター向けの説明段落が書いている取得順の未規定など）
- **由来しないなら足さず、そのまま残す。** 書き足せば台帳が本文を追い越し、落とせば spec を狭める。どちらの向きも採らず、本文を直すかどうかの判断は契約を決めるスライスへ渡す
- **言い換えの差と、アダプター実装者だけに向いた注記は非対称ではない。** 前者は同じ主張であり、後者（「DB 側に一意制約を置くのは自由だが、契約としては要求しない」など）は `adapter.md` にあることが正しい

## 検討した代替案

### 食い違う組をすべて機械的にそろえる

一貫して見え、検査も単純になる。しかし本文に無い主張を DOM 行へ運ぶことになり、`spec/inventory/` が宣言する「本文からの生成物」という性質が崩れる。台帳が本文を追い越す欠陥を、別の行で作り直すことになる。

### DOM 行と ADP 行は同文であることを不変として書く

差分検査を機械化できる。しかしアダプター実装者だけに向けた注記が書けなくなり、`adapter.md` の情報量が落ちる。台帳の 2 面が別の読者を持つという事実に反する。

### 本文へ主張を書き足して非対称を消す

台帳の非対称も同時に消える。しかし本文へ主張を足すことは契約の拡張であり、正本がどちらにあるか（[ADR 046](./046-port-contract-divergence.md)）が定まらないうちは下せない判断である。

## 影響

- 台帳の対称化に上限が付き、「本文に無い主張を台帳に書く」向きへ滑らない
- 残す非対称に理由が付くので、同じ組を次に数え直しても判定が変わらない
- 「本文に由来するか」の判定には本文の読みが要り、機械検査にはできない
- 本文に無いまま ADP 行にだけ主張が残る箇所がある（`ObjectStorage.put` の上書き契約）。適合スイートが拘束しているので実害は小さいが、`spec/domains/storage.md` だけを読んだ実装者には見えない
