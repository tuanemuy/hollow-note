# アカウント（AC）

登録・認証・プロフィール・退会に関するシナリオ。認証手段の扱いは [ADR 001](../adr/001-authentication-strategy.md) に従う。

## AC-01: メールアドレスとパスワードでアカウントを作成する

**利用者**: 未登録の訪問者
**事前条件**: なし

### 基本フロー

1. トップページで「はじめる」を選ぶ
2. サインアップ画面でメールアドレスとパスワードを入力する
3. 利用規約への同意にチェックを入れて送信する
4. 「確認メールを送信しました」という案内が表示される
5. 受信したメールのリンクを開くと、メールアドレスが確認済みになりサインイン状態でノート一覧に着地する
6. ノートが 1 件もないため、最初のファイルをアップロードするよう促す案内が表示される

### 異常系・エッジケース

- メールアドレスの形式が不正 / パスワードが強度要件（長さ・文字種）を満たさない場合、該当項目にその場でエラーを表示し送信させない
- 既に登録済みのメールアドレスの場合、アカウントの存在を外部に漏らさないため画面上は同じ「確認メールを送信しました」を表示し、実際には「このアドレスは既に登録済みです」という案内メールを送る
- 利用規約に同意しないまま送信しようとした場合、送信を抑止して同意欄を強調する
- 確認前に再度サインアップを試みた場合は、確認メールを再送する
- 短時間に大量のサインアップ試行があった場合はレート制限し、しばらく待つよう案内する
- ワークスペースの招待リンク（WS-04）から、招待されたメールアドレスのままサインアップした場合は、確認メールを送らずに確認済みとして扱う。異なるメールアドレスを入力した場合は通常どおり確認を求める

## AC-02: メールアドレスを確認する

**利用者**: 確認待ちの利用者
**事前条件**: AC-01 でアカウントを作成済み

### 基本フロー

1. 確認メールのリンクを開く
2. 確認が完了し、サインイン状態でノート一覧に遷移する

### 異常系・エッジケース

- リンクの有効期限（24 時間）が切れている場合、期限切れである旨と再送ボタンを表示する
- リンクが既に使用済みの場合、確認済みである旨を伝えてサインイン画面へ誘導する
- リンクが改ざんされている / 存在しない場合、無効なリンクである旨と再送導線を表示する
- 確認が済むまではセッションを発行しない。未確認のままサインインしようとした場合は、確認が必要である旨と再送導線を表示する（AC-04 と同じ扱い）
- 確認メールが届かない場合に備え、サインイン画面と設定画面の両方から再送できる。再送には間隔制限（60 秒）を設ける

## AC-03: Google アカウントでサインアップ / サインインする

**利用者**: 未登録の訪問者 / 登録済みの利用者
**事前条件**: なし

### 基本フロー

1. サインイン画面で「Google で続ける」を選ぶ
2. Google の同意画面でアカウントを選び、基本プロフィールのスコープを許可する
3. サービスに戻り、初回であればアカウントが作成され、2 回目以降は既存アカウントにサインインする
4. ノート一覧に着地する

### 異常系・エッジケース

- Google 側で同意をキャンセルした場合、サインイン画面に戻り「キャンセルされました」と表示する
- 同じメールアドレスのパスワードアカウントが既に存在し、そのメールアドレスが確認済みの場合、Google の Identity を既存ユーザーに紐づけてサインインさせる
- 同じメールアドレスのパスワードアカウントが存在し未確認の場合、乗っ取りを防ぐため自動紐づけせず、先にメールアドレスの確認を完了するよう案内する
- Google から返るメールアドレスが未確認の場合は連携を拒否する
- 認可コードの交換に失敗した場合（state 不一致、期限切れ、通信エラー）、サインイン画面でやり直しを促す
- Drive のスコープはこの段階では要求しない（IN-04 で増分認可する）

## AC-04: メールアドレスとパスワードでサインインする

**利用者**: 登録済みの利用者
**事前条件**: パスワードの Identity を持つ

### 基本フロー

1. サインイン画面でメールアドレスとパスワードを入力する
2. 認証に成功し、直前に開こうとしていた画面（なければノート一覧）に遷移する

### 異常系・エッジケース

- メールアドレスまたはパスワードが誤っている場合、どちらが誤りかを区別しない共通のエラーを表示する
- 連続して失敗した場合は段階的に待ち時間を設け、一定回数を超えたら一時的にロックして解除方法（パスワード再設定）を案内する
- パスワードの Identity を持たない（Google のみで登録した）アカウントのメールアドレスが入力された場合も同じ共通エラーを表示し、「Google で続ける」への導線を併記する
- 未確認のアカウントの場合、確認が必要である旨と再送導線を表示する
- 保護されたページに直接アクセスして弾かれた場合、サインイン後に元のページへ戻す

## AC-05: パスワードを再設定する

**利用者**: パスワードを忘れた利用者
**事前条件**: なし

### 基本フロー

1. サインイン画面で「パスワードをお忘れですか」を選ぶ
2. メールアドレスを入力して送信する
3. 「再設定メールを送信しました」と表示される
4. メールのリンクを開き、新しいパスワードを 2 回入力して確定する
5. 完了後、他のすべてのセッションが無効化され、新しいパスワードでサインインする

### 異常系・エッジケース

- 未登録のメールアドレスでも、存在を漏らさないため同じ完了メッセージを表示する（メールは送らない）
- リンクの有効期限（1 時間）切れ・使用済み・改ざんの場合は、無効である旨と再申請の導線を表示する
- パスワードの Identity を持たないアカウントの場合、「Google でサインインしてから設定画面でパスワードを追加してください」と案内するメールを送る
- 新しいパスワードが強度要件を満たさない / 2 回の入力が一致しない場合はその場でエラー表示する
- 再設定リンクの発行はメールアドレス単位でレート制限する

## AC-06: ログイン方法を追加・変更・解除する

**利用者**: サインイン済みの利用者
**事前条件**: なし

### 基本フロー

1. 設定画面の「ログイン方法」を開く
2. 現在有効な方法（パスワード / Google）の一覧を確認する
3. 未設定の方法があれば「追加」を選ぶ
   - パスワード: 新しいパスワードを 2 回入力して設定する
   - Google: 認可フローを通して紐づける
4. パスワードが設定済みの場合は「変更」を選び、現在のパスワードと新しいパスワードを入力して更新する
5. 不要な方法は「解除」を選び、確認ダイアログを経て削除する

### 異常系・エッジケース

- 有効なログイン方法が 1 つしかない場合、解除ボタンを無効化し、理由を添える
- 追加しようとした Google アカウントが既に別の利用者に紐づいている場合、その旨を伝えて追加を拒否する
- パスワードを追加する際は、現在のセッションの再認証（Google 再認可）を求める
- パスワードを変更する際は現在のパスワードの入力を求め、誤っている場合は共通のエラーを表示する
- パスワードを変更すると、他のすべてのセッションを無効化する（現在のセッションは維持する）
- 新しいパスワードが強度要件を満たさない / 2 回の入力が一致しない場合はその場でエラー表示する
- Google の連携を解除しても、Google Drive 連携（IN-04）は独立して残る。解除時にその旨を明示する

## AC-07: プロフィールと公開ハンドルを編集する

**利用者**: サインイン済みの利用者
**事前条件**: なし

### 基本フロー

1. 設定画面の「プロフィール」を開く
2. 表示名、アイコン画像、自己紹介、公開ハンドル（公開ページの URL に使う一意の文字列）を編集する
3. 保存すると、公開ページとタイムラインの表示に反映される

### 異常系・エッジケース

- 公開ハンドルが既に使用されている場合、入力中に重複を検出して代替候補を提示する
- 公開ハンドルに使えない文字・予約語（`settings`, `api`, `login` 等）が含まれる場合は保存を拒否する
- アイコン画像がサイズ上限（5 MB）や対応形式（PNG / JPEG / WebP）を外れる場合はアップロード前に弾く
- 公開ハンドルを変更すると旧 URL は失効する。変更前にその旨を警告する
- 公開ハンドルを未設定のまま公開ノートを持とうとした場合、公開操作時にハンドルの設定を求める

## AC-08: サインアウトする

**利用者**: サインイン済みの利用者
**事前条件**: なし

### 基本フロー

1. ヘッダーのアカウントメニューから「サインアウト」を選ぶ
2. セッションが破棄され、トップページに遷移する

### 異常系・エッジケース

- 未保存の編集がある状態でサインアウトしようとした場合、破棄してよいか確認する
- 設定画面から「他のすべての端末からサインアウト」を選べる。現在のセッションは維持される
- 既にセッションが期限切れの場合も、エラーにせずトップページへ遷移させる

## AC-09: アカウントを削除する

**利用者**: サインイン済みの利用者
**事前条件**: なし

### 基本フロー

1. 設定画面の最下部から「アカウントを削除」を選ぶ
2. 削除されるもの（ノート、アップロードしたファイル、タグ、連携）と、削除されないもの（バックアップ先の Google Drive 上のファイル）の説明を読む
3. 確認のため自分のメールアドレスを入力する
4. 実行すると即座にサインアウトされ、アカウントと関連データが削除される

### 異常系・エッジケース

- 自分が唯一の owner であるワークスペースが存在する場合、先に他のメンバーへ owner を譲渡するか、ワークスペースを削除するよう促し、削除を進めさせない
- 確認入力のメールアドレスが一致しない場合は実行しない
- 実行中に処理中のジョブ（変換、バックアップ、一括ダウンロード）がある場合は、それらをキャンセルしてから削除する
- 削除後、公開・限定公開だったノートの URL はすべて 404 を返す

## AC-10: 使用量を確認する

**利用者**: サインイン済みの利用者
**事前条件**: なし

### 基本フロー

1. 設定画面の「使用量」を開く
2. 個人の保存容量の使用量と上限、ノート件数が表示される
3. owner または editor として参加しているワークスペースについても、ワークスペースごとの使用量と上限が表示される
4. 当月の LLM 実行回数と上限が表示される

### 異常系・エッジケース

- 上限の 80 % を超えている項目は警告として強調する
- 上限に達している場合、新しいアップロードが拒否される旨と、不要なノートの削除（ED-09 / ED-10）への導線を示す
- ゴミ箱の中のノートも使用量に数える。その旨を明記する
- 使用量の集計は一定の遅延を伴いうる。最終更新時刻を添える
