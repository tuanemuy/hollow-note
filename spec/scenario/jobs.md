# 処理（JB）

時間のかかる処理はすべて非同期のジョブとして実行される（[ADR 005](../adr/005-async-processing.md)）。ここでは、ジョブの状況を確認・再試行・キャンセルする横断的なシナリオを扱う。

## ジョブの種類

| 種類 | 発生元 | 生成物 |
| --- | --- | --- |
| 取り込み（変換） | IM-01 / IM-02 | ノートの本文 |
| 再生成 | IM-06 / IN-07 | ノートの本文 |
| 参照リソースの取り込み | IM-05（取り込みの一部） | 保存されたリソースと差し替え後の本文 |
| Drive バックアップ | IN-06 / OR-09 / 自動バックアップ | Drive 上のファイル |
| PDF 生成 | EX-01 / EX-04 | PDF ファイル（24 時間保持） |
| 一括ダウンロード | EX-02 / OR-09 | ZIP ファイル（7 日保持） |
| 一括移動 | OR-09 | なし |
| 一括の公開ステータス変更 | OR-09 | なし |
| 一括タグ付け・タグ外し | OR-09 | なし |
| 一括削除 | OR-09 / ED-10 | なし |

一括操作は「親ジョブ 1 件 + 対象ごとの子ジョブ」に分解される。

## JB-01: 処理の状況を確認する

**利用者**: ジョブを開始した利用者
**事前条件**: 1 件以上のジョブがある

### 基本フロー

1. 実行中のジョブがあると、中央カラムの最上部に 1 行のティッカーが現れ、件数と代表するファイル名が表示される。実行中が 0 件のときはティッカーごと現れない
2. ティッカーの「処理履歴」から処理履歴の画面へ移動する。実行中が 0 件でも、アカウントメニューから処理履歴を開ける
3. 処理履歴には、種別・対象・状態（待機中 / 実行中 / 完了 / 失敗 / キャンセル済み）・開始日時・所要時間が新しい順に並ぶ
4. 親ジョブを開くと、子ジョブごとの結果を確認できる
5. ジョブが完了・失敗するとトーストで通知され、ティッカーの件数から外れる

### 異常系・エッジケース

- ジョブが 1 件もない場合は空状態を表示する
- 失敗したジョブには、利用者に説明できる理由（未対応の形式 / 破損 / 連携なし / LLM なしでは取り込めない / モデルエラー / 容量超過 / LLM 実行回数の上限超過 / タイムアウト / 権限失効 など）を表示する
- 「キャンセル済み」は失敗ではなく独立した状態で、理由を持たない。キャンセル操作や連携解除・除名・ロールの降格などで処理が外から止められたことを表す。取り込み中だったノートの本文には「処理が取り消されました」と表示され、取り込み直しまたは再試行の導線を出す
- 画面を離れてもジョブは継続する。再訪時には最新の状態を表示する
- 実行が中断された処理（サービス側の異常などで実行中のまま応答がなくなったもの）は、一定時間後にタイムアウトによる失敗として記録され、再試行できる状態になる。中断された処理が自動で引き継がれて再開されることもあり、その場合は試行回数が 1 回消費される
- 履歴は 90 日を過ぎたものから削除される。その旨を明示する
- 生成物（PDF / ZIP）が保持期間を過ぎたものは「期限切れ」として表示し、再実行の導線を出す
- ジョブは他の利用者には見えない。ワークスペースのノートに対するジョブでも、実行者本人にのみ表示する
- サインインしていない閲覧者による PDF 生成（EX-04）は処理履歴には現れず、ダウンロード操作を行った画面内の進捗表示で完結する
- 実行中の件数が多い場合、待機中のものは待機中として表示する

## JB-02: 失敗した処理を再試行する

**利用者**: ジョブを開始した利用者
**事前条件**: 失敗したジョブがある

### 基本フロー

1. 処理履歴、またはノート詳細の失敗表示から「再試行」を選ぶ
2. 同じ対象・同じ設定で新しいジョブが登録される
3. 親ジョブの画面からは、失敗した子ジョブだけをまとめて再試行できる
4. 失敗した子だけを再試行すると、いったん完了 / 失敗として終わっていた親ジョブは再び実行中に戻り、進捗が計算し直される

### 異常系・エッジケース

- 失敗の原因が解消されていない場合（連携が未接続のまま等）、再試行の前に原因の解消を促す導線を出す
- 対象のノートやファイルが削除されている場合、再試行できない旨を示す
- 対象への権限を失っている場合、再試行できない旨を示す
- 同じジョブの多重実行は抑止する
- 一括ダウンロードの親ジョブが ZIP の組み立てに入っている間は、失敗した子だけの再試行を受け付けない。1 件も再試行せず、完了を待ってからやり直すよう案内する（組み立ては必ず終わるため、親が完了または失敗として終わったあとに改めて再試行でき、そこから組み立てもやり直される）
- 完了済み・キャンセル済みのジョブは再試行ではなく、元の操作をやり直す形で扱う

## JB-03: 処理をキャンセルする

**利用者**: ジョブを開始した利用者
**事前条件**: 待機中または実行中のジョブがある

### 基本フロー

1. 処理履歴から対象のジョブを選ぶ
2. 「キャンセル」を選び、確認のうえ実行する
3. 待機中の子ジョブは取り消され、既に実行中のものは完了を待って結果を残す
4. 状態が「キャンセル済み」になり、内訳（完了 / 取り消し）が表示される

### 異常系・エッジケース

- 既に完了・失敗しているジョブはキャンセルできない。ボタンを出さない
- ただし、失敗した子の再試行で処理中に戻った親ジョブ（JB-02）は、再びキャンセルできる状態になる
- キャンセルしても、それまでに作成されたノートや取り込み済みのファイルは残る。その旨を確認時に示す
- 一括ダウンロードをキャンセルした場合、中間生成物は破棄する
- 再生成（IM-06 / IN-07）をキャンセルした場合、ノートの本文は変更前のまま維持する
- アカウント削除・ワークスペース削除・連携解除・メンバーの除名・自らの脱退・ロールの降格・対象ノートのゴミ箱への移動に伴って、関連するジョブは自動でキャンセルされる。理由は JB-01 の「取り消し」として表示される
