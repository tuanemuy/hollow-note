# 整理（OR）

ノートの一覧表示・検索・タグ付け・一括操作に関するシナリオ。

## OR-01: ノート一覧を表示する

**利用者**: 所有者 / メンバー
**事前条件**: サインイン済み

### 基本フロー

1. サインイン後、既定でノート一覧が表示される
2. 現在の文脈（個人 / ワークスペース）に属するノートが更新日時の新しい順に並ぶ
3. 各ノートはサムネイル（本文の先頭部分から生成）、タイトル、更新日時、タグ、公開ステータスとともに表示される
4. スクロールすると続きが読み込まれる

### 異常系・エッジケース

- ノートが 1 件もない場合、アップロードと新規作成への導線を含む空状態を表示する
- 絞り込みの結果が 0 件の場合は、条件を解除する導線つきの空状態を表示する
- 読み込み中は一覧の形に合わせたスケルトンを表示する
- 読み込みに失敗した場合、再試行の導線つきのエラーを表示する
- 変換処理中のノートは処理中であることを示し、開いても本文はまだない旨を表示する
- 「要 LLM 連携」状態のノートはその旨のバッジを表示する

## OR-02: 表示形式を切り替える（タイル / リスト / カレンダー）

**利用者**: 所有者 / メンバー
**事前条件**: ノート一覧を表示している

### 基本フロー

1. 一覧上部の表示形式スイッチから形式を選ぶ
2. タイル: サムネイルを大きく並べる
3. リスト: 1 行 1 件で、タイトル・タグ・更新日時・公開ステータスを密に並べる
4. カレンダー: 月表示で、作成日ごとにノートを配置する
5. 選んだ形式は次回以降も引き継がれる

### 異常系・エッジケース

- カレンダー表示では月の切り替えができる。月の絞り込み（OR-05）と状態を共有する
- カレンダーの 1 日に多数のノートがある場合、上限数まで表示して「他 N 件」で展開する
- カレンダー表示では並び順（OR-10）の指定を無効にする
- 表示形式は URL に反映され、共有・再訪時に復元される

## OR-03: 全文検索でノートを探す

**利用者**: 所有者 / メンバー
**事前条件**: ノート一覧を表示している

### 基本フロー

1. コマンドパレット（⌘K / Ctrl+K、上部バーのトリガー、一覧の「絞り込み」チップのいずれか）を開く。独立した検索ボックスは画面に常駐しない
2. キーワードを入力すると、現在の文脈のノートをタイトルと本文で検索した結果が「ノート」の候補として並ぶ。入力欄の左には現在の文脈が固定表示され、検索がその文脈に閉じることが入力前から分かる
3. 各結果に、一致箇所の抜粋がハイライトつきで表示される
4. 候補を選ぶとそのノートが開き、検索語を条件として一覧に持ち帰るとチップ列に積まれてタグ・月の絞り込みと組み合わせられる

### 異常系・エッジケース

- 一致が 0 件の場合、絞り込み条件（タグ・月）を解除する提案を含む空状態を表示する
- 検索の対象は現在の文脈に限られる。他のワークスペースを探す場合は文脈を切り替える必要がある旨を空状態に添える
- 検索語が短すぎる（1 文字）場合は検索を実行しない。2 文字以上で検索できる
- 日本語のように単語区切りのない文章でも部分一致できる
- 英数字の語は語頭からの一致で探す。単語の途中だけを指定した検索（`flare` で `Cloudflare`）は一致しない（`cloud` なら一致する）
- 変換処理中で本文がないノートはタイトルのみが検索対象になる
- 検索条件は URL に反映され、共有・再訪時に復元される
- 検索が一定時間内に完了しない場合、タイムアウトして再試行を促す

## OR-04: タグで絞り込む

**利用者**: 所有者 / メンバー
**事前条件**: ノート一覧を表示している

### 基本フロー

1. 一覧のサイドまたはフィルター領域に、文脈内で使われているタグが使用頻度順に並ぶ
2. タグを選ぶと、そのタグを持つノートに絞り込まれる
3. 複数選んだ場合は、すべてを持つノート（AND）に絞り込まれる
4. 選択したタグはチップとして表示され、個別に解除できる

### 異常系・エッジケース

- タグが 1 件もない場合、タグ領域は空状態を表示する
- タグが多い場合は検索して探せる
- 絞り込み中に対象タグがすべてのノートから外れた場合、結果は 0 件になり条件解除の導線を出す
- 選択したタグは URL に反映される

## OR-05: 月で絞り込む

**利用者**: 所有者 / メンバー
**事前条件**: ノート一覧を表示している

### 基本フロー

1. フィルター領域の月セレクターで年月を選ぶ
2. その月に作成されたノートに絞り込まれる
3. 選択は解除できる

### 異常系・エッジケース

- ノートが存在しない月は選択肢に出さない、または件数 0 として示す
- カレンダー表示中は、表示中の月と絞り込みの月が連動する
- 利用者のタイムゾーンで月の境界を判定する

## OR-06: 一覧からノートにタグを付ける

**利用者**: 所有者
**事前条件**: 対象ノートの編集権限がある

### 基本フロー

1. 一覧のノートにポインターを合わせるとタグ追加のボタンが現れる
2. 選ぶと入力欄が開き、既存タグの候補が使用頻度順に表示される
3. 入力すると候補が絞り込まれる。一致する候補がない場合は「"○○" を作成」が選べる
4. 選ぶと即座にタグが付き、一覧の表示に反映される
5. 付いているタグはその場で外せる

### 異常系・エッジケース

- 付与・削除は楽観的に画面へ反映し、失敗した場合は元に戻して理由を表示する
- 既に付いているタグは候補で選択済みとして示し、重複して付かない
- タグ名の前後の空白は取り除き、大文字小文字と全角半角の違いを同一視して重複作成を防ぐ
- タグ名の長さ上限（50 文字）と、1 ノートあたりのタグ数上限（50 個）を設ける
- 編集権限がない場合、タグ追加のボタンを出さない
- ワークスペースのタグは、そのワークスペース内で共有される。個人のタグは個人内で閉じる

## OR-07: ノート詳細でタグを付ける

**利用者**: 所有者
**事前条件**: 対象ノートの編集権限がある

### 基本フロー

1. ノート詳細のタグ領域で「タグを追加」を選ぶ
2. OR-06 と同じ入力・候補・新規作成の操作でタグを付ける
3. 付いたタグを選ぶと、そのタグで絞り込んだ一覧へ移動できる

### 異常系・エッジケース

- OR-06 と同じ制約・エラー処理に従う
- 閲覧者にはタグを表示するが編集操作は出さない

## OR-08: タグを整理する（リネーム・削除・統合）

**利用者**: 所有者 / ワークスペースの owner・editor
**事前条件**: サインイン済み

### 基本フロー

1. 設定またはフィルター領域から「タグを管理」を開く
2. タグの一覧が使用件数つきで表示される
3. タグ名を変更すると、そのタグが付いたすべてのノートに反映される
4. タグを削除すると、すべてのノートから外れる（ノートは消えない）
5. 既存のタグと同じ名前に変更した場合は統合するかを確認し、統合すると両方のノートが片方のタグにまとめられる

### 異常系・エッジケース

- 削除は影響件数を示して確認する
- 使用件数 0 のタグは一括で片付けられる
- 変更後の名前が空 / 空白のみの場合は拒否する
- 権限のない利用者には管理画面を出さない

## OR-09: 複数のノートを選択して一括操作する

**利用者**: 所有者 / メンバー
**事前条件**: ノート一覧を表示している

### 基本フロー

1. 一覧で選択モードに入り、チェックで複数のノートを選ぶ。全選択もできる
2. 画面下部に操作バーが現れ、選択件数と実行できる操作が表示される。操作は利用者の権限に応じて絞られる
   - タグを付ける / 外す
   - 公開ステータスを変更する
   - 所属先を移動する（個人 ↔ ワークスペース）
   - Drive にバックアップする
   - ダウンロードする
   - 削除する
3. 操作を選ぶと、必要に応じて確認ダイアログを経て実行される
4. 完了後、成功件数と失敗件数の内訳が表示される

### 異常系・エッジケース

- viewer は選択と一括ダウンロードのみ行える。それ以外の操作は操作バーに表示しない
- 選択の中に権限のないノートが混ざる場合、その操作を無効化するか、対象外として件数を示す
- 移動先で編集権限がない場合は移動先の選択肢に出さない（[ADR 003](../adr/003-note-ownership-model.md)）
- 移動によって閲覧できなくなる利用者が出る場合、その旨を警告する
- 移動時のタグの扱いは OR-12 と同じ（移動先に同名のタグがあれば付け替え、なければ外れる）
- 公開への一括変更は、公開ハンドル未設定なら設定を促して中止する
- 一部が失敗しても他は継続し、失敗分の理由を一覧できる
- 一度に選択できる件数の上限（500 件）を超える場合は分割を促す
- 絞り込み中の「全選択」は、絞り込み結果全体を対象とするかどうかを明示して選ばせる
- 選択したまま絞り込みを変更した場合、選択は解除する

## OR-10: 並び順を変える

**利用者**: 所有者 / メンバー
**事前条件**: ノート一覧を表示している

### 基本フロー

1. 一覧上部の並び順セレクターから選ぶ（更新日時 / 作成日時 / タイトル、それぞれ昇順・降順）
2. 選択が即座に一覧へ反映される
3. 選択は URL に反映され、次回以降も引き継がれる

### 異常系・エッジケース

- 検索中は関連度順も選べる。既定は関連度順
- カレンダー表示中は無効化する
- タイトル順は日本語を含む文字列でも安定した順序で並ぶ

## OR-11: ノートを開いて内容を読む

**利用者**: 所有者 / メンバー
**事前条件**: 対象ノートを閲覧できる

### 基本フロー

1. 一覧、検索結果、またはタイムラインからノートを選ぶ
2. ノート詳細が開き、タイトル・本文・タグ・公開ステータス・更新日時・作成者が表示される
3. 本文は `styleMode`（ED-11）に従って描画される
4. 編集権限があれば、編集・共有・タグ付け・移動・ダウンロード・削除の操作が表示される
5. 元ファイルがある場合は、その名前・形式・サイズと、バックアップの状態が表示される

### 異常系・エッジケース

- 変換処理中のノートを開いた場合、進捗と「完了すると本文が表示される」旨を示し、完了時に自動で本文へ切り替える
- 「要 LLM 連携」の状態のノートは本文の代わりに連携への導線を表示する
- 変換に失敗したノートは失敗の理由と再試行（JB-02）の導線を表示する。内容を作り直したい場合の導線として LLM での再生成（IM-06）も併記する
- 閲覧権限を失った状態で開いた場合、「見つかりません」を表示する
- 存在しない / 削除済みのノートも「見つかりません」を表示する
- 本文が非常に長い場合も一度に読み込み、目次相当の見出し一覧を補助として表示する
- 読み込み中は本文の形に合わせたスケルトンを表示する

## OR-12: ノートの所属先を移動する

**利用者**: 所有者
**事前条件**: 移動元での編集権限と、移動先での編集権限をどちらも持つ（[ADR 003](../adr/003-note-ownership-model.md)）

### 基本フロー

1. ノート詳細のメニューから「移動」を選ぶ
2. 移動先の候補（個人、および editor 以上で参加しているワークスペース）が一覧される
3. 移動先を選ぶと、移動後に誰が閲覧できるようになるか / できなくなるかが具体的に示される
4. 確定すると即座に移動する。公開ページと共有リンクの URL は変わらない（アプリ内でのノートの URL は、新しい所属先の文脈のものに変わる）

### 異常系・エッジケース

- viewer としてのみ参加しているワークスペースは候補に出さない
- 移動元のタグは移動先には引き継がれない（タグは文脈ごとに独立しているため）。引き継がれない旨を事前に示し、同名のタグが移動先にあれば付け替える
- 移動によってワークスペースのメンバーがノートを見られなくなる場合、その旨を警告する
- 変換処理中・再生成中のノートは移動できない。理由を示す
- 移動先で権限を失っていた場合（移動の確定時点で除名されていた等）、移動を拒否して理由を示す
- 複数ノートの移動は OR-09 で行う
