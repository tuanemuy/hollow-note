# 共有（SH）

ノートの公開ステータスの管理と、閲覧者による閲覧に関するシナリオ。

## 公開ステータスと閲覧できる人

| ステータス | 個人所有のノート | ワークスペース所有のノート |
| --- | --- | --- |
| 非公開（既定） | 所有者本人のみ | ワークスペースのメンバー全員（viewer を含む） |
| 限定公開 | 上記に加えて、共有リンクを知っている人 | 上記に加えて、共有リンクを知っている人 |
| 公開 | 誰でも。公開タイムライン・公開検索・検索エンジンの対象になる | 同左。ワークスペースが公開されていればその公開ページにも並ぶ |

限定公開の共有リンクには任意でパスワードを設定できる。

## SH-01: ノートの公開ステータスを変更する

**利用者**: 所有者
**事前条件**: 対象ノートの編集権限がある

### 基本フロー

1. ノート詳細の「共有」を開く
2. 現在のステータスと、そのステータスで誰が見られるかの説明が表示される
3. 別のステータスを選ぶ
4. 限定公開を選ぶと共有リンクが発行される（SH-02）
5. 公開を選ぶと、公開タイムラインと検索の対象になる旨の確認が出る
6. 変更は即座に反映される

### 異常系・エッジケース

- 公開に変更しようとしたときに公開ハンドル（AC-07）が未設定の場合、設定を促し、完了後に元の操作へ戻る。ワークスペース所有のノートは、公開ハンドルの代わりにワークスペースの公開ページ用スラッグ（WS-01 / WS-07）の設定有無で判定する
- 変換処理中・「要 LLM 連携」で本文が空のノートは公開できない。理由を示す
- 公開から非公開に戻すと、共有リンクも無効になり、公開タイムラインからも消える。検索エンジンのインデックス削除には時間がかかる旨を添える
- 限定公開から非公開に戻すと共有リンクは無効になる。再度限定公開にすると同じリンクが復活する（SH-04 で再発行しない限り）
- ワークスペース所有のノートを公開する場合、ワークスペース自体が非公開でもノートは公開される。その旨を説明に含める
- 権限のない利用者には共有パネルを読み取り専用で表示する

## SH-02: 限定公開の共有リンクを取得する

**利用者**: 所有者
**事前条件**: 対象ノートが限定公開または公開である

### 基本フロー

1. ノート詳細の「共有」を開く
2. 共有リンクが表示され、「コピー」でクリップボードにコピーできる
3. コピーされたことがその場で示される

### 異常系・エッジケース

- 非公開のノートでは共有リンクを表示せず、限定公開への変更を促す
- クリップボードへのアクセスが許可されていない場合、リンクを選択可能なテキストとして表示する
- 共有リンクは推測できない十分な長さのトークンを含む

## SH-03: 共有リンクにパスワードを設定する

**利用者**: 所有者
**事前条件**: 対象ノートが限定公開である

### 基本フロー

1. 共有パネルで「パスワードで保護する」をオンにする
2. パスワードを入力して保存する
3. 以降、共有リンクを開いた閲覧者にはパスワードの入力が求められる
4. 設定済みのパスワードは変更・解除できる

### 異常系・エッジケース

- パスワードが強度要件（8 文字以上）を満たさない場合は保存を拒否する
- 設定済みのパスワードは画面に再表示しない。変更するには新しい値を入力する
- パスワードを解除すると、リンクを知る全員が即座に閲覧できるようになる旨を確認する
- パスワードを変更すると、既にパスワードを通過した閲覧者のアクセス権も失効する
- 公開ステータスのノートにはパスワードを設定できない（設定済みのまま公開に変更した場合はパスワードを解除する旨を確認する）

## SH-04: 共有リンクを無効化・再発行する

**利用者**: 所有者
**事前条件**: 共有リンクが発行されている

### 基本フロー

1. 共有パネルの「リンクを再発行」を選ぶ
2. 既存のリンクが使えなくなる旨の確認を経て実行する
3. 新しいリンクが発行され、古いリンクは無効になる

### 異常系・エッジケース

- 古いリンクを開いた閲覧者には、SH-05 と同じ共通の「見つかりません」を表示する（存在の有無を区別しない）
- 公開ステータスを非公開に変更した場合も同じ扱いになる
- 再発行してもパスワードの設定は維持される

## SH-05: 共有リンクからノートを閲覧する

**利用者**: 閲覧者（サインイン不要）
**事前条件**: 有効な共有リンクを持っている

### 基本フロー

1. 共有リンクを開く
2. ノートの本文が、既定のスタイル（GitHub の Markdown 相当）または元の HTML の装飾を保った状態で表示される
3. タイトル、著者の表示名、更新日時、タグが表示される
4. ダウンロードのボタンからノートを保存できる（EX-04）

### 異常系・エッジケース

- リンクが無効 / 削除済み / 非公開に戻されている場合、共通の「見つかりません」を表示する（存在の有無を区別しない）
- パスワードが設定されている場合は SH-06 に従う
- 限定公開のノートは検索エンジンにインデックスさせない
- 閲覧者にはコメント・編集の操作を出さない
- サインイン済みで、かつそのノートの編集権限を持つ利用者が共有リンクを開いた場合は、編集導線を表示する
- 本文中の外部リソースが取得できない場合も、本文自体は表示する

## SH-06: パスワード保護されたノートを閲覧する

**利用者**: 閲覧者（サインイン不要）
**事前条件**: パスワード保護された共有リンクを持っている

### 基本フロー

1. 共有リンクを開くと、パスワードの入力画面が表示される
2. 正しいパスワードを入力すると本文が表示される
3. 通過した状態は一定期間（24 時間）その端末で保持され、再入力を求められない

### 異常系・エッジケース

- パスワードが誤っている場合、共通のエラーを表示する
- 連続して失敗した場合はレート制限をかける
- 所有者がパスワードを変更・解除した場合、保持していた通過状態は失効する
- パスワード入力画面ではノートのタイトルや本文の断片を表示しない
- 保持期間が切れた場合は再度入力を求める

## SH-07: 公開ノートを閲覧する

**利用者**: 閲覧者（サインイン不要）
**事前条件**: 対象ノートが公開である

### 基本フロー

1. 公開タイムライン、公開検索、外部の検索エンジン、または直接の URL からノートを開く
2. 本文が表示される
3. 著者の公開ページ、ノートに付いたタグ、（ワークスペース所有なら）ワークスペースの公開ページへのリンクが表示される
4. ダウンロードのボタンからノートを保存できる

### 異常系・エッジケース

- 非公開に戻された・削除されたノートの URL は「見つかりません」を返す
- 検索エンジン向けのメタ情報（タイトル、説明、代表画像）を出力する
- 本文の HTML はサニタイズ済みのものを表示し、スクリプトは実行しない
- 公開ページには編集導線を表示しない。編集権限を持つ利用者が開いた場合も同様で、編集はアプリ内のノート詳細（OR-11）から行う（検索エンジン向けのページとしての意図的な設計）
- 著者が公開ハンドルを変更した場合、旧 URL は失効する

## SH-08: ノートの公開範囲を確認する

**利用者**: 所有者 / メンバー
**事前条件**: 対象ノートを表示している

### 基本フロー

1. ノート詳細と一覧のどちらにも、公開ステータスを示すバッジが表示される
2. バッジを選ぶと、現在の設定で誰が閲覧できるかが具体的に説明される（例: 「ワークスペース『設計』のメンバー 5 名とリンクを知っている人」）
3. パスワード保護の有無、共有リンクの有無もあわせて示される

### 異常系・エッジケース

- 権限のない利用者には設定操作を出さず、表示のみとする
- 所属先の移動（OR-12）を行うと閲覧できる範囲が変わる。移動時にその旨を警告する
- ワークスペースのメンバー数はメンバー本人にのみ表示する
