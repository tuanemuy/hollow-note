# 発見（DS）

公開されたノートを見つけるためのタイムラインと横断検索に関するシナリオ。

## タイムラインの種類

| 種類 | 対象 | 見られる人 |
| --- | --- | --- |
| 個人の公開タイムライン | ある利用者が所有する公開ノート | 誰でも（`/@ハンドル`） |
| ワークスペースの公開タイムライン | あるワークスペースが所有する公開ノート | 誰でも（ワークスペースが公開の場合のみ、`/w/スラッグ`） |
| 作業用の一覧 | 現在の文脈で自分がアクセスできる全ノート | 本人 / メンバーのみ（OR-01） |

作業用の一覧と公開タイムラインは別のものであり、切り替え（DS-03）は文脈（個人 / ワークスペース）の切り替えを指す。

## DS-01: 自分の公開タイムラインを確認する

**利用者**: サインイン済みの利用者
**事前条件**: 公開ハンドルを設定している

### 基本フロー

1. アカウントメニューから「公開ページを見る」を選ぶ
2. 外部から見えるとおりの自分の公開ページが表示される（公開ノートのみ、新しい順）
3. 「これは外部に公開されている表示です」というバナーと、設定への導線が表示される

### 異常系・エッジケース

- 公開ハンドルが未設定の場合、設定画面へ誘導する
- 公開ノートが 0 件の場合、空状態と「ノートを公開する方法」の案内を表示する
- ワークスペース所有の公開ノートは、個人の公開ページには並ばない（所有者が異なるため）。その旨を空状態の説明に含める

## DS-02: ワークスペースの公開タイムラインを確認する

**利用者**: メンバー
**事前条件**: 対象ワークスペースが公開である

### 基本フロー

1. ワークスペース設定の「公開」から公開ページへの導線を選ぶ
2. WS-09 と同じ内容が表示され、外部向けの表示であるバナーが出る

### 異常系・エッジケース

- ワークスペースが非公開の場合、公開に切り替える導線を示す
- 公開ノートが 0 件の場合は空状態を表示する

## DS-03: タイムラインを切り替える

**利用者**: サインイン済みの利用者
**事前条件**: なし

### 基本フロー

1. 上部バーのスコープトークン（WS-02）で「個人」または参加中のワークスペースを選ぶ
2. 選んだ文脈の一覧に切り替わる
3. 公開タイムラインへは、個人ならアカウントメニューの「自分の公開ページ」から、ワークスペースならスコープトークンのメニューから移る。作業用の一覧へは同じ経路で戻る

### 異常系・エッジケース

- 切り替えの前後で表示形式（OR-02）と並び順（OR-10）は引き継ぐ
- 絞り込み条件は文脈ごとに独立しているため引き継がない
- 切り替え先で権限を失っていた場合は、その旨を表示して個人の文脈へ戻す

## DS-04: 他の利用者の公開ページを見る

**利用者**: 閲覧者（サインイン不要）
**事前条件**: 対象の利用者が公開ハンドルを設定している

### 基本フロー

1. 公開ノートの著者名、または直接の URL（`/@ハンドル`）から公開ページを開く
2. 表示名・アイコン・自己紹介と、公開ノートの一覧が表示される
3. タグでの絞り込みと、そのページ内の検索ができる
4. ノートを選ぶと SH-07 の表示へ遷移する

### 異常系・エッジケース

- 存在しないハンドル、削除済みのアカウントは「見つかりません」を返す
- 公開ノートが 0 件の場合は空状態を表示する
- ハンドルが変更された場合、旧 URL は「見つかりません」を返す

## DS-05: 公開ノートを横断検索する

**利用者**: 閲覧者（サインイン不要）
**事前条件**: なし

### 基本フロー

1. トップページまたは検索ページの検索ボックスにキーワードを入力する
2. 全利用者・全ワークスペースの公開ノートを対象に検索した結果が、関連度順に表示される
3. 各結果にタイトル、抜粋、著者、更新日時、タグが表示される
4. タグと期間で絞り込める。タグは所属先をまたいで名前で一致させる。期間は**更新日時**（結果に表示される日時と同じ軸）で絞り込む。個人のノート一覧の月絞り込み（OR-05）が作成日時を軸にするのとは基準が異なる

### 異常系・エッジケース

- 一致が 0 件の場合、条件を緩める提案つきの空状態を表示する
- 非公開・限定公開のノートは対象に含めない
- 公開から外されたノートは検索結果から取り除かれる
- 検索語が短すぎる（1 文字）場合は実行しない。2 文字以上で検索できる（OR-03 と同じ規則）
- 日本語のように単語区切りのない文章でも部分一致できる。英数字の語は語頭からの一致で探すため、単語の途中だけを指定した検索（`flare` で `Cloudflare`）は一致しない（`cloud` なら一致する）
- 検索結果は URL に反映され、共有できる
- サインイン済みの利用者でも、公開検索の対象は公開ノートのみ。自分のノートを探す場合は作業用の一覧の検索（OR-03）へ誘導する
- 大量の要求に対してはレート制限をかける

## DS-06: 検索エンジンから公開ノートにたどり着く

**利用者**: 閲覧者
**事前条件**: 対象ノートが公開である

### 基本フロー

1. 検索エンジンの結果からノートの URL を開く
2. ノートの本文が表示される（SH-07）

### 異常系・エッジケース

- 公開ノート、公開ページ（利用者 / ワークスペース）のみをインデックス対象とする
- 非公開・限定公開のノート、作業用の一覧、設定画面はインデックスさせない
- 公開ノートと公開ページを含むサイトマップを提供する
- 読めなくなったノートの URL への応答は、公開を取り下げた事実を漏らさないことを優先して分ける
    - 非公開・限定公開に戻された場合（公開だったものを含む）は「見つかりません」（404 相当）を返す。共有リンクで「無効・再発行済み・削除・非公開化」を区別しない原則（SH-05）と揃える
    - 公開状態のままゴミ箱に入っている場合だけ、インデックス削除を促す応答（410 相当）を返す。所有者が復元すれば同じ URL で再び読めるため、公開を取り下げた事実は漏れない
    - 完全削除後は「見つかりません」を返す（記録が残らず、公開されていた事実を判定できないため）
- 既知の限界として、完全削除されたノートの URL にはインデックス削除を促す応答を返せない。検索エンジンからの削除は「見つかりません」の応答とサイトマップからの除去に依存する
- 各公開ページに、タイトル・説明・代表画像・正規 URL のメタ情報を出力する
