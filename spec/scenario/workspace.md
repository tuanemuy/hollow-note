# ワークスペース（WS）

複数人でノートを共有する場としてのワークスペースの作成・参加・運営に関するシナリオ。ロールは [ADR 004](../adr/004-workspace-roles.md) に従う。

## WS-01: ワークスペースを作成する

**利用者**: サインイン済みの利用者
**事前条件**: なし

### 基本フロー

1. 上部バーのスコープトークンを開き、「ワークスペースを作成」を選ぶ
2. 名前、説明、公開ページ用のスラッグを入力する
3. 作成すると、自分が owner として参加した状態のワークスペースができる
4. 作成直後のワークスペースに切り替わり、メンバー招待への導線が表示される

### 異常系・エッジケース

- スラッグが既に使われている場合、入力中に検出して代替候補を示す
- スラッグに使えない文字・予約語が含まれる場合は保存を拒否する
- 名前が空の場合は保存を拒否する
- 作成できるワークスペース数の上限（1 人あたり 20 件）を超える場合は理由を示して拒否する
- 作成直後の公開ステータスは非公開

## WS-02: 表示中のワークスペースを切り替える

**利用者**: メンバー
**事前条件**: 1 つ以上のワークスペースに参加している

### 基本フロー

1. 上部バーのスコープトークン（現在の文脈名を常時表示している）を開く
2. 「個人」と参加中のワークスペースが一覧される
3. 選ぶと、その文脈のノート一覧に切り替わる
4. 選択は URL に反映され、次回の訪問時にも引き継がれる

### 異常系・エッジケース

- 参加中のワークスペースがない場合、切り替えメニューには「個人」と作成の導線のみを表示する
- 切り替え時に絞り込み条件（検索語・タグ・月）は解除する。タグは文脈ごとに独立しているため
- 除名されたワークスペースを URL で直接開いた場合、アクセスできない旨を表示して個人の文脈へ誘導する
- 削除されたワークスペースを開いた場合も同様に扱う
- **引き継ぎ（手順 4）を畳むのは、その文脈を開く読み出しが「開けない」と答えた時点である。** 自分の操作（脱退・削除）の応答で畳むだけでは、他の owner に除名された／ワークスペースを削除された利用者の引き継ぎが誰にも畳まれず、次回の訪問がエラー画面へリダイレクトされ続ける。入口（`/`）側で権限を判定し直す形は採らない（権限判定は遷移先が行う）

## WS-03: メンバーを招待する

**利用者**: owner
**事前条件**: 対象ワークスペースの owner である

### 基本フロー

1. ワークスペース設定の「メンバー」を開く
2. 「招待」を選び、メールアドレスと付与するロール（owner / editor / viewer）を指定する
3. 招待リンクを含むメールが送られ、保留中の招待として一覧に表示される
4. 招待リンクをコピーして自分で共有することもできる

### 異常系・エッジケース

- 既にメンバーであるメールアドレスを招待しようとした場合、その旨を示して招待しない
- 既に保留中の招待があるメールアドレスには、再送として扱う
- 招待の有効期限は 14 日。期限切れの招待は一覧で区別され、再送できる
- 保留中の招待は取り消せる
- 一度に招待できる件数と、期間あたりの招待数に上限を設ける
- owner ロールでの招待は、権限の重さを説明したうえで確認する
- メールアドレスの形式が不正な場合は送信前に弾く

## WS-04: 招待を受けて参加する

**利用者**: 招待された利用者
**事前条件**: 有効な招待リンクを持っている

### 基本フロー

1. 招待リンクを開く
2. ワークスペースの名前・説明・付与されるロール・招待者が表示される
3. サインインしていない場合はサインイン / サインアップを求められ、完了後に招待の確認へ戻る
   - 招待されたメールアドレスのままサインアップした場合は、招待メールの受信をもって到達性が確認できているため、メール確認を省いてそのままサインインさせる
4. 「参加する」を選ぶとメンバーになり、そのワークスペースの一覧へ遷移する

### 異常系・エッジケース

- 招待が期限切れ / 取り消し済み / 使用済みの場合、その旨を表示し、招待者への連絡を促す
- 招待されたメールアドレスと、サインインしているアカウントのメールアドレスが異なる場合、確認したうえで参加させる（招待リンク自体を認可の根拠とする）
- 既にメンバーの場合は、参加済みである旨を示してワークスペースへ遷移する
- ワークスペースが削除済みの場合、その旨を表示する
- 「参加しない」を選んで招待を破棄できる

## WS-05: メンバーのロールを変更する / 除名する

**利用者**: owner
**事前条件**: 対象ワークスペースの owner である

### 基本フロー

1. ワークスペース設定の「メンバー」を開く
2. メンバー一覧に、表示名・メールアドレス・ロール・参加日が表示される
3. ロールのセレクターから別のロールを選ぶと即座に反映される
4. 「除名」を選ぶと、確認のうえメンバーから外れる

### 異常系・エッジケース

- 最後の owner を降格・除名することはできない。操作を無効化して理由を示す
- 自分自身のロールは変更できない（脱退は WS-06 で行う）
- 除名されたメンバーは、そのワークスペースのノートに一切アクセスできなくなる。除名時にその旨を確認する
- 除名されたメンバーが作成したノートはワークスペースに残る
- 除名対象が編集中だった場合、次回の保存時に拒否される（ED-08）
- owner でない利用者にはメンバー一覧を読み取り専用で表示し、ロール変更・除名の操作を出さない

## WS-06: ワークスペースを脱退する

**利用者**: メンバー
**事前条件**: 対象ワークスペースに参加している

### 基本フロー

1. ワークスペース設定の下部から「脱退する」を選ぶ
2. 脱退後はノートにアクセスできなくなる旨を確認する
3. 実行すると、個人の文脈へ遷移する

### 異常系・エッジケース

- 自分が唯一の owner である場合、先に他のメンバーを owner にするか、ワークスペースを削除するよう促し、脱退させない
- 自分が作成したノートはワークスペースに残る。脱退前に個人へ移動したい場合の導線を案内する
- 脱退後、同じワークスペースに再参加するには改めて招待が必要

## WS-07: ワークスペースの設定を編集する

**利用者**: owner
**事前条件**: 対象ワークスペースの owner である

### 基本フロー

1. ワークスペース設定の「一般」を開く
2. 名前、説明、アイコン、公開ページのスラッグを編集する
3. 保存すると、スコープトークン・タイムライン・公開ページの表示に反映される

### 異常系・エッジケース

- スラッグの重複・予約語・不正な文字は WS-01 と同じ規則で拒否する
- スラッグを変更すると旧 URL は失効する。公開中の場合は事前に警告する
- アイコンのサイズ・形式の制約は AC-07 と同じ
- owner でない利用者には読み取り専用で表示する

## WS-08: ワークスペースを公開する / 非公開に戻す

**利用者**: owner
**事前条件**: 対象ワークスペースの owner である

### 基本フロー

1. ワークスペース設定の「公開」を開く
2. 公開すると何が見えるようになるか（公開ステータスのノートのみが公開ページに並ぶ）の説明を読む
3. 公開に切り替えると、公開ページの URL が表示され、コピーできる
4. 非公開に戻すと、公開ページは見られなくなる

### 異常系・エッジケース

- スラッグが未設定の場合、公開前に設定を求める
- 公開に切り替えても、個々のノートの公開ステータスは変わらない。公開ノートが 0 件なら公開ページは空状態になる旨を示す
- 非公開に戻しても、個々のノートが公開ステータスであれば、そのノート自体は引き続き公開のままである。誤解を避けるため明示する
- 非公開に戻すと検索エンジンのインデックス削除には時間がかかる旨を添える

## WS-09: ワークスペースの公開ページを閲覧する

**利用者**: 閲覧者（サインイン不要）
**事前条件**: 対象ワークスペースが公開である

### 基本フロー

1. 公開ページの URL を開く
2. ワークスペースの名前・説明・アイコンと、公開ステータスのノートが新しい順に並ぶ
3. タグでの絞り込みと検索ができる
4. ノートを選ぶとノートの公開ページ（SH-07）へ遷移する

### 異常系・エッジケース

- 非公開のワークスペース、削除済みのワークスペース、存在しないスラッグはいずれも「見つかりません」を返す
- 公開ノートが 0 件の場合は空状態を表示する
- メンバー一覧は外部に表示しない
- メンバーが自分のワークスペースの公開ページを開いた場合も、外部から見える内容のみを表示し、その旨のバナーを出す

## WS-10: ワークスペースを削除する

**利用者**: owner
**事前条件**: 対象ワークスペースの owner である

### 基本フロー

1. ワークスペース設定の最下部から「ワークスペースを削除」を選ぶ
2. 削除されるもの（ノート、タグ、メンバーシップ、公開ページ）の説明を読む
3. 確認のためワークスペース名を入力する
4. 実行すると、メンバー全員がアクセスできなくなり、個人の文脈へ遷移する

### 異常系・エッジケース

- 確認入力が一致しない場合は実行しない
- 削除前に、ノートを個人または他のワークスペースへ移動できる旨を案内する
- 削除後、公開・限定公開だったノートの URL はすべて「見つかりません」を返す
- 実行中のジョブ（変換、バックアップ）はキャンセルする
- 削除は取り消せない旨を明示する
