# 取り込み（IM）

ファイルをアップロードして HTML のノートに変換するシナリオ。変換方式は形式によって異なり、LLM を要するものは OpenRouter 連携（IN-01）が前提になる。

## 形式ごとの変換方針

| 形式 | LLM 未連携時 | LLM 連携時 | LLM を使わない取り込みを選んだとき |
| --- | --- | --- | --- |
| HTML | そのまま取り込む（サニタイズのみ） | 同左（LLM は使わない） | 同左 |
| Markdown | HTML へ機械変換 | 同左（LLM は使わない） | 同左 |
| Word / Excel / PowerPoint / プレーンテキスト | テキストを機械抽出して素朴な HTML にする | 抽出結果を LLM で構造化する | 機械抽出（未連携時と同じ） |
| PDF（テキスト層あり） | テキストを機械抽出して素朴な HTML にする | 抽出結果を LLM で構造化する | 機械抽出（未連携時と同じ） |
| PDF（テキスト層なし） | 変換できず「要 LLM 連携」の状態で保存 | ページ画像を LLM で解析して構造化する | 「LLM なしでは取り込めません」と失敗として記録 |
| 画像 | 変換できず「要 LLM 連携」の状態で保存 | LLM でテキスト抽出・構造化する | 同上 |
| 音声 | 変換できず「要 LLM 連携」の状態で保存 | 音声認識でテキスト化し、LLM で構造化する | 同上 |

「要 LLM 連携」の状態のノートは、元ファイルとメタデータのみを保持し、本文が空であることを示す。後から連携すれば IM-06 で生成できる。

LLM を使わない取り込み（IM-01 の選択）で LLM 必須形式を指定した場合は、「要 LLM 連携」ではなく失敗として記録する。連携済みの利用者がこの選択をすることもあり、「連携すれば解決する」という案内は当たらないため。案内は連携ではなく「LLM を使う設定で取り込み直す」ことを指し、元ファイルは残るので IM-06 でも生成できる。

## 共通の前提

- **元ファイルの保持**: アップロードされた元ファイルは、ノートが存在する限りオブジェクトストレージに保持する。期限による自動削除はしない。ノートを完全削除したときにのみ削除される
- **通知の手段**: ジョブの完了・失敗はアプリ内でのみ通知する（実行中を示す処理ティッカー、処理履歴、画面内のトースト）。メールを送るのは認証系（メール確認、パスワード再設定、ワークスペースの招待）に限る
- **保存容量の上限**: 個人とワークスペースのそれぞれに保存容量の上限を設ける（既定は個人 5 GB、ワークスペース 20 GB）。元ファイル・挿入したメディア・取り込んだ参照リソース・ゴミ箱の中身をすべて数える。上限に達している場合、新たなアップロードは開始前に拒否し、使用量の画面（AC-10）と不要なノートの削除へ誘導する。アップロードの途中で上限を超えた場合は、そのファイル以降を失敗として記録し、既に取り込んだ分は保持する
- **LLM 実行回数の上限**: 月あたりの LLM 実行回数に上限を設ける。超過した場合は変換ジョブを失敗として記録し、翌月まで待つか実行回数を消費しない機械的な変換で取り込むよう案内する。機械的な変換で取り込めない形式（テキスト層のない PDF・画像・音声）では、翌月まで待つ案内のみとする

## IM-01: ファイルをアップロードしてノートを作る

**利用者**: 所有者
**事前条件**: サインイン済み

### 基本フロー

1. ノート一覧の「アップロード」を選ぶ
2. ファイル選択、またはドラッグ & ドロップでファイルを指定する
3. 取り込み先（IM-04）と公開ステータス（既定は非公開）を確認する
4. アップロードを開始すると、ファイルごとに進捗が表示される
5. アップロードが完了した時点でノートが作成され（本文は空、状態は「処理中」）、変換ジョブが登録される
6. 単一ファイルの場合は、この時点で作成されたノートの詳細へ遷移し、変換の進捗をその画面で見られる（OR-11）
7. 変換が完了すると本文が現れ、一覧の表示も更新される。非公開以外の公開ステータスを指定していた場合は、この時点で適用される（変換が完了するまでノートは非公開のまま）
8. 自動バックアップ（IN-05）が有効な場合、変換の成否とは独立してバックアップジョブが登録される

### 異常系・エッジケース

- 未対応の拡張子 / MIME タイプの場合、選択時に弾いて理由を表示する
- ファイルサイズが上限を超える場合、選択時に弾く（上限は形式別: 音声 200 MB、その他 50 MB）
- 拡張子と実際の内容が食い違う場合は内容を優先して判定し、判定できなければ未対応として扱う
- 破損して読み取れないファイルは、変換失敗として記録し、原因と再試行の導線を示す
- パスワード保護された PDF / Office ファイルは、解除が必要である旨を伝えて失敗として記録する
- LLM を要する形式で未連携の場合、アップロード自体は成功させ「要 LLM 連携」の状態で保存し、連携への導線を表示する
- LLM 連携済みでも、アップロード時に LLM を使わない機械的な変換を選べる（LLM 実行回数を消費しない）。機械抽出できる形式は「LLM 未連携時」の列と同じ方針で取り込まれる。LLM 必須形式（テキスト層のない PDF・画像・音声）は失敗として記録し、LLM を使う設定での取り込み直しを案内する（未連携でない限り「連携が必要です」とは案内しない）
- 公開を選んだ場合、公開ハンドル（AC-07。ワークスペース所有ならワークスペースの公開ページ用スラッグ）が未設定であればアップロード開始前に検出し、設定を促す
- 公開ステータスの適用時点（変換成功後）でハンドル / スラッグが未設定に戻っていた場合、ノートは非公開のまま保存し、その旨をジョブ詳細（JB-01）に記録する
- 通信が切れた場合、アップロード済みの分は保持し、再開または再試行できる
- 変換に長時間かかる場合、画面を離れても処理は継続し、完了は処理履歴（JB-01）とノート一覧で確認できる
- 同名ファイルを再アップロードしても既存ノートは上書きせず、別のノートとして作成する
- 自動バックアップが失敗しても取り込み自体は成功として扱う。失敗は処理履歴に記録し、ノートには未バックアップと表示する

## IM-02: 複数のファイルをまとめてアップロードする

**利用者**: 所有者
**事前条件**: サインイン済み

### 基本フロー

1. アップロード画面で複数のファイルを一度に指定する
2. 一覧に各ファイルの名前・サイズ・判定された形式・変換方式が表示される
3. 不要なファイルを一覧から取り除ける
4. 取り込み先と公開ステータスをまとめて指定する
5. アップロードを開始すると、ファイルごとに個別の進捗が表示される
6. 完了後、成功件数と失敗件数の内訳が表示され、失敗分は理由つきで一覧される

### 異常系・エッジケース

- 1 回あたりの件数上限（100 件）と合計サイズ上限（500 MB）を超える場合、選択時に弾く
- 一部が失敗しても他の変換は継続する（1 件の失敗で全体を止めない）
- 失敗した分だけをまとめて再試行できる
- フォルダをドロップした場合は再帰的にファイルを取り出し、未対応の形式は除外して件数を示す
- ZIP ファイルは展開せず、未対応の形式として扱う
- 途中でキャンセルした場合、開始済みの変換は完了させ、未開始分は取り消す。結果の内訳を表示する
- LLM を要するファイルが多数含まれ、未連携の場合、開始前に「N 件は連携が必要です」と警告する。LLM を使わない機械的な変換を選んでいる場合は、同じ件数を「N 件は LLM なしでは取り込めません」と警告する（判定は開始前の暫定値のため、いずれも受け付け自体は止めない）
- LLM を使わない機械的な変換の選択、および公開ステータスの保留適用（変換成功後に適用、ハンドル / スラッグ未設定の事前検出）は IM-01 と同じ扱いになる
- 取り込めなかったファイルも 1 件ずつ結果として記録されるため、6 の内訳と処理履歴（JB-01）に必ず現れる

## IM-03: 取り込みの進捗と結果を確認する

**利用者**: 所有者
**事前条件**: 取り込みを開始している

### 基本フロー

1. アップロード中はアップロード画面で全体と個別の進捗が見える
2. 画面を離れた場合も、処理ティッカーで進行中の件数が分かる
3. 完了すると通知が表示され、ノート一覧に反映される
4. 処理履歴（JB-01）から過去の取り込み結果を確認できる

### 異常系・エッジケース

- 変換が失敗したファイルは、原因（未対応 / 破損 / 連携なし / LLM なしでは取り込めない / モデルエラー / 容量超過 / LLM 実行回数の上限超過 / タイムアウト）別に表示する。LLM 実行回数の上限超過の場合は、翌月まで待つか、実行回数を消費しない機械的な変換で取り込み直す案内を添える（機械的な変換で取り込めない形式では翌月まで待つ案内のみ）。「LLM なしでは取り込めない」場合は、逆に LLM を使う設定での取り込み直し（未連携なら連携）を案内する
- タイムアウトした場合は、その旨と再試行の導線を出す
- ブラウザを閉じても処理は継続する。再訪時に最新の状態を表示する
- 同時実行数の上限を超えた分は待機状態として表示する

## IM-04: 取り込み先（個人 / ワークスペース）を指定する

**利用者**: 所有者
**事前条件**: サインイン済み

### 基本フロー

1. アップロード画面の取り込み先セレクターで「個人」または参加中のワークスペースを選ぶ
2. 既定値は、直前に表示していたタイムラインの文脈（個人 / ワークスペース）に一致する
3. 選択した先にノートが作成される

### 異常系・エッジケース

- viewer としてのみ参加しているワークスペースは選択肢に出さない
- アップロード中にそのワークスペースから除名された場合、残りの取り込みは失敗として記録し理由を示す
- 参加しているワークスペースが 1 つもない場合、セレクターは「個人」のみを表示する
- 取り込み先を後から変えたい場合は、ノートの移動（OR-12）で行う

## IM-05: 参照されている外部ファイルを取り込んで参照先を差し替える

**利用者**: 所有者
**事前条件**: 変換結果に外部リソースへの参照が含まれる

### 基本フロー

1. HTML や Markdown に含まれる画像・動画・スタイルシートなどの参照を変換時に検出する
2. 画像・動画などのリソースは、取得できたものをオブジェクトストレージに保存し、本文中の参照先を保存先の URL に差し替える
3. スタイルシートは、取得できた内容をノートの本文に直接埋め込む。読み込み元への参照は残らないため、後から配布元が消えても中身が変わっても、取り込んだ時点の見た目がそのまま保たれる
4. ノート詳細に、取り込んだリソースの件数と一覧を表示する。この表示は**そのノートを読める人なら誰でも見られ、いつまでも残る** — 取り込みを実行したのが自分でなくても、ワークスペースの他のメンバーが取り込んだものでも見られる

### 異常系・エッジケース

- 取得に失敗したリソース（404、タイムアウト、認証が必要）は元の URL のまま残し、取り込めなかったものとして一覧に示す。表示のたびに元の場所から読み込まれる状態が続く
- 取得に失敗したスタイルシートは元の URL のまま残せないため、そのスタイルシートによる装飾は失われる。取り込めなかったものとして一覧に示し、見た目が変わっている可能性があることを伝える。素のブラウザ表示のままにせず既定のスタイルを当て直したい場合は、ノート詳細でスタイルの適用を切り替えられる（ED-11）
- 「まだ取り込んでいない参照」と「取り込もうとして取れなかった参照」は区別して示す。前者は取り込みを選び直せば取り込まれるが、後者は同じ結果になる可能性が高い
- 失敗の理由（見つからない・時間切れ・拒否・上限による打ち切り）は、記録が残っているあいだ添えて示す。理由が分からなくなっても「取り込めていない」ことと対象の URL は示し続ける
- 埋め込んだスタイルシートが背景画像やフォントを外部から読み込んでいる場合、その読み込み先は取り込みの対象にならず元のままになる。装飾のうちその部分だけは、表示のたびに外部から読み込まれ、配布元が消えれば失われる
- 埋め込んだスタイルシートのうち、ページ全体を覆うような配置の指定と、別のスタイルシートをさらに読み込む指定は取り除かれる。取り除いた内容は取り込み結果に示す
- 相対パスの参照は、同時にアップロードされたファイル群の中から解決を試み、見つからなければ元のまま残す
- 内部ネットワークやローカルアドレスを指す URL は取得しない
- リソースの合計サイズ上限（100 MB）または件数上限（200 件）を超えた分は取り込まず、その旨を示す。スタイルシートもこの上限に数え、掛かった分は取得に失敗した場合と同じく装飾が失われる
- `data:` URI で埋め込まれたリソースは、一定サイズを超える場合のみ切り出して保存する
- 既にサービス内のストレージを指す URL は差し替えない

## IM-06: LLM による構造化をやり直す

**利用者**: 所有者
**事前条件**: OpenRouter 連携済みで、対象ノートに元ファイルまたはバックアップがある

### 基本フロー

1. ノート詳細のメニューから「LLM で作り直す」を選ぶ
2. 使用するモデルと、任意の追加指示（例: 「見出しを章立てにして」）を入力できる
3. 現在の本文が置き換わる旨の警告を読んで実行する
4. 完了後、新しい本文に更新される。タグ・公開設定・共有リンクは維持される
5. 直前の本文に「元に戻す」で戻せる

### 異常系・エッジケース

- エディタで新規作成したノートには元ファイルが存在しないため、この操作を提供しない
- OpenRouter が未連携 / 鍵が失効している場合、連携を促して中止する
- モデルのレート制限・残高不足の場合、その旨を伝えて時間をおいた再試行を促す
- 実行中は該当ノートを編集不可にする
- 失敗した場合は元の本文を維持する
- 「要 LLM 連携」状態のノート、および LLM を使わない取り込みで失敗したノートでは、この操作が初回生成として機能する
