# シナリオレビュー 003

対象: `spec/scenario/` 配下すべて

## 1. 変換失敗時の再試行導線が誤った操作を指している

OR-11 の異常系は「変換に失敗したノートは失敗の理由と再試行（IM-06）の導線を表示する」としているが、IM-06 は OpenRouter 連携を事前条件とする LLM 再生成である。機械的な変換（Markdown、Office、テキスト層のある PDF）の失敗は LLM と無関係であり、連携を求めるのは誤り。

**対応**: OR-11 の導線を JB-02（失敗した処理の再試行）に変更する。LLM で作り直したい場合の導線として IM-06 を併記する。

## 2. ED-01 の「下書き」が独立した状態のように読める

ED-01 に「自動保存され、下書きとしてノートが作成される」とあるが、公開ステータス（非公開 / 限定公開 / 公開）とは別に「下書き」という状態が存在するのか判別できない。実際には非公開ステータスのノートが作られるだけであり、余計な状態を実装者に想像させる。

**対応**: 「非公開のノートとして作成される」に改める。

## 3. 公開検索におけるタグの扱いが未定義

DS-05 は「タグと期間で絞り込める」としているが、タグは所属先（個人 / ワークスペース）ごとに独立している（OR-12、ADR 003）。所有者が異なる公開ノートを横断して絞り込むとき、どのタグ集合を対象にするのかが決まっていない。

**対応**: 公開検索では所属先をまたいでタグ名で一致させると明記する。

## 4. 自動バックアップが取り込みの流れに現れていない

IN-05 で「アップロード時に元ファイルを自動バックアップする」を設定できるとしているが、`import.md` の IM-01 / IM-02 にはバックアップの記述がなく、いつバックアップジョブが登録されるのかが分からない。`jobs.md` のジョブ一覧には「自動バックアップ」が発生元として挙がっており、片側だけの記述になっている。

**対応**: IM-01 の基本フローに、自動バックアップが有効な場合はバックアップジョブが続けて登録される旨を追加し、異常系にバックアップ失敗が取り込みの成否に影響しないことを明記する。
