# シナリオレビュー 001

対象: `spec/scenario/` 配下すべて

## 1. 所有者がノートを閲覧するシナリオがない

`organize.md` は一覧までしか扱っておらず、`sharing.md` の SH-05 / SH-07 は閲覧者視点に限定されている。所有者・メンバーがノートを開いて本文を読む（処理中・要 LLM 連携・スタイル適用・タグ・共有状態・編集導線が同居する画面）というもっとも基本的な流れが、どのカテゴリーにも記述されていない。

**対応**: `organize.md` に「ノートを開いて内容を読む」シナリオを追加し、index に登録する。

## 2. 単体ノートの所属先移動がシナリオ化されていない

ADR 003 で「所属先は後から移動できる」と決めているが、シナリオ上は OR-09（複数選択の一括操作）の一項目としてしか現れない。1 件のノートを詳細画面から移す流れ、移動元・移動先の権限判定、閲覧範囲が変わる警告が具体化されていない。

**対応**: `organize.md` に単体移動のシナリオを追加する。

## 3. 「全ワークスペース横断」の検索が実在しない機能として言及されている

OR-03 の異常系に「条件を緩める提案（タグの解除、全ワークスペース横断）」とあるが、文脈をまたいで自分のノートを検索するシナリオはどこにもない。WS-02 では文脈の切り替え時に絞り込みを解除するとしており、横断検索は設計上存在しない。

**対応**: OR-03 の記述から横断検索の提案を削除する。

## 4. 元ファイルの保持方針が未定義

IM-06 に「元ファイルが保持されていない（保持期間切れ、または新規作成ノート）場合」とあるが、元ファイルをいつまで保持するかはどこにも書かれていない。ED-09 では「完全削除するとアップロードされた元ファイルとメディアも削除される」としており、保持期間の存在と矛盾しうる。

**対応**: 元ファイルはノートが存在する限り保持すると定め、IM-06 の「保持期間切れ」の記述を削除する。`import.md` の冒頭に保持方針を明記する。

## 5. AC-06 にパスワードの変更が埋もれている

タイトルは「ログイン方法を追加・解除する」だが、異常系に「パスワードを追加・変更する際は再認証を求める」とあり、変更の流れが基本フローに現れていない。パスワード変更は独立した頻出操作であり、再設定（AC-05）とも別物。

**対応**: AC-06 の基本フローにパスワードの変更を明示し、タイトルを実態に合わせる。

## 6. 完了通知の手段が未定義

IM-03 / EX-03 / IN-06 に「完了すると通知が表示される」とあるが、アプリ内の表示なのかメールなのかが決まっていない。メール通知が要るなら送信基盤とオプトアウトの設計が必要になる。

**対応**: 通知はアプリ内のみとし、メールは認証系（確認・再設定・招待）に限ると `import.md` または共通の前提として明記する。

## 7. ゴミ箱が独立した流れとして扱われていない

ED-09 の基本フローに「ゴミ箱の一覧から個別に復元、または完全削除できる」とあるが、ゴミ箱を開いて中身を確認する流れ（空状態、保持期限の表示、一括の完全削除）は具体化されていない。Phase 2 で画面として必要になる。

**対応**: ED-09 を削除と復元で分け、ゴミ箱を開く流れを明示する。
