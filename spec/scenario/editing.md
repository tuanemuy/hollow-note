# 編集（ED）

ノートの新規作成と本文編集に関するシナリオ。ノートの正データは常に HTML であり、3 つの編集モードはいずれも同じ HTML を編集する（[ADR 006](../adr/006-html-content-model.md)）。

## 編集モードの性質

| モード | できること | 失われうるもの |
| --- | --- | --- |
| ビジュアル | レンダリング結果のテキストノードだけを直接書き換える | なし（構造・属性は保持される） |
| HTML | HTML ソースを直接編集する | なし（サニタイズで除去される要素を除く） |
| WYSIWYG | 見出し・リスト・表・リンクなどをリッチテキストとして編集する | エディタが表現できない要素・属性・インラインスタイル |

## ED-01: 白紙のノートを新規作成する

**利用者**: 所有者
**事前条件**: サインイン済み

### 基本フロー

1. ノート一覧の「新規作成」を選ぶ
2. WYSIWYG エディタが開き、タイトルと本文を入力できる
3. 入力すると自動保存され、非公開のノートとして作成される
4. 「完了」を選ぶとノート詳細に遷移する

### 異常系・エッジケース

- タイトルが未入力のまま保存した場合、本文の先頭行から自動で仮のタイトルを付ける。本文も空なら「無題」とする
- 保存先は取り込み先セレクター（IM-04 と同じ規則）で選ぶ。既定は現在のタイムラインの文脈
- 自動保存が通信エラーで失敗した場合、未保存である旨を表示し、内容をブラウザに退避して再試行する
- 何も入力せずに離脱した場合、空の下書きは作成しない
- 同時に複数のタブで同じノートを開いている場合は、後から保存した内容が優先され、他方には内容が更新された旨を通知する

## ED-02: ビジュアルエディタでテキストを直接編集する

**利用者**: 所有者
**事前条件**: 対象ノートの編集権限がある

### 基本フロー

1. ノート詳細で「編集」を選び、モードとして「ビジュアル」を選ぶ
2. ノートが通常どおりレンダリングされた状態で表示され、テキスト部分だけが編集可能になる
3. 文字を書き換えると、対応するテキストノードのみが更新される
4. 保存すると、元の構造・装飾を保ったまま本文が更新される

### 異常系・エッジケース

- 要素の追加・削除・並べ替えはできない。試みた場合はその旨を示す
- `script` や `style` の中身は編集対象にしない
- 元の HTML に含まれる属性（class、style、data-*）は保持する
- 空になったテキストノードは削除せず空文字として保持し、構造を壊さない
- 編集中に他の誰かが同じノートを更新した場合、保存時に競合を検出して、上書きするか破棄するかを選ばせる

## ED-03: HTML エディタでソースを編集する

**利用者**: 所有者
**事前条件**: 対象ノートの編集権限がある

### 基本フロー

1. 編集画面でモードとして「HTML」を選ぶ
2. シンタックスハイライト付きのソースエディタが表示される
3. 編集すると、隣（または切り替え）でプレビューが更新される
4. 保存すると、サニタイズを経て本文が更新される

### 異常系・エッジケース

- 構文が壊れている場合、保存前に警告し、補正後の結果をプレビューで示す
- サニタイズで除去される要素・属性（`script`、イベントハンドラー属性、`javascript:` などの危険な URL）がある場合、保存時に何が除去されたかを一覧で示す
- 極端に大きな HTML（1 MB 超）は保存を拒否し、分割を促す
- 外部リソースへの参照を新たに書いた場合、IM-05 と同じ規則で取り込むかどうかを選べる

## ED-04: WYSIWYG エディタで編集する

**利用者**: 所有者
**事前条件**: 対象ノートの編集権限がある

### 基本フロー

1. 編集画面でモードとして「WYSIWYG」を選ぶ
2. 元が HTML ファイル由来のノートである場合、装飾が失われる可能性があるという警告が表示される
3. 警告を了解して進むと、リッチテキストとして編集できる
4. 保存すると、エディタの表現に沿って正規化された HTML で本文が更新される

### 異常系・エッジケース

- 警告は「今後表示しない」を選べる。設定画面から再表示に戻せる
- 警告を出したうえで進んだ場合も、保存前に自動で版を保持し、「元に戻す」で戻せる
- エディタが解釈できない要素は、可能な限りそのまま保持するブロックとして扱い、内容を破棄しない
- 表・画像・コードブロック・リンクの基本的な編集操作を提供する
- 大きな表や深いネストで動作が重くなる場合、HTML モードでの編集を勧める

## ED-05: 編集モードを切り替える

**利用者**: 所有者
**事前条件**: 編集画面を開いている

### 基本フロー

1. 編集画面上部のモード切り替えから別のモードを選ぶ
2. 未保存の変更がある場合は、保存してから切り替える旨の確認が出る
3. 切り替えると、同じ本文が新しいモードで開かれる

### 異常系・エッジケース

- WYSIWYG へ切り替える場合は ED-04 と同じ警告を出す
- ビジュアルモードは、本文が空、または編集可能なテキストノードが存在しない場合は選べない
- モードの選択は次回の編集時に既定として引き継ぐ（ノート単位ではなく利用者単位）

## ED-06: 画像や動画をアップロードして本文に挿入する

**利用者**: 所有者
**事前条件**: 編集画面を開いている（HTML / WYSIWYG モード）

### 基本フロー

1. エディタのツールバーから「画像 / 動画を挿入」を選ぶか、ファイルを本文にドロップする
2. アップロードの進捗がその場に表示される
3. 完了すると、保存先の URL を参照する要素が挿入される
4. 画像は代替テキストを入力できる

### 異常系・エッジケース

- 対応形式（画像: PNG / JPEG / GIF / WebP / SVG、動画: MP4 / WebM）以外は弾く
- SVG はサニタイズしてから保存する
- サイズ上限（画像 20 MB、動画 200 MB）を超える場合は弾く
- アップロード中に編集画面を離れようとした場合、中断される旨を確認する
- アップロードに失敗した場合、挿入されたプレースホルダーを取り除き、再試行できるようにする
- ビジュアルモードでは要素を追加できないため、この操作を提供しない
- 本文から参照が外れたメディアは、一定期間後に回収の対象とする

## ED-07: タイトルを変更する

**利用者**: 所有者
**事前条件**: 対象ノートの編集権限がある

### 基本フロー

1. ノート詳細または編集画面でタイトルを選んで書き換える
2. 入力を終えると自動保存され、一覧・タイムライン・共有ページの表示に反映される

### 異常系・エッジケース

- 空にした場合は「無題」に戻す
- 長すぎる場合（200 文字超）は入力時点で制限する
- タイトルの重複は許容する

## ED-08: 編集内容を保存する / 破棄する

**利用者**: 所有者
**事前条件**: 編集画面で変更を加えている

### 基本フロー

1. 編集中は一定間隔で自動保存され、「保存済み」「保存中」の状態が表示される
2. 明示的に「保存」を選ぶこともできる
3. 「破棄」を選ぶと、最後に保存した状態に戻る

### 異常系・エッジケース

- 通信エラーで自動保存に失敗した場合、未保存であることを表示し、内容をブラウザに退避して再試行する。復帰時に復元を提案する
- 未保存のまま画面を離れようとした場合、離脱を確認する
- 保存時に編集権限を失っていた場合（ワークスペースから除名された等）、保存を拒否して理由を示し、内容をダウンロードできるようにする
- 保存のたびに版を記録し、直近の一定数（20 版）から復元できる
- 別の利用者が同時に編集して競合した場合、ED-02 と同じ扱いで解決する

## ED-09: ノートを削除する

**利用者**: 所有者
**事前条件**: 対象ノートの削除権限がある

### 基本フロー

1. ノート詳細または一覧のメニューから「削除」を選ぶ
2. 確認のうえ実行すると、ノートはゴミ箱に移り、一覧から消える
3. 削除直後は画面上の「元に戻す」で取り消せる

### 異常系・エッジケース

- 削除するとノートは公開・限定公開の URL からアクセスできなくなる。公開中のノートを削除する場合はその旨を警告する
- 変換処理中・再生成中のノートを削除しようとした場合、実行中のジョブをキャンセルしてから削除する旨を確認する
- 権限のない利用者には削除操作を出さない
- 複数ノートの削除は OR-09 で行う

## ED-10: ゴミ箱を開いて復元・完全削除する

**利用者**: 所有者
**事前条件**: サインイン済み

### 基本フロー

1. サイドバーから「ゴミ箱」を開く
2. 現在の文脈（個人 / ワークスペース）で削除されたノートが、削除日時の新しい順に並ぶ
3. 各項目に、完全削除されるまでの残り日数（既定 30 日）が表示される
4. 個別に「復元」を選ぶと、削除前の状態に戻って一覧に現れる
5. 個別に「完全に削除」を選ぶと、確認のうえ復元できなくなる
6. 「ゴミ箱を空にする」ですべてを完全削除できる

### 異常系・エッジケース

- ゴミ箱が空の場合は空状態を表示する
- 復元すると、削除前の公開ステータス・共有リンク・タグが復活する
- 完全削除すると、アップロードされた元ファイル・挿入したメディア・版の履歴も削除される。Google Drive 上のバックアップは残る
- 保持期限（30 日）を過ぎた項目は自動で完全削除される
- 所属先のワークスペースが削除された場合、そのワークスペースのゴミ箱の内容も削除される
- 完全削除は取り消せない旨を明示する
- ワークスペースのゴミ箱は owner / editor のみが開ける

## ED-11: 本文への既定スタイルの適用を切り替える

**利用者**: 所有者
**事前条件**: 対象ノートの編集権限がある

### 基本フロー

1. ノート詳細のメニューから「表示スタイル」を開く
2. 現在の設定（既定スタイルを適用 / 元の装飾のみ）と、それが取り込み時に自動判定された結果である旨が表示される
3. 切り替えると、その場で表示が変わる
4. 設定はノートごとに保持され、共有ページ・公開ページ・HTML の書き出しにも反映される

### 異常系・エッジケース

- 取り込み時の自動判定の規則は [ADR 007](../adr/007-default-style-isolation.md) に従う。装飾を持つ本文は「元の装飾のみ」が既定になる
- 装飾を持たない本文に「元の装飾のみ」を選ぶと、素のブラウザ表示になる。プレビューで確認したうえで切り替えられる
- 編集で本文の装飾の有無が変わっても、設定は自動では変えない
- 権限のない利用者には切り替え操作を出さず、表示のみとする
