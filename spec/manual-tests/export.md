# 書き出し テスト

## 概要

このドキュメントは、ノートのダウンロード（HTML / Markdown / PDF、個別・一括）に関するマニュアルテストの手順書です。

対応シナリオ: `spec/scenario/export.md`（EX-01〜EX-04）

## 前提条件

### 環境

- ユーザー A（`user-a@example.com`）でサインインできる
- ユーザー B が viewer として参加するワークスペース `設計チーム` がある
- ダウンロードしたファイルの内容を確認できる（テキストエディタ、PDF ビューアー）

### テストデータ

| 名前 | 内容 |
|---|---|
| 装飾ノート | `style` 要素と画像を含む、`styleMode: preserve` のノート |
| 素朴ノート | 見出し・リスト・表を含む、`styleMode: default` のノート |
| 表現困難ノート | Markdown で表現できない要素（`iframe` 相当のブロック）を含むノート |
| 処理中ノート | 変換処理中で本文がまだないノート |
| 記号タイトルノート | タイトルが `///` のみのノート |
| 公開ノート | 公開ステータスのノート |
| 共有ノート | パスワード保護された限定公開のノート |

## TC-26: 保存先の異なるノートを混ぜて一括ダウンロードしようとする

**種別**: 異常系
**目的**: EX-02 の一括ダウンロードで、対象の保存先（個人 / ワークスペース）が混ざらないことを検証する

| # | 操作 | 期待結果 |
|---|---|---|
| 1 | 個人のノート一覧で 2 件を選ぶ | 操作バーに「ダウンロード」が表示される |
| 2 | 選択したまま `設計チーム` に切り替える | 選択が解除され、一覧はワークスペースのノートだけになる（個人とワークスペースのノートを同時に選ぶ手段がない） |
| 3 | `設計チーム` で 2 件を選んで一括ダウンロードを実行する | 単一の保存先の対象として受け付けられ、ジョブが登録される |
| 4 | 個人所有とワークスペース所有のノートを混ぜた要求をサーバーへ直接送る | 「まとめてダウンロードできるのは同じ保存先のノートだけです」と拒否され、ジョブが 1 件も登録されない（全体中止） |
| 5 | `/jobs` を確認する | 手順 4 の要求による親ジョブも子ジョブも残っていない |

**確認ポイント**: 手順 4 は UI からは混在した選択を作れないため、要求を直接送れる環境でのみ実行する。送れない場合は手順 4・5 を対象外とし、手順 1〜3 で「混在を作れないこと」を確認する
