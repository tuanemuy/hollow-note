# マニュアルテストレビュー 001

対象: `spec/manual-tests/` 配下すべて

## 1. 前提となる状態の作り方が書かれていないテストケースがある

いくつかのテストケースが「そういう状態にする」とだけ書かれており、実行者が状態を作れない。

| ドキュメント | テストケース | 作り方が不明な状態 |
|---|---|---|
| `import.md` | TC-24 | 「保存容量を上限まで使った状態」 |
| `import.md` | TC-25 | 「当月の LLM 実行回数を上限まで使った状態」 |
| `editing.md` | TC-19 | 「サニタイズ後に 1 MB を超える HTML」 |
| `jobs.md` | TC-17 | 「必ず失敗するジョブ」 |

**対応**: 各ドキュメントの「テストデータ」または「事前準備」に、状態の作り方（上限値を一時的に下げる、用意済みの大きなファイルを使う、破損ファイルを使う）を追記する。

## 2. `editing.md` TC-01 の入力値に英単語が混ざっている

手順の入力値が `today の議題` になっており、日本語の手順書として不自然。実行者が入力ミスと判断して別の値を入れる恐れがある。

**対応**: `本日の議題` に直す。

## 3. `import.md` のテストデータに 51 MB / 501 MB のファイルの用意が書かれていない

TC-16 と TC-17 は 50 MB / 51 MB の PDF、合計 501 MB のファイル群を使うが、テストデータの表には `big-audio.m4a`（201 MB）と `edge-audio.m4a`（200 MB）しか載っていない。TC-17 の 100 件・101 件のファイル群も同様。

**対応**: テストデータの表に不足分を追記する。
