# 共有 テスト

## 概要

このドキュメントは、ノートの公開ステータスの管理と、閲覧者による閲覧に関するマニュアルテストの手順書です。

対応シナリオ: `spec/scenario/sharing.md`（SH-01〜SH-08）

## 前提条件

### 環境

- ユーザー A（`user-a@example.com`、ハンドル `user-a`）でサインインできる
- ハンドル未設定のユーザー C（`user-c@example.com`）を用意する
- ユーザー A が editor、ユーザー B が viewer として参加するワークスペース `設計チーム`（スラッグ未設定）がある
- サインインしていない閲覧者として確認するためのシークレットウィンドウを使える

### テストデータ

| 名前 | 内容 |
|---|---|
| 本文ありノート | 本文が生成済みの個人ノート（非公開） |
| 処理中ノート | 変換処理中で本文がまだない個人ノート |
| 連携待ちノート | 「要 LLM 連携」の状態の個人ノート |
| WS ノート | `設計チーム` に属する本文ありのノート（非公開） |

### 事前準備

1. ユーザー A でサインインし、上記のノートを用意する

## TC-11: 誤ったパスワードで共有ノートを開こうとする

**種別**: 異常系
**目的**: SH-06 の認証を検証する

| # | 操作 | 期待結果 |
|---|---|---|
| 1 | シークレットウィンドウでパスワード保護されたリンクを開く | パスワード入力画面が表示される |
| 2 | `WrongPass` を入力する | 「パスワードが正しくありません」と表示される |
| 3 | 続けて何度も誤ったパスワードを入力する | レート制限がかかり、しばらく待つよう案内される |
| 4 | 待機・ロック中に正しいパスワードを入力する | 照合に進まず、同じレート制限の案内が出る |
| 5 | 別のブラウザ（別の発信元）から同じリンクを開いてパスワードを入力する | 手順 3 の制限に巻き込まれず、通常どおり照合される |
| 6 | 同じブラウザから**別の**共有リンクのパスワードを入力する | 共有リンクごとに別の記録になるため、手順 3 の制限に巻き込まれない |

**確認ポイント**: 入力画面にノートのタイトルも本文の断片も表示されない

## TC-19: 公開ノートが削除されたときの応答を確認する

**種別**: 異常系
**目的**: SH-07 と DS-06 の削除時の扱いを検証する。410 を返す範囲が「ゴミ箱在籍中で公開状態を保持している」場合だけであることを確認する

| # | 操作 | 期待結果 |
|---|---|---|
| 1 | 公開ノートの URL をメモする | — |
| 2 | 公開のまま（公開を取り下げずに）そのノートをゴミ箱に入れる | — |
| 3 | シークレットウィンドウでその URL を開く | 「見つかりません」が表示される |
| 4 | 応答のステータスコードを確認する | インデックス削除を促す応答（410 相当）が返る |
| 5 | ゴミ箱から復元する | 同じ URL で再び本文が表示される |
| 6 | 別の公開ノートを非公開に戻してから、その URL を開く | 「見つかりません」が表示され、応答は 404 相当になる（410 にはしない。公開を取り下げた事実そのものを漏らさないため） |
| 7 | 手順 2 のノートを公開のままゴミ箱に入れ、さらにゴミ箱から完全削除する | — |
| 8 | その URL をシークレットウィンドウで開き、応答を確認する | 404 相当が返る。完全削除後は行そのものが消えて公開されていた事実を判定できないため、**410 を返せないことが仕様である**（インデックス削除は 404 と、サイトマップから消えることに依存する） |
| 9 | そもそも公開したことのない非公開ノートの URL を開く | 同じく 404 相当が返り、手順 6・8 と応答が区別できない |
