# ワークスペース テスト

## 概要

このドキュメントは、ワークスペースの作成・招待・メンバー管理・公開・削除に関するマニュアルテストの手順書です。

対応シナリオ: `spec/scenario/workspace.md`（WS-01〜WS-10）

## 前提条件

### 環境

- ユーザー A（`user-a@example.com`）、ユーザー B（`user-b@example.com`）、ユーザー C（`user-c@example.com`）でサインインできる
- 未登録のメールアドレス `invitee@example.com` の受信箱を確認できる。参照ランタイム（Node + in-memory）では実際の送信は行われないため、送信ログの `mail.sent` 行に出る `actionUrl` を招待リンクとして読む
- 3 つのブラウザ（またはプロファイル）で同時にサインインできる

### テストデータ

| 名前 | 内容 |
|---|---|
| `設計チーム` | ユーザー A が owner、ユーザー B が editor、ユーザー C が viewer |
| `個人検証` | ユーザー A が唯一の owner のワークスペース |
| 公開ノート | `設計チーム` に属する公開ステータスのノート |
| 非公開ノート | `設計チーム` に属する非公開のノート |

### 事前準備

1. ユーザー A でサインインする
2. 上記のワークスペースとノートを用意する

## TC-01: ワークスペースを作成する

**種別**: 正常系
**目的**: WS-01 の基本フローを検証する

| # | 操作 | 期待結果 |
|---|---|---|
| 1 | 上部バーのスコープトークンからワークスペースの作成を開始する | 作成画面（`/workspaces/new`）が開く |
| 2 | 名前に `新規チーム`、説明に `テスト用` と入力する | 入力値が表示される |
| 3 | スラッグに `new-team` と入力する | 使用可能であることが示される |
| 4 | 作成する | 作成したワークスペースのメンバー管理（`/workspaces/{workspaceId}/settings/members`）に切り替わり、スコープトークンの表示が `新規チーム` になる |
| 5 | 画面を確認する | 招待の入力欄がそのまま出ていて（WS-01 手順 4 の招待への導線）、メンバー一覧には自分が owner として 1 名だけ表示される |
| 6 | 設定タブ「公開」を開く | 非公開であることが示される |
| 7 | スコープトークンから `新規チーム` のノート一覧を開く | `/workspaces/{workspaceId}/notes` に移り、0 件の空状態になる |

| # | 操作 | 期待結果 |
|---|---|---|

| 2 | `invitee@example.com` を入力し、ロールに editor を選んで招待を送信する | 保留中の招待として一覧に表示される |
| 3 | `invitee@example.com` の受信箱（参照ランタイムでは `mail.sent` のログ行）を確認する | 招待リンク（`actionUrl`）を含むメールが届いている |
| 4 | 保留中の招待の有効期限を確認する | 発行から 14 日後になっている |
| 5 | シークレットウィンドウで招待リンクを開く | ワークスペース名・説明・付与されるロール・招待者・招待先のメールアドレスが表示され、サインイン / アカウント作成へ誘導される |

| 7 | 招待を受諾する | 招待先と同じアドレスのアカウントなので確認は挟まらず、そのまま参加する。`設計チーム` のノート一覧（`/workspaces/{workspaceId}/notes`）へ遷移し、スコープトークンが `設計チーム` になる |
| 8 | ユーザー A のメンバー管理を再読み込みする | 新しいメンバーが editor として表示される |

## TC-06: メンバーのロールを変更する

**種別**: 正常系
**目的**: WS-05 の基本フローと、降格に伴う実行中ジョブの取り消しを検証する

| # | 操作 | 期待結果 |
|---|---|---|
| 1 | メンバー管理でユーザー B の行のロールセレクターを開く | owner / editor / viewer が並ぶ |
| 2 | viewer を選ぶ | 即座に反映され、再読み込みしても viewer のままになる |
| 3 | ユーザー B の画面で個人のノート詳細を開き、メニューから移動先の候補を開く | `設計チーム` が候補に並ばない（候補は editor 以上のワークスペースだけ） |
| 4 | ユーザー B の画面で `/workspaces/{workspaceId}/notes` を開く | 一覧は読めるが、ノートを作る導線も行の操作メニューも出ない（viewer には書き込みの導線を出さない） |
| 5 | ロールを editor に戻し、ユーザー B の画面で同じ候補と一覧を見直す | `設計チーム` が再び移動先の候補に並び、一覧にノートを作る導線と行の操作メニューが戻る |
| 6 | ユーザー B が `設計チーム` のノートで変換ジョブを実行中にしてから、viewer に降格する | ユーザー B の `/jobs` でその変換ジョブが `canceled` になっている（降格後に本文が書き換わらない） |
| 7 | 対象のノートを開く | 処理中の表示のままではなく、処理が取り消されたことが示される |
| 8 | ユーザー B が実行中の一括ダウンロード（`bulkExport`）を持つ状態で viewer に降格する | viewer でも実行できる種別のため取り消されず、そのまま完了する |
| 9 | ユーザー B が実行中の Drive バックアップ（単体・一括のいずれでも）を持つ状態で viewer に降格する | バックアップは編集側の操作のため取り消され、`/jobs` で `canceled` になる |
| 10 | 降格後のユーザー B で `設計チーム` のノート詳細のメニューを開く | Drive バックアップの操作が表示されない（ダウンロードの操作は表示される） |
| 11 | ユーザー B を owner から editor に降格する | 実行中ジョブは 1 件も取り消されない（owner だけに許される操作に対応する処理の種別がないため） |

## TC-29: 期限切れ・使えない招待リンクを開く

**種別**: 異常系
**目的**: WS-04 の異常系を検証する

| # | 操作 | 期待結果 |
|---|---|---|
| 1 | 期限切れの招待リンクを開く | 期限切れである旨と、有効期限が 14 日であること・招待し直してもらう案内が表示される |
| 2 | 既に受諾済みの招待リンクを、招待された本人**以外**のアカウント（または未サインイン）で開く | 使えない招待であることだけが示され、招待し直してもらう案内が付く |

| 4 | 存在しないトークンのリンクを開く | 手順 2・3 と同じ表示になる |
| 5 | ワークスペースが削除された後の招待リンクを開く | 手順 2〜4 と同じ表示になる |

**確認ポイント**: 理由まで示すのは手順 1 の期限切れだけである。受諾・取り消し・ワークスペース削除はいずれも招待リンクの通り道自体を閉じるので、手順 2〜5 は存在しないトークンと区別されない — 区別すると、状態を答えること自体がそのトークンの実在を答えてしまう。いずれもトップへ戻る導線が付き、例外画面やスタックトレースにならないこと
