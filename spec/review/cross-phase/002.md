# クロスフェーズ検証 002

対象: `spec/` 配下すべて

## 1. ゴミ箱を空にする経路が一括操作の定義から漏れている

`emptyTrash` は 500 件を超える場合に「一括削除ジョブとして登録する」とし、`JobPayload` の `bulkDelete` は `mode: "trash" | "purge"` を持つ。しかし `requestBulkNoteOperation` の `BulkOperation` には `trash` しかなく、`runBulkNoteOperationItem` の処理も `trashNote` の呼び出しだけを定めている。完全削除を子ジョブとして実行する経路が定義されていない。

**対応**: `BulkOperation` に `purge` を加え、`runBulkNoteOperationItem` の分岐に `purgeNote` を加える。`emptyTrash` はこの経路を使う旨を明記する。

## 2. `moveNote` の後続処理にファイルの付け替えが書かれていない

クロスフェーズ検証 001 の対応で `relocateFilesForNote` を追加したが、`moveNote` の処理フローには「タグの付け替えは `note.moved` を購読するハンドラーが行う」としか書かれていない。`note.moved` の購読者が 3 つ（Tag / Storage / Usage）になったことが、移動を実装する側から見えない。

**対応**: `moveNote` の処理フローに `note.moved` の購読者を列挙する。
