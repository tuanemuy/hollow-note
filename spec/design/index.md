# デザイン方針

Hollow — あらゆるファイルを HTML に変換して保存・共有するサービスの UI デザイン方針。
数値で表現できる定義は [`tokens.md`](./tokens.md) を正典とする。本ファイルは数値にならない判断基準を扱う。

- **UI 構造**: 集中とコマンド — 常設ナビを持たない中央 1 カラム ＋ コマンドパレット
- **デザイン様式**: Apple Calm — apple.com / iCloud 系のミニマリズム ＋ GitHub Markdown 互換の本文表示

---

## 1. このプロダクトが何であるか

> 利用者はここに**自分では作れない形の文書**を投げ込み、読める HTML に変わったものを溜め、必要なぶんだけ人に見せる。

3 つの事実がすべての判断の起点になる。

1. **本文は他人が作ったもの**。PDF・Word・スライド・音声から生成された HTML が画面の大部分を占める。UI が色や装飾を持つと、本文が持ち込む色と競合する。だから UI は無彩色に徹し、彩度はすべて本文に譲る。
2. **変換は失敗しうる**。処理中・要 LLM 連携・変換失敗は例外ではなく日常の状態。これらを「エラー扱いで隅に押しやる」のではなく、一覧・詳細の第一級の情報として、静かに、しかし必ず見える形で置く。
3. **公開範囲は取り返しがつかない**。非公開 / リンクを知る人 / 公開の別は、常に視界にある。ただし警告色で脅すのではなく、6px のドット ＋ 文字で淡々と示す。

---

## 2. 全体のトーン

> 「読むための白い面と、呼べば出てくる道具」

- **白基調 ＋ 余白**。ベースは `--color-bg`。区切りは線ではなく余白で作り、線が要るときは限りなく薄いヘアラインを使う
- **アクセントは無彩色一色**（`--color-accent`）。色相を持たず明度だけで階調を作る
- **タイポグラフィは軽く、字間はわずかにタイト**。書体は 1 ファミリー、階層はサイズとウェイトだけで作る
- **角丸はコンテンツ系 12px、ピル系は完全な丸**。中間値は作らない
- **シャドウは浮く要素だけ**。ベース UI はシャドウなし
- **常設クロームは上下 2 本のバーだけ**。それ以外の枠・柱・パネルを画面に常駐させない

## 3. UI 構造

### 3.1 シェル体系

画面は 3 つのシェルのいずれかに属する。**どのシェルも常設サイドバーを持たない**。

| シェル | 対象 | 構成 |
|---|---|---|
| アプリシェル | L-01 配下のすべて（P-10〜P-16, P-20〜P-25, P-30〜P-34） | 上部バー ＋ 中央 1 カラム ＋（読む画面と選択モードでは）下端操作バー |
| 公開シェル | L-02 配下のすべて（P-40〜P-47） | 公開ヘッダー ＋ 中央 1 カラム ＋ フッター ＋（読む画面では）下端操作バー |
| 認証シェル | P-01〜P-06 | 最小のバー（マークのみ）＋ 中央 1 カラム |

**読む画面（P-11, P-12, P-44, P-45）はシェルの上の変形**であって 4 つ目のシェルではない。どちらのシェルでも「本文だけの中央 1 カラム ＋ 下端操作バー」になり、アプリシェルでは上部バーを戻る導線と ⌘K トリガーだけに絞り、公開シェルではヘッダーとフッターをそのまま残す。

シェルを増やさない。設定も管理的な画面も、アプリシェルの中央カラムに横タブで収める（§3.9）。

### 3.2 上部バー（アプリシェル）

高さ `--bar-height`、`position: sticky; top: 0`、半透明 ＋ `backdrop-filter`。載せるのは 5 つだけ。

```
[マーク] [スコープトークン ▾]  ────────  [⌘K 検索・操作] [アップロード] [アバター]
```

- **スコープトークン**: 現在の文脈（個人 / ワークスペース名）を常時表示し、押すとメニューが開く。この構造ではここが唯一の「今どこにいるか」の表示なので、**省略しない**（モバイルでもラベルを残し、長い名前は省略記号で詰める）。メニューには文脈の切り替え（個人 / 参加中ワークスペース / ワークスペースを作成）に続けて、**現在の文脈に属する行き先**（タグ管理・ゴミ箱、ワークスペース文脈ではワークスペース設定とその公開ページ）が並ぶ
- **⌘K トリガー**: `sm` 未満ではアイコンのみ、`sm` 以上でラベル ＋ キーチップ
- **アップロード**: プロダクトの主動線なので、パレットの中だけに畳まず常に露出させる
- **アバター**: **利用者本人に属する行き先**のメニュー — プロフィール / 自分の公開ページ / 処理履歴 / 設定 / サインアウト

行き先を 2 つのメニューに割る軸は帰属である（文脈に属するか、本人に属するか）。サイドバーは 1 本の柱にこの 2 種類を混ぜて置けたが、柱がない以上その軸を判断の基準に据えないと規則が失われる（[ADR 022](../adr/022-command-palette-navigation.md)）。

実行中ジョブの件数はバーに置かない（§3.4）。

### 3.3 コマンドパレット（⌘K）

**この構造の航法そのもの**。常設ナビが担っていた到達性をすべてここが引き受ける。

- 入口: `⌘K` / `Ctrl+K`、上部バーのトリガー、一覧の「絞り込み」チップ
- 入力欄の左に**現在のスコープをトークンとして固定表示**する。検索も操作もこのスコープに閉じることを、入力前から見せる
- セクションは常に同じ順で並べる: **ノート → 絞り込み → 移動・操作**
  - ノート: タイトル・本文の全文検索結果（一致箇所を太字で示す）
  - 絞り込み: タグ / 公開状態 / 変換状態 / 月。選ぶと一覧のチップ列に積まれる
  - 移動・操作: アップロード、新規作成、スコープ切替、タグ管理、ゴミ箱、処理履歴、設定、公開ページ
- フッターに `↑↓ 移動` `↵ 開く` `⌘↵ 新しいタブ` `esc 閉じる` を常時表示する。**キーボードだけで完結することを、UI 自身が教える**
- パネルは `--palette-max` / `--radius-lg` / `--shadow-lg`。上から 8vh の位置に置き、画面中央には置かない（入力欄が視線の高さに来るため）

**発見性の担保**（この構造の最大の弱点への対策、必須）:

1. 一覧のフィルタ列の末尾に `⌘K で絞り込み・移動・アップロード` のヒントチップを常に出す
2. 初回サインイン後の空状態（P-10）で、パレットの使い方を 1 行で教える
3. **パレットにしか入口がない機能を作らない**。すべての機能は、パレット以外に最低 1 つの視覚的な導線を持つ（上部バー、一覧ツールバー、アバターメニュー、下端操作バー、空状態 CTA のいずれか）。パレットは近道であって唯一路ではない

### 3.4 処理の可視化

実行中ジョブは**中央カラム最上部の 1 行ティッカー**で知らせる。

- 実行中が 0 件のときは何も出さない（行ごと消える）
- 1 件以上: スピナー ＋ `N 件を変換中 — {代表ファイル名} ほか M 件` ＋ 右端に「処理履歴」リンク
- 完了・失敗はトーストで通知し、ティッカーからは消える

**バッジ付きアイコンをバーに常駐させない**。この構造は「見えているものを減らす」ことに賭けているので、常時光る通知点を置くと主張が崩れる。件数は必要なときだけ 1 行で現れる。

### 3.5 中央カラムの幅の使い分け

| 幅 | 使う画面 |
|---|---|
| `--content-max`（680px） | ノート詳細 P-11、エディタ P-12 のプレビュー、公開ノート P-44、共有リンク P-45 |
| `--list-max`（780px） | ノート一覧（リスト表示）、ゴミ箱、タグ管理、処理履歴、設定各種、認証、ワークスペース設定 |
| `--wide-max`（1100px） | ノート一覧のタイル / カレンダー表示、処理履歴の親子ジョブ展開時 |

**幅の切替は表示形式に紐づけ、画面に紐づけない**。同じ P-10 でもリストなら 780px、タイル / カレンダーなら 1100px。切替時に本文の左端が動かないよう、どちらも中央揃えにする。

### 3.6 一覧（P-10）の構成

上から順に固定する。

1. ページタイトル（現在のスコープ名、`--text-3xl` / `--weight-light`）
2. 件数（`--text-sm` / `--color-ink-tertiary`）
3. ツールバー（選択モード・並び順・白紙から書く ／ 右端に表示形式セグメンテッド）。**新規作成の視覚的な入口はここだけ**なので畳まない（アップロードは上部バーが持つ）
4. 適用中のフィルタチップ列 ＋ `⌘K` ヒント
5. 一覧本体

**リスト表示は日付グループの見出しだけで区切る**（今日 / 今週 / 各月）。行の枠線も背景も持たず、ホバーでのみ `--color-surface-elevated` が敷かれる。行の構成:

```
[公開ドット] タイトル                                    [変換状態] [操作] 日付
             サブ情報（タグ · 元ファイル名 · 変換方式）
```

- タイトルは `--weight-regular`。詰めて並べないので 500 にしなくても読める
- 変換状態（変換中 62% / 要 LLM 連携 / 変換失敗）は右側に、色と文字の両方で示す
- 行アクション（タグ追加・メニュー）は `sm` 以上でホバー時に現れる。**`sm` 未満ではメニューボタンを常時表示**する（タッチではホバーが使えないため）

タイル表示は本文先頭からのサムネイル、カレンダー表示は月グリッド。どちらも `--wide-max`。

### 3.7 詳細（P-11）の構成

**読む面には操作を置かない**。

```
上部バー: [← スコープ名]  ────  [⌘K]
─────────────────────────────────
キッカー: ● 公開 · 2026年8月3日 · 山田 一郎
タイトル
本文
─────────────────────────────────
末尾: タグ / 折りたたみ「{元ファイル名} から変換 — 取り込み N 件」
      折りたたみ「公開 — {URL}」
下端操作バー: [編集] [公開範囲] [ダウンロード]  ──  [⋯]
```

- **取り込みの来歴は本文の後ろに折りたたむ**。サマリー行に「取り込み N 件」と、警告があれば右端に `未取り込み M 件` を出す。開くと元ファイル / 変換方式 / バックアップ / 取り込み済み / 取り込めなかったもの / 除去した CSS 宣言が並ぶ
- 取り込めなかったスタイルシートがある場合は、折りたたみを開いた中に `.alert`（warning）で「装飾が失われています」＋「表示スタイルで当て直せる」を示す。**サマリー行の警告ラベルだけで詳細を語らない**
- 見出しの一覧は**本文の直前に折りたたみとして置く**。追従する目次レールは作らない — 左右の余白に何も置かないという構造の主張を、目次のために崩さない。長い本文の中の移動はブラウザの検索と ⌘K も担う
- 処理中 / 要 LLM 連携 / 変換失敗の状態では、本文の位置にそれぞれの状態表示（進捗・連携導線・失敗理由と再試行）を置き、下端操作バーの内容を状態に応じて差し替える

### 3.8 下端操作バー

`position: sticky; bottom: 0`、上部バーと同じ質感。**操作の主体が「今開いているもの 1 つ」に定まる画面**でのみ使う。

- 使う: ノート詳細 P-11、エディタ P-12、公開ノート P-44、共有リンク P-45、一覧の選択モード（一括操作バー）
- 使わない: 一覧の通常表示、設定、処理履歴、ゴミ箱

一括操作バーも同じ枠に載せる（左に選択件数、続けて実行できる操作、右端に選択解除）。権限で操作が減る場合は**ボタンを消す**（無効化して並べない）。

### 3.9 設定・多セクション画面

個人設定（P-21〜P-25）とワークスペース設定（P-31〜P-34）は、中央カラムの上部に**水平タブ列**（P-20）を置く。

- タブ列は `sm` 未満で横スクロールを許す（ページ全体の横スクロールは禁止）
- ページ冒頭に h1 を置き、各セクションは h2 のパネルとして積む
- 個人設定とワークスペース設定はタブ列を分ける。行き来はスコープトークンとパレットから

### 3.10 ダイアログ

**パレットと同じ視覚言語**を使う: `--radius-lg` / `--shadow-lg` / 白地 / 上から 8vh。ダイアログを「別の世界」に見せない。

- `sm` 未満では**ボトムシート**（下端から迫り上がり、上端のみ角丸、ドラッグハンドル付き）
- 確認ダイアログは「何が起きるか」を本文 1〜2 行で述べ、破壊的操作のボタンは `--color-error` のテキスト色（塗りつぶさない）
- フォーカストラップと `Escape` での閉じるを必ず持つ

「モーダルは安易」という原則は本設計でも尊重する — **spec が明示的にダイアログを要求する箇所（移動、一括操作、削除確認、共有設定、エクスポート）にのみ使い、それ以外はページ内に展開する**。

## 4. デザイン様式（Apple Calm）の適用

### 4.1 タイポグラフィ階層

| 役割 | サイズ | ウェイト | 字間 |
|---|---|---|---|
| ページタイトル（一覧・設定） | `--text-3xl` | `--weight-light` | `--tracking-tightest` |
| ノートタイトル | `--text-3xl` | `--weight-regular` | `--tracking-tightest` |
| 本文内 h2 | `--text-xl` | `--weight-semibold` | `--tracking-tighter` |
| 本文内 h3 | `--text-lg` | `--weight-semibold` | `--tracking-tight` |
| 一覧行タイトル | `--text-md` | `--weight-regular` | `--tracking-tight` |
| UI ラベル・ボタン | `--text-sm` | `--weight-medium` | `--tracking-normal` |
| メタ・キャプション | `--text-xs` | `--weight-regular` | `--tracking-normal` |

**大きな見出しほど軽く**。これが Apple Calm の指紋で、逆をやると（大見出しを bold にすると）様式が壊れる。

### 4.2 カラーの役割分担

- `--color-ink`: 本文・タイトル・アクティブなラベル
- `--color-ink-secondary`: サブテキスト・非アクティブなボタンラベル。**本文には使わない**
- `--color-ink-tertiary`: メタ情報・プレースホルダー・区切り記号。コントラスト 3.6:1 なので**本文とボタンラベルには使わない**
- `--color-accent`: リンク・プライマリボタンの地・フォーカスリング・進捗バー
- セマンティック 4 色: 状態の表明のみ。**装飾に使わない**

### 4.3 形状と深さ

- ベース UI に影を置かない。区切りはヘアラインと余白
- 影を持つのは、**実際に手前に浮いているもの**だけ: パレット、ダイアログ、ドロップダウン、トースト、ボトムシート
- 上下のバーは影を持たず、`backdrop-filter` で奥行きを表す

### 4.4 余白の規律

- ページ上下は `--space-16`〜`--space-20`
- ブロック間は `--space-8`〜`--space-12`
- 行内は `--space-2`〜`--space-3`
- **中間の値を跳ばす**。`--space-5` と `--space-6` の両方を同じ文脈で使わない

## 5. 本文レンダリング（P-11 / P-44 / P-45）

ユーザーがアップロードした / 生成された HTML の描画は **GitHub README のレイアウト規約**を踏襲し、質感だけを Apple Calm に翻訳する。

| GitHub | Hollow | 補足 |
|---|---|---|
| `font-family: system-ui` | `--font-sans` | より厳密なフォールバック制御 |
| H1/H2 に bottom border | **どちらにも付けない** | この構造は本文の左右に何も置かないため、横線が入ると画面が分断されて見える。階層はサイズと余白で作る |
| body line-height 1.5 | `--leading-relaxed`（1.75） | 日本語の可読性 |
| `<code>` グレー背景 | `--color-surface` ＋ `--radius-xs` | |
| `<pre>` `#f6f8fa` + 6px | `--color-surface` ＋ `--radius-lg` | ボーダーなし |
| blockquote `0.25em solid` | `3px solid --color-hairline-strong` | テキストは `--color-ink-secondary` |
| table 縞 ＋ 全周ボーダー | 横ヘアラインのみ、外周なし | 横スクロールは `.table-wrap` に閉じる |
| `<a>` ブルー | `--color-accent` | ホバー時のみ下線（`text-underline-offset: 3px`） |
| `<img>` 角なし | `--radius-lg`、本文幅に収める | フルブリードにしない |

**GitHub から変えた点**で最も大きいのは H2 の下線を外したこと。左サイドバーが常に画面を縦に区切る構成なら本文内の横線も馴染むが、この構造では本文が画面唯一の要素なので、横線が「ページの終わり」に見えてしまう。

取り込んだ HTML は Shadow DOM で隔離し、上記は隔離境界の内側に注入する既定スタイル（`styleMode`）として適用する。利用者が既定スタイルを外した場合は、素の HTML がそのまま描画される。

## 6. レスポンシブ戦略

**モバイルファースト**。`min-width` ベース。

**この構造の最大の利点は、ブレークポイントでレイアウトが組み替わらないこと**。常設サイドバーがないので、モバイルとデスクトップで DOM 構造も情報階層も同じ。変わるのは次の 4 つだけ。

| 変化 | base | `sm` 以上 |
|---|---|---|
| ボタンのラベル | アイコンのみ | アイコン ＋ ラベル |
| フィルタ | 集約トリガー → ボトムシート | チップ列をインライン展開 |
| 行アクション | メニューボタンを常時表示 | ホバーで現れる |
| タイル列数 | 1 列 | `md` 2 列 / `lg` 3 列 / `xl` 4 列 |

- **タッチターゲット**: 譲れない床は WCAG 2.5.8 AA、目標は 2.5.5 AAA。タッチ主体の文脈（`pointer: coarse` / `sm` 未満）では目標を確保する。上部バーの密なコントロール行のみ、⌘K トリガーの高さ（30px）に揃えて床を外す局所例外を認める（バー全体の高さが 56px で、タップ可能な領域は視覚要素より広く取れるため）
- **スティッキー要素**: 上部バーと下端操作バーのみ。それ以外に追従要素を作らない
- **横スクロール**: テーブル・コードブロック・タブ列・横長メディアの単体スクロールは許可。**ページ全体の横スクロールは絶対に発生させない**
- **モバイル専用モックは作らない**。この構造ではデスクトップ版とモバイル版で構造が変わらないため、1 ファイルのレスポンシブで両方を表現し、構造が実際に分岐する箇所（フィルタのボトムシート、パレット、行アクション）は同一ファイル内に状態を並べて示す

## 7. インタラクション

- **ホバーは「薄く色が変わる」だけ**。`--color-surface` ↔ `--color-surface-hover`、または `--color-ink-secondary` → `--color-ink`。スケール変化・影の濃化はしない
- **トランジションは速め**。`--duration-fast`（120ms）を基本に、もたつきを感じさせない
- **タッチではホバーに依存しない**。ホバーでのみ現れる操作は `@media (hover: hover)` に閉じ、タッチ環境では常時表示か選択モードで代替する
- **フォーカス**: `:focus-visible` のみで `--shadow-focus`。キーボード航法が主要導線なので、リングは必ず見える状態に保つ
- **ロード状態**: スケルトンを優先。スピナーは進捗率が出せない短時間の処理（パレットの検索、ダウンロード生成）に限る
- **楽観的更新**: タグ付与・公開ステータス変更・削除は即座に画面へ反映し、`--opacity-pending` で保留を示す。失敗したら巻き戻して理由を出す
- **アニメーション**: 状態遷移を伝える補助のみ。`prefers-reduced-motion: reduce` で全 transition / animation を 0.01ms にする

### キーボードショートカット

この構造ではキーボードが一級の入力手段。最低限、次を持つ。

| キー | 動作 |
|---|---|
| `⌘K` / `Ctrl+K` | パレットを開く |
| `↑` `↓` | パレット / 一覧の候補移動 |
| `↵` | 開く |
| `⌘↵` | 新しいタブで開く |
| `esc` | パレット・ダイアログ・選択モードを閉じる |
| `U` | アップロード（パレット内から） |

ショートカットは**パレットのフッターと各行の右端で必ず可視化する**。隠れたショートカットを作らない。

## 8. 画像・アイコン

- **アイコン**: 線画・ストローク 1.5px・`currentColor`。塗り潰しアイコンと 2 トーンアイコンは使わない。サイズは 16 / 20 / 24px の 3 段階（16 未満の dense グリフは `--icon-*` トークン）
- **使う場面**: 上部バー、下端操作バー、パレット行、行アクション、空状態のアイキャッチ、状態バッジ
- **使わない場面**: 本文（Markdown 描画領域）、チップ内部、見出しの装飾、賑やかし
- **a11y 契約**: アイコン ＋ テキストのボタンではアイコンを `aria-hidden="true"` にしてテキストが accessible name を担う。アイコンのみのボタンでは `<button>` 側に `aria-label` を必ず付ける（アイコン側には付けず、二重化を避ける）
- **イラスト**: 空状態のみ、グレースケール ＋ 無彩色アクセントの線画。多色・キャラクター系は使わない
- **アバター**: 円形（`--radius-full`）、`linear-gradient(135deg, #c9d3df 0%, #8e99a8 100%)` のフォールバック
- **本文の画像**: `--radius-lg`、`width: 100%; height: auto;`、本文幅に収める。`loading="lazy"` / `decoding="async"` を基本、`object-fit: cover` を既定にしトリミングが重要要素を切らないアスペクト比（16/9, 4/3, 1/1）を選ぶ
- **ブランド**: マークは Vesica（二円の重なり）。上部バーではマーク単体、公開ヘッダーとランディングではマーク ＋ wordmark のロックアップを使う。マスター SVG と wordmark の決定は [`icons/index.md`](./icons/index.md)

## 9. フィードバックとエラー

- **即時 feedback**: 非同期処理を伴うボタンは押下直後に disabled ＋ ローディング状態にする
- **バックグラウンド進捗**: 取り込み・エクスポートはポーリングで進捗を可視化する。実行中は短い間隔、無い間は伸ばし、連続失敗時はバックオフを挟む
- **`aria-live`**: 状態遷移・完了・失敗は `polite`、即時に伝えるべきエラーのみ `assertive`

通知は 2 系統で使い分ける。

- **トースト**（一時的・グローバル）: 成功・保存完了・コピー完了・ジョブ受付など、結果のフィードバックだが文脈に残す必要がないもの。既定は右上、`sm` 未満は下端中央（下端操作バーがある画面ではその上）。白地（`--color-bg`）＋ `--shadow-md` ＋ `--radius-lg`、先頭にセマンティックアイコン、本文、任意で 1 つのアクションと閉じる ×。塗りつぶし背景もセマンティックバーも使わず、**アイコンの色だけで意味を出す**。4〜6 秒で自動 dismiss
- **インラインアラート（`.alert`）**（恒常的）: 文脈に紐づき消えずに残すべき注意喚起・案内・エラー。白地 ＋ セマンティックカラーのヘアライン枠（`color-mix(in oklab, var(--alert-accent) 30%, transparent)`）＋ `--shadow-xs`。アイコンと見出しを `--alert-accent` で着色、本文は `--color-ink-secondary`。`--alert-accent` 1 変数で `info` / `success` / `warning` / `error` を切り替え、modifier 無しは neutral

**同じ内容をトーストと `.alert` で二重に出さない。**

エラー文言は「何が起きたか ＋ 何をすればいいか」の 2 部構成にする。内部 stack / 原文 message / 内部エラーコードは UI に出さない。

## 10. 文言

UI に出る文字列は、**機能と結果を説明する文**に統一する。§1・§2 はプロダクトの性格を掴むための記述であって、UI コピーの下書きではない。設計文書の語り口をそのまま画面に載せない。

使わない書き方。

- **比喩・見立て**（「書庫」「投げ込む」「溜まる」）。機能名か実際の操作名（アップロード・ワークスペース・一覧に追加）で書く
- **体言止めの反復や倒置による情感**（「HTML にして、残して、必要なぶんだけ見せる。」）
- **呼びかけ・勧誘**（「まず 1 つ、〜してみてください」）。誘導はボタンラベルが担い、見出しには何が起きるかを書く
- **口語的な度合い表現**（「もう少し」「全部ここから」）。数値・条件で書く

書き方の基準。

- 見出しは名詞句か「〜する」の言い切り、本文は「です・ます」
- 主語はシステムの動作（「〜されます」「〜できます」）に置き、断定できる事実だけを書く。体験の価値づけはしない
- 数量・期限・上限は具体値で書く（「30 日で完全に消えます」「1 回あたり 100 件・合計 500 MB まで」）
- エラー文言は §9 の 2 部構成に従う

ノート本文・ノートタイトル・利用者のプロフィールなど、**利用者が書いた内容を再現しているダミーテキストはこの規律の対象外**。UI が発話する文字列だけを対象にする。

## 11. アクセシビリティ

- **コントラスト**: WCAG AA 以上（本文 4.5:1、UI 3:1）
  - `--color-ink` on `--color-bg` = 17.3:1
  - `--color-ink-secondary` on `--color-bg` = 5.0:1
  - `--color-ink-tertiary` on `--color-bg` = 3.6:1 → **本文とボタンラベルには使わない**。メタ・プレースホルダー専用
  - `--color-accent` on `--color-bg` = 9.3:1
- **フォーカス**: すべてのインタラクティブ要素で `:focus-visible` 時に `--shadow-focus`。outline はリセットしたうえで box-shadow で代替する
- **キーボード操作**: パレット・ダイアログ・ボトムシートはフォーカストラップと `Escape` を持つ。Tab 順は DOM 順
- **色だけに依存しない**: 公開ステータス（非公開 / リンク / 公開）と変換ステータスは、ドットの色だけでなく必ずテキストラベルを伴う
- **動きの抑制**: `prefers-reduced-motion: reduce` で全 transition / animation を 0.01ms にする
- **見出し**: 各ページは h1 を 1 つ持つ。設定画面のようにタブ列が現在地を示す構成でも、視覚非表示でよいので h1 を置く

## 12. 実装上の取り決め（HTML 試作）

- すべての試作（`spec/design/pages/*.html`）は単一ファイルでブラウザ表示できるようにする。CSS はインライン `<style>`、外部依存なし
- `:root` のトークンは [`tokens.md`](./tokens.md) の「ルート定義の最終形」をそのままコピーして使う
- ローカル変数（`--bg`, `--ink` などの短縮名）は使わず、トークンの正式名を使う
- 共通要素（上部バー、下端操作バー、パレット）は画面ごとに同じマークアップを貼る。この段階ではコンポーネント化しない
- レスポンシブは `min-width` ベース。特定範囲だけに適用したいスタイル（`sm` 未満でのみ行アクションを常時表示するなど）では `max-width` も使ってよい
- 1 画面に複数の状態がある場合、モックには**代表状態を 1 つ**描き、他の状態は別ファイル（`{name}-{state}.html`）に分ける。ただし次の 2 つは同一ファイルに並べてよい
  - **同じ領域を置き換えるだけの状態群**（ノート詳細の本文が「処理中 / 要 LLM 連携 / 変換失敗」に入れ替わる等）。シェルが共通で差分が本文だけなので、並べたほうが比較して判断できる
  - **ダイアログ・トーストのバリエーション**。1 つあたりが小さく、単独のファイルにすると比較できない
