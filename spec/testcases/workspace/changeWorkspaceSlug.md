# テストケース: changeWorkspaceSlug

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| owner で非公開のワークスペース | 未使用のスラッグに変更する | スラッグが更新され、`workspace.slugChanged` が旧スラッグつきで発行される | |
| 公開中のワークスペース | スラッグを `null` にする | `BusinessRuleError(PublishedWorkspaceRequiresSlug)` が投げられる | |
| 非公開のワークスペース | スラッグを `null` にする | 成功する。旧slugの `release` は応答喪失に備えて 1 度だけ再試行され、恒久的に失った場合も同じ要求（`null`）の再送が `workspace_directory` の広告から旧slugを拾って回収するので、そのslugは再び取得できるようになる（**解放は投影より先**に行うため手掛かりが消えない） | |
| 他のワークスペースが使用中のスラッグ | 変更する | `ConflictError("SLUG_ALREADY_USED")` が投げられる | |
| 自分と同じスラッグ | 同じ値に変更する | 変更もイベントも起きず成功する | |
| owner でない | 変更する | `BusinessRuleError(InsufficientRole)` が投げられる | |
| 公開中でスラッグを変更した | 旧スラッグの公開ページを開く | 「見つかりません」が返る | |
| 新slug予約後にlocal更新が失敗 | 変更する | この試行が保持する新reservationだけを解放し、旧slugを維持する | |
| 同じslugを狙う2つの要求のうち、片方が自分の理由（降格・バリア拒否）で落ちる | 同時に変更する | 落ちた試行は勝った試行の予約を落とさない | |
| local更新後にglobal切替応答を失う | recoveryを実行する | operation IDで新slugをactiveにしてから旧slugを解放する | |
| 切替を恒久的に失った後、同じslugをもう一度送る | 変更する | globalがscopeと食い違うときだけ予約と投影を打ち直し、新しい公開 URL が解決するようになる | |
| 切替を恒久的に失った後、**別の**スラッグを送る | 変更する | 手放す鍵は候補を 1 つに決めず scope の現在値と `workspace_directory` の広告値の両方を解放するので、`active` のまま取り残された旧鍵が解放され、再び取得できるようになる | |
| 切替を恒久的に失った後、スラッグを `null` にする | 変更する | 同じく両候補を `release` する（**解放は投影より先**なので手掛かりが消えない） | |
| 改名が commit も切替も終えたあとで投影を恒久的に失う | 変更する | scope と鍵は新slugへ進み、`workspace_directory` は旧slugを広告したまま残る。広告している鍵はもう誰も保持していない | |
| 投影を恒久的に失った後、**第 3 の**スラッグを送る | 変更する | 広告値ではなく scope が保持していた鍵が取り残される側なので、両候補を解放する形だけがそれを回収する | |
| 投影を恒久的に失った後、スラッグを `null` にする | 変更する | 同じく scope が保持していた鍵が `release` され、予約が 1 件も残らない | |
| 切替を失った改名のあと、投影も失った改名が新slugを `active` にした（鍵を 2 つ保持している） | 同じslugをもう一度送る | 再予約は global が scope と一致するのでスキップされるが、広告値の解放はスキップの外なので毎回評価され、もう一方の鍵が回収される | |
| 鍵を 2 つ保持し、`workspace_directory` が広告している側だけが公開 URL を解決している | **第 3 の**スラッグへ変更し、その切替も失う | 広告値の単独 `release` は `activate` の**後段**なので、交換が着地するまで生きた公開 URL を手放さない（どちらの URL も解決しない窓を作らない） | |
