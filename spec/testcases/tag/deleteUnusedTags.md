# テストケース: deleteUnusedTags

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| 使用件数 0 のタグが 4 件ある | 実行する | operationを開始し、完了時に4件が削除される | |
| 使用中のタグがある | 実行する | それらは削除されない | |
| 使用件数 0 のタグがない | 実行する | `deletedCount: 0` が返る | |
| ワークスペースの viewer | 実行する | `BusinessRuleError(InsufficientRole)` が投げられる | |
| 個人スコープで実行する | 実行する | ワークスペースのタグは削除されない | |
| 削除の経路 | 発行する処理を確認する | `deleteUnusedInScope(scope, 200)` とAlarm continuationを使い、1 turnのrow/event payloadを200件以下にする | |
| 使用件数 0 のタグが 3,000 件ある | 実行する | 15 turn以上に分けて全件を削除し、途中停止後も同じoperation IDで再開する | |
| 削除された | 発行イベントを確認する | 1page最大200 IDの `tag.unusedBatchDeleted` を1件発行し、3,000個の個別eventを一度に作らない | |
| 実行の直前に 1 件が別の要求で削除された | 実行する | 集合削除の対象に現れないだけで、残りの削除は成立する。`deletedCount` は実際に消えた行数を返す | |
| 画面に件数を出したあと、削除の直前に 1 件へ付与が付いた | 実行する | そのタグは削除されない。未使用かどうかの判定を削除の副問い合わせが削除の時点で行うため、列挙から削除までの窓が存在しない（`TagQueryService.listWithUsage` は画面表示用であって削除の根拠ではない） | |
