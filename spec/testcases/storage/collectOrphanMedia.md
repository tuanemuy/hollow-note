# テストケース: collectOrphanMedia

回収の条件は「**作成から 30 日が経過し、かつ本文から参照されていない**」の 2 つ。参照が外れた時刻は保持しないため、起点は作成時刻に取る。走査は所有者を絞らない `StoredFileRepository.listByPurposeOlderThan("media", now - 30 日, limit)` で行う。

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| 作成から 31 日が経過し、本文から参照されていないメディア | 実行する | 削除される | |
| 作成から 31 日が経過しているが、本文から参照されているメディア | 実行する | 削除されない（2 条件の AND） | |
| 作成から 29 日で、本文から参照されていないメディア | 実行する | 削除されない（境界値。参照が外れた時刻ではなく作成時刻で判定する） | |
| 作成からちょうど 30 日のメディア | 実行する | 走査の起点（`now - 30 日`）に含まれる（境界値） | |
| 走査の方法を確認する | 実行する | 所有者を絞らない全体走査のため `listByPurposeOlderThan("media", now - 30 日, limit)` を使う（所有者を必須とする `listByOwner` は使わない） | |
| 走査対象のメディア | 所属ノートの解決方法を確認する | `FileProvenance.noteId`（`media` では必須）からノートを引き、`HtmlProcessor.extractExternalReferences` で本文に URL が現れるかを調べる。本文の逆引きで所属を探すことはしない | |
| `noteId` の指す所属ノートが既に削除済みのメディア | 実行する | 削除対象として扱う | |
| 所属ノート（`noteId`）の本文からは参照が外れているが、別のノートの本文が同じ URL を参照している | 実行する | 判定は所属ノートの本文だけで行うため削除される | |
| `purpose` が `media` でないファイル | 実行する | 対象にならない（走査は `media` に限る） | |
| 対象が `limit` を超える | 実行する | `limit` 件だけ削除される | |
| 1 件の削除が失敗する | 実行する | 記録して継続する | |
| 対象が 0 件 | 実行する | `collectedCount: 0` が返る | |
