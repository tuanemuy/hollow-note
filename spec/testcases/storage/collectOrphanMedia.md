# テストケース: collectOrphanMedia

回収の条件は「**作成から 30 日が経過し、かつ本文から参照されていない**」の 2 つ。参照元に数えるのは現在の本文と保持している版（`NoteRevision.RETENTION` 件）の本文で、まだ復元できる版が指すメディアは残す。参照が外れた時刻は保持しないため、起点は作成時刻に取る。走査はcurrent scope内で所有者を絞らない `StoredFileRepository.listByPurposeOlderThan("media", now - 30 日, limit, cursor)` で行い、`cursor` は前の turn が止まった位置を排他的に指す（`null` は先頭）。1 turn は「読む行数」（`limit`）・「本文を読むノート数」（5 件）・「同時に保持する本文の文字数」（16,000,000 文字）の 3 つで有界で、後ろ 2 つに当たったページは判定し終えた位置から続きの turn を回す。

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| 作成から 31 日が経過し、本文から参照されていないメディア | 実行する | 削除される | |
| 作成から 31 日が経過しているが、本文から参照されているメディア | 実行する | 削除されない（2 条件の AND） | |
| 現在の本文からは参照が外れているが、保持中の版の本文がまだ参照しているメディア | 実行する | 削除されない（版から復元した本文の画像が生きているよう、版の本文も参照元に数える） | |
| 作成から 29 日で、本文から参照されていないメディア | 実行する | 削除されない（境界値。参照が外れた時刻ではなく作成時刻で判定する） | |
| 作成からちょうど 30 日のメディア | 実行する | 走査の起点（`now - 30 日`）に含まれる（境界値） | |
| 走査の方法を確認する | 実行する | 所有者を絞らない全体走査のため `listByPurposeOlderThan("media", now - 30 日, limit, cursor)` を使う（所有者を必須とする `listByOwner` は使わない） | |
| 走査対象のメディア | 所属ノートの解決方法を確認する | `FileProvenance.noteId`（`media` では必須）からノートを引き、`HtmlProcessor.extractExternalReferences` で本文に URL が現れるかを調べる。本文の逆引きで所属を探すことはしない | |
| `noteId` の指す所属ノートが既に削除済みのメディア | 実行する | 削除対象として扱う | |
| 所属ノート（`noteId`）の本文からは参照が外れているが、別のノートの本文が同じ URL を参照している | 実行する | 判定は所属ノートの本文だけで行うため削除される | |
| `purpose` が `media` でないファイル | 実行する | 対象にならない（走査は `media` に限る） | |
| 走査の対象が `limit` を超える | 実行する | 1 turn が読むのは `limit` 行までで、削除されるのはその中の孤児だけである（`limit` は読む行数の上限であって削除件数の上限ではない）。残りは次の turn がカーソルの先から読む | |
| scopeにmediaが初めて流入する（保管、またはノート移動の受け入れ） | taskを確認する | 当該scopeの日次taskが自己登録される。2 回目以降は `dueAt` を押し出さない | |
| ページが満ちた | Alarm設定を確認する | 読んだ最後の行の `(createdAt, id)` を payload に載せた残件用taskを直後に設定し、後ろに何も無くなった turn で翌日へ戻る。継続の条件は「回収できたか」ではなく「ページが満ちたか」 | |
| 1 ページの中で 6 つ目のノートに当たる（ノート数の予算は 5） | 実行する | その手前で走査を打ち切り、判定し終えた最後の行の位置を載せた継続を直後に積む。ページが満ちていなくても継続する（本文の解析回数はファイル数ではなくノート数で有界にする） | |
| 1 ノートの本文（現在＋保持中の版 20 本）だけで文字数の予算 16,000,000 に達し、次に別のノートのファイルが並ぶ | 実行する | 次のノートを読む前に走査を打ち切り、ノート数の予算と同じく判定し終えた最後の行の位置を載せた継続を直後に積む（1 turn が同時に保持する本文の量を isolate の上限の内側に収める） | |
| 本文から参照され続けている media が `limit` 件並び、その後ろに孤児がある | 2 turn 実行する | 1 turn 目は 0 件回収して満ページのまま継続し、2 turn 目がカーソルの先の孤児を回収する（先頭を読み直さない） | |
| task の payload に読める位置が無い | 実行する | 失敗させず先頭からやり直す（掃引行を `failed` に駐車させないため）。位置を名指しながら読めない payload では `logger.warn` を 1 行残し、位置を持たない日次の payload では残さない | |
| 1 件の削除が失敗する | 実行する | 記録して継続する | |
| turn 全体が失敗する | 実行する | 記録して翌日の掃引を張り直し、`collectedCount: 0` で正常終了する（`backoff` を回さず、scope 唯一の掃引行を上限で `failed` に駐車させないため）。張り直し自体が失敗したときだけ throw する | |
| turn 全体が失敗する | 位置を確認する | 開始した位置をそのまま張り直しの payload と `nextCursor` に載せる（先頭へ戻すと、解消しない失敗を持つページを毎日読み直してその後ろを永久に見なくなる） | |
| 対象が 0 件 | 実行する | `collectedCount: 0` が返る | |
