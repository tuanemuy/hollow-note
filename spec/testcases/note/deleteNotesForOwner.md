# テストケース: deleteNotesForOwner

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| 退会処理中の利用者の個人所有ノートが 10 件ある（ゴミ箱の 2 件を含む） | account deletionのpersonal cleanup commandを処理する | `listByOwner(owner, "all", pagination)` で生死を問わず読み、10 件すべてが削除され、1 件ごとに `note.purged` が発行され、`purgedCount: 10` が返る | |
| ゴミ箱のノートだけを持つ利用者 | 処理する | `lifecycle: "all"` で引くため、ゴミ箱のノートも取りこぼさず削除される | |
| 退会者が作成したワークスペース所有のノートがある | account deletionのpersonal cleanup commandを処理する | そのノートは削除されない（AC-09。消えるのは個人所有のみ） | |
| 削除されたワークスペースの所有ノートがある | `workspace.deleted` を処理する | そのワークスペース所有のノートがすべて削除される | |
| メンバーの個人所有ノートがある | `workspace.deleted` を処理する | 個人所有のノートは削除されない | |
| 削除が完了した | タグ付与・保管ファイル・バックアップ記録・読み取りモデル・件数を確認する | `note.purged` の購読者（`purgeNote` と同じ受け手）によって後始末される | |
| 対象が `batchSize`（既定 40 件）ちょうど | 処理する | 全件が処理され、継続要求は積まれない（境界値） | |
| 対象が 41 件 | 処理する | 40 件を処理してcurrent scopeのcontinuation taskを1件だけ積み、残り1件は次のAlarm turnで削除される | |
| 継続が要る | 積まれたイベントを確認する | `deletionOperationId`を保持した購読者1件の`note.ownerPurgeContinued`だけを積み、受け取った削除eventは再投入しない | |
| 継続要求を受け取る | 処理する | `ownerType` / `ownerId` から対象を組み立て直し、残っているものを先頭から `batchSize` 件読んで続きを削除する（カーソルは持たない — 対象は処理するそばから消えるため先頭から読むだけで前に進む） | |
| 対象が残っているのにそのバッチで 1 件も削除できなかった | 処理する | 継続要求を積まず、失敗として返る（キューの再試行と DLQ に委ねる。恒久的に失敗する 1 件が列の先頭に居座って継続が無限に回るのを防ぐ） | |
| 継続要求が重複配送され 2 系列が並走する | 処理する | 両系列とも「残っているものを読んで消す」だけなので結果は変わらず、対象が 0 件になった系列から順に継続をやめる | |
| 1 バッチを処理する | 上限根拠を確認する | `batchSize` 40 は 1 Alarm turn の CPU と purge/public-remove event fan-out に加えて、1 件 11〜12 文かかる global D1 statement 数（40 × 12 = 480）を設計上限 500 の内側に収める値である | |
| 対象のノートが 1 件もない | 処理する | 何もせず成功として返る | |
| 個々の削除が失敗する | 処理する | 記録して次のノートへ継続する（再配送・継続要求でやり直す） | |
| 同じイベントを 2 回受け取る | 2 回処理する | 削除済みのノートは `listByOwner` に現れず、2 回目は 0 件で終わる（冪等） | |
| 対象ノートの route が別 operation の `purging` のまま停止している | 処理する | そのノートは purge されず、`purgedCount` に数えず、`note` 成分を ack しない（他人が握る route は「ノートが消えた」ことを何も意味しない） |  |
| local delete が commit した直後に purge が停止した | 処理する | そのノート ID を継続要求の payload に載せ、次の turn が route を再claimして public remove 以降を再開する。tombstone に到達して初めて `note` 成分を ack する |  |
| 持ち回っている対象が次の turn でも解消せず、他に削除できたものも無い | 処理する | 新しく持ち回る対象が増えないので継続を積まず、現在taskをbackoffする（`note` 成分は ack しない） |  |
| 持ち回っている対象が残ったまま、その turn の列挙が尽きた | 処理する | 列挙が空でも継続要求を積み直し、`note` 成分を ack しない |  |
| 持ち回っていた purge が完了し、ページにはまだノートが残る | 処理する | 持ち回りの完了はページの残件を肩代わりしない（列挙が尽きていないので継続する） |  |
