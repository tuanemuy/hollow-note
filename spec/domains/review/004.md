# ドメインレビュー 004

対象: `spec/domains/` 配下すべて

## 結果

対応が必要な問題は見つからなかった。

### 実装可能性

- 9 ドメインすべてで、エンティティのフィールド・型・制約、振る舞いのシグネチャと処理内容、不変条件、ライフサイクルが定義されている
- 値オブジェクトはすべてバリデーションルールと等価性を持つ
- ドメインサービスはメソッドのシグネチャ・処理・依存ポートを持つ
- ポートはすべてメソッドシグネチャとエラーケースを持つ。未定義のまま残っているメソッドはない
- 振る舞いを持たないエンティティはない。Conversion は永続状態を持たないため、その旨を明示したうえでドメインサービスにロジックを置いている

### 状態表現

排他的な状態はすべて判別可能なユニオンで表現されている。boolean フラグや optional の併置で「あり得ない組み合わせ」を作れる箇所はない。

- `User`: pending / active
- `Identity`: password / oauth
- `AuthToken`: pending / consumed
- `Workspace`: private / published（published は `slug` 必須）
- `Invitation`: pending / accepted / revoked
- `Note`: active / trashed、`content` 4 状態、`visibility` 3 状態（unlisted は `shareLink` 必須）
- `StoredFile`: persistent / ephemeral
- `ExternalConnection`: active / expired（expired は資格情報を持たない）
- `Job`: queued / running / succeeded / failed / canceled（`artifact` は succeeded のみ）
- `ConversionPlan`: 8 種の判別ユニオン

### アーキテクチャ適合性

- ドメインモデルに DB / HTTP / フレームワークの関心事は現れていない。時刻と ID は引数とポートで受け取る
- ビジネスルールはエンティティの振る舞いとドメインサービスに置かれている
- 集約をまたぐ参照はすべて ID による。エンティティを直接保持している箇所はない
- 依存方向は `Identity → Workspace → Storage → Conversion → Note → {Tag, Integration, Job, Usage}` の順で、循環はない

### ビジネスロジックの網羅

シナリオ側の異常系がドメインの不変条件・エラーコードとして表現されていることを確認した。とくに次の分岐がドメインに存在する。

- 最後の認証手段の削除不可（`IdentityPolicy.ensureRemovable`）
- 最後の owner の降格・脱退不可（`MembershipPolicy.ensureOwnerRemains`）
- 本文が空のノートの公開不可（`Note.makeUnlisted` / `makePublic`）
- 処理中ノートの移動不可（`NoteOwnershipPolicy.ensureMovable`）
- 共有パスワード変更による通過証の失効（`ShareLink.passwordUpdatedAt`）
- 失効した連携での変換・バックアップ不可（`CredentialResolver.resolve`）
- ジョブの終端状態からの遷移不可と再試行上限（`Job` の状態ユニオンと `AttemptCount`）
- クォータ超過（`QuotaEnforcement.ensureUploadAllowed`）
