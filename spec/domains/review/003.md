# ドメインレビュー 003

対象: `spec/domains/` 配下すべて

## 1. `MarkdownRenderer.toMarkdown` が Conversion → Note の循環依存を作る

`conversion.md` の `MarkdownRenderer.toMarkdown(html: NoteHtml): string` は Note ドメインの値オブジェクトを引数に取っている。Note は `ConversionFailureReason` を通じて Conversion に依存しているため、この参照によって Note ↔ Conversion の循環が生まれる。アーキテクチャ制約の「ドメイン間の非循環」に反する。

**対応**: `toMarkdown` は生の文字列を受け取る形にする。`NoteHtml` から文字列への変換はブランド型が原始型へ自然に広がるため、呼び出し側でキャストは不要。

## 2. `MailSender` ポートのシグネチャが未定義

`domains/index.md` の横断的な関心事に `application/ports/mailSender.ts` を新設すると書かれているだけで、メソッドも送信するメッセージの型も定義されていない。Identity（確認・再設定）と Workspace（招待）の両方がこれに依存するため、シグネチャがないとどちらも実装できない。

**対応**: `domains/index.md` に横断的ポートの定義を追加する。

## 3. `setSharePassword` が `passwordUpdatedAt` を更新する旨を書いていない

レビュー 002 の対応で `ShareLink` に `passwordUpdatedAt` を加えたが、`Note.setSharePassword` の処理内容にはその更新が書かれていない。通過証の失効判定はこのフィールドの更新に依存しているため、書かれていないと実装が抜ける。

**対応**: `setSharePassword` の処理に `passwordUpdatedAt = now` の更新を明記する。
