# ドメインレビュー 002

対象: `spec/domains/` 配下すべて

## 1. 「仮題」の判定が定義されていない

`Note.applyConversionResult` は「`title` が渡され、かつ現在のタイトルが仮題なら差し替える」としているが、何をもって仮題とするかが書かれていない。アップロード時はファイル名からタイトルを付ける想定であり、利用者が明示的に付け直したタイトルを変換結果で上書きしてはならない。判定規則がないと実装できない。

**対応**: `Note` にタイトルの由来を持たせ、由来が「自動」のときだけ差し替える。

## 2. 共有パスワードの通過状態の失効判定が設計に存在しない

SH-06 は「通過した状態は 24 時間その端末で保持される」「所有者がパスワードを変更・解除した場合、保持していた通過状態は失効する」と定めている。`NoteAccessPolicy` は `credential.passwordVerified: boolean` を受け取るだけで、その真偽をどう決めるかがどのドメインにもない。

**対応**: `ShareLink` にパスワードの更新時刻を持たせ、通過証（クライアントが保持する値）にその時刻を含めて照合する規則を Note ドメインに定義する。

## 3. 月による絞り込みのタイムゾーンが型に現れていない

OR-05 は「利用者のタイムゾーンで月の境界を判定する」としているが、`NoteSearchCriteria.month: YearMonth` にはタイムゾーンの情報がない。`YearMonth` だけでは境界を決められず、実装者は UTC を仮定してしまう。

**対応**: 絞り込みの条件を、タイムゾーンを解決したあとの日時範囲として渡す形に改める。

## 4. `TagRelocationPolicy.plan` の戻り値が付け替え対象と対応づかない

`RelocationPlan.reassignTo: readonly TagId[]` は移動先のタグ ID を並べるだけで、どの既存の付与を置き換えるものなのかが分からない。付与は削除して作り直す設計なので、実装者は「どの付与を消して、どのタグで作り直すか」の対応が必要になる。

**対応**: 付与 ID と移動先タグ ID の組を返す形に改める。
