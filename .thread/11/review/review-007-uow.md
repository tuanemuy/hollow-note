#### Warnings

- **[W-001]** `leaseMsOf` の 3 分岐のうち、ADR-094 が「黙って既定へ戻さない」と決めた**不正値 → `dataIntegrityError`** の分岐と、**未設定 / 空文字 → 定数**の分岐が、どのテストからも観測されていない
  - 場所: `packages/core/src/adapters/cloudflare/do/scopeObject.ts:71-84`（テスト側は `packages/core/src/adapters/cloudflare/__tests__/alarm.test.ts:886`「grants the lease the deployment configured」が唯一の観測点）
  - 理由: `withLeaseMs(instance, "90000")` が通す正常値の分岐だけがテストされている。`SCOPE_TASK_LEASE_MS` を `"abc"` / `"0"` / `"-1"` / `"1.5"` に置いた turn が落ちること、および未設定の turn が `SCOPE_TASK_LEASE_MS` 定数の lease を切ることは、いずれも assert されていない。この決定の要点はまさに「不正値で既定へフォールバックしない」ことで（ADR-094 Decision 2 番目の箇条・`spec/platform/index.md:195` の「正の整数のミリ秒でない値は turn を落とす」）、`leaseMsOf` を `Number(raw) || SCOPE_TASK_LEASE_MS` の 1 行へ戻しても全テストが緑のまま通る。fencing token を持たない settle の安全性が「配備が帯の中から値を選べること」に全面的に依存している以上（ADR-094 Context）、帯の外の値を黙って受け入れる退行はこの PR で最も気づきにくい部類に入る。
    加えて、既定値の分岐は他の alarm テストが暗黙に通しているだけで、「未設定なら 300000ms」という数値そのものはどこにも固定されていない。`alarm.test.ts:135` の `withLeaseMs` はすでに env を差し替えるヘルパーを持っているので、追加コストはほぼゼロ。
  - 提案: `alarm.test.ts` に 2 ケース足す。(a) `withLeaseMs(instance, "0")`（および文字列 1 種）で `runDurableObjectAlarm` が reject し、`scheduled_tasks` の行が `pending` のまま `attempts` も動かないこと — 「turn は落ちるが行は巻き込まれない」まで観測すると ADR-094 Consequences のトレードオフ記述と 1 対 1 になる。(b) env を触らない turn の `lease_expires_at` が `before + SCOPE_TASK_LEASE_MS` 〜 `after + SCOPE_TASK_LEASE_MS` に収まること。
