#### Blockers
- **[B-001]** `inlineStylesheets` の `</style` 無害化が 1 回置換なので、重なった綴りで `<style>` を突き破れる（保存型 XSS の穴）
  - 場所: `packages/core/src/adapters/html/htmlProcessor.ts:1080`（`filtered.replace(/<\/style/gi, "")`）、`packages/core/src/adapters/html/__tests__/htmlProcessor.test.ts:1249`
  - 理由: `String.prototype.replace` は重ならない一致を 1 パスで消すだけなので、取得した CSS が `a{}</st</styleyle><img src=x onerror=alert(1)>` のとき内側の `</style` を消した残りが `</style` に合流する。実際に現在のツリーで `inlineStylesheets` を呼ぶと戻り値は `<style data-imported-stylesheet="…">a{}</style><img src=x onerror=alert(1)></style>` になり、`<style>` の raw text から `<img onerror>` が要素として抜け出す（再現手順: `processor.inlineStylesheets(body, new Map([[url, "a{}</st</styleyle><img src=x onerror=alert(1)>"]]), new Set())`）。ポートの JSDoc（`domain/note/ports/htmlProcessor.ts:161-165`）は「the sheet arrives from a third-party origin and nothing downstream re-sanitizes what it returns」と、この戻り値がそのまま保存される前提を契約として書いているので、呼び手（Issue #6 の `importExternalReferences`）が着地した瞬間に、参照先の CSS を握る第三者が公開ページにスクリプトを置ける。既存テストは `</style` が 1 回だけ現れる入力しか検証しておらず（`not.toContain("</style><script")` と再 `process` の `removed` が空であること）、この形を検出しない。ADR 013「規則の正典を 1 か所に置く」が `<style>` へのインライン化に「次項の制約を等しく適用する」と約束している面の穴で、`process` 側の raw text 境界（トークナイザーが `</style` で切るので生成不能）と対称になっていない
  - 提案: 消すのではなく **再一致が生じない形に書き換える**。例: `filtered.replace(/<\/(?=style)/gi, "<\\/")` — CSS では `\/` は `/` のエスケープなのでブラウザの CSS パーサーにとって意味は変わらず、HTML トークナイザーは `<\/style` を終了タグと読まない。置換結果に `</style` が再出現しないこと（`<\/` は `</` を含まない）と、再 `process` で不動点であることをテストに足す。少なくとも `expect(inlined).not.toMatch(/<\/style/i)` を `</st</styleyle` 入力に対して置く。ループ置換（`while (/<\/style/i.test(s))`）でも塞がるが、`</` を残したまま消す形は次の綴り（`</st</st</styleyleyle`）で同じ論証を繰り返すことになる
