#### Warnings

- **[W-001]** 継続 reader `readNotePurgeTurn` は `deletionOperationId: ""` を「障壁なし（`null`）」として黙って読み替える
  - 場所: `packages/core/src/application/cleanup/notePurgeFanOut.ts:94-102`（`typeof token === "string" && token.length > 0 ? token : null`）、テストで固定: `packages/core/src/application/workers/__tests__/subscribers.test.ts:578-592`
  - 理由: `""` はどの書き手も生まない値である（`settleNotePurgeTurn` は `null` か非空文字しか書かず、`note.purged` の `deletionOperationId` は `string | null`）。したがって `""` は「鍵があるのに読めない」側の値で、`noteId: "   "` を fault させたのと同じ整理に属する。いまの読み替えは、削除由来の turn を通常 purge へ格下げして admission（`assertNotePurgeAdmission`）を飛ばし、再 arm の priority も `securityCleanup` から `expiryCollection` へ落とす。行そのものは purge 済みノートの残骸なので削除結果に害は無いが、`spec/domains/index.md`「読めない payload の扱い」が要求する「仕事を名指す欄が読めなければ fault」の網から `deletionOperationId` だけが外れており、握り潰しの形になっている
  - 提案: `token === ""`（trim 後に空）を `corrupt("payload carries an empty deletionOperationId")` で fault させ、テストの「absent, null or empty」から empty を fault 側へ移す。あるいは意図的に許容するなら、なぜ空文字を `null` と同一視してよいのかを JSDoc に 1 文置く
