# レビュー 010 — frontend

### frontend

#### Blockers

- **[B-001]** `NoteDetailIsland` の props 同期 effect が、`reconcile()` の解決と断片の到着のあいだの窓で版・保存済みタイトル・表示スタイルを **古い props へ巻き戻す**。低速回線ではタイトルの変更が競合として巻き戻り、さらに次の自動保存が古いタイトルをサーバーへ書き戻す
  - 場所: `apps/web/app/components/note/NoteDetail/detail.tsx:156-161`（`useEffect(() => { if (busy) return; versionRef.current = initialVersion; setSavedTitle(initialTitle); setStyleMode(initialStyleMode); }, [busy, ...])`）
  - 理由: `reconcile()` は `router.invalidate()` の解決で返るが、loader は `renderServerFragment(...)` の promise を await せずに返す（`presentation/serverFragment.ts` / `components/ui/Deferred/index.tsx` の JSDoc「navigation settles immediately and the unresolved leaf streams in」）。`Deferred` は `useDeferredValue` で旧 payload を保持するので、島の props が新しくなるのは Flight payload が届いた **後** である。一方 `busy` は `runExclusive` の `finally` と transition の完了で下りるので、`reconcile()` が返った直後に **props はまだ古いまま** effect が走る。具体的には `saveTitle` 成功後: `versionRef = v+1`, `savedTitle = T2` → `await reconcile()` → `busy=false` → effect が `versionRef = v`（旧）, `savedTitle = T1`（旧）に戻す → `title(T2) !== savedTitle(T1)` で「未保存」が出て 800 ms 後に自動保存が **古い版 v** で `rename` → `OPTIMISTIC_LOCK_FAILURE` → `catch` の `setTitle(savedTitle)` で入力欄が **T1 に戻る** → その後 断片が届いて `savedTitle = T2` になると `title(T1) !== savedTitle(T2)` で自動保存が走り、サーバーのタイトルを **T1 に戻す**。断片の到着が 800 ms 以上遅れる条件（本文が大きいノート × 低速回線。P-11 の断片は本文 HTML を丸ごと運ぶ）で再現し、利用者の改題が黙って取り消される。同じ窓で `setStyleMode(initialStyleMode)` も旧値へ戻るので、ED-11 の「その場で表示が変わる」が一瞬戻ってから再適用される。`onBlur` の即時保存（`detail.tsx:354-356`）も同じ窓で同じ競合に落ちる
  - 提案: 取り込みを **版の単調性で門にする**。`if (busy || initialVersion < versionRef.current) return;` を effect の先頭に置き、props が島の持つ版より新しい（または等しい）ときだけ `versionRef` / `savedTitle` / `styleMode` を揃える。版は単調増加なので、古い断片からの巻き戻りだけが弾かれ、失敗後の引き直し（本来の目的）はそのまま通る。`spec/pages/index.md` P-11 状態表「操作実行中」の「正本を引き直し、版・保存済みタイトル・表示スタイルを揃え直す」に「島が持つ版より古い正本では揃えない」を一行足す。同じ根（`reconcile()` が断片より先に返る）は `NoteList/board.tsx` / `TrashList/board.tsx` の `useOptimistic` にもあり、transition の終了から断片の到着までのあいだ除いた行が一瞬戻る — こちらは版を持ち回らないので表示だけの揺れであり、ここでは指摘に含めない

- **[B-002]** 保存後の載せ直しの失敗を `{ kind: "mode" }` に分類したことで、その「再試行」が **失敗後に打った内容を確認なしに捨てる** 経路になった。あわせて `failed` の表示文言が「保存できませんでした」「内容はまだこの端末に退避していません」と、**通っている保存** を失敗と告げる
  - 場所: `apps/web/app/components/note/NoteEditor/editor.tsx:763-775`（`commit` の `reseedIfUnchanged` の `catch`）、`editor.tsx:1574-1589`（`retryFailed` の `case "mode": applyMode(target.mode, target.acknowledged)`）、`editor.tsx:1781-1828`（`failed` の Alert）、`editor.tsx:759-762`（自己回復の JSDoc）
  - 理由: 載せ直しが通信エラーで落ちると状態は `failed` になり、自動保存は `failed` から再開しない（`editor.tsx:966-973`）。面は `editable` のままなので利用者は打ち続けられる。そこで「再試行」を押すと `applyMode(mode)` → `runExclusive("reseeding")` → `reseedFromServer` → `seedMode` → `reseed` → `loadSurface` が **正本で面を置き換える** — これは `discard` と同じ経路であり、`requestMode`（`dirty` なら `pendingMode` で確認）や `acknowledgeWysiwyg`（`dirty` なら引き直さない）が必ず挟む `dirty` の門がここには無い。前ラウンドまでは `{ kind: "save" }` だったので再試行は `commit` を走らせ内容を捨てなかった。分類は正しくなったが、**再試行が破棄になる** 穴が新しく開いている。ビジュアルモードでは skip があるたび（`needsReseed = nextSkipped.length > 0`）と丸ごと保存のたびに載せ直しが走るので到達は容易である。さらに JSDoc（759-762 行）の「落ちたままでも次の保存は『丸ごと送る枝』へ落ちて…打鍵の無い往復が 1 回あれば噛み合いが戻る」は skip 経路では偽 — `settled()` は `pathwise: sent.visual.pathwise`（真のまま）を確定させるので次の保存も経路単位で送り、差し戻した `before` を `expected` に再送して再び `contentChanged` になる。表示側も `RetryTarget` を見ずに保存前提の文言（Alert の title「保存できませんでした」、`SaveIndicator` の「保存に失敗しました」、本文「内容はまだこの端末に退避していません。もう一度お試しください」）を出す
  - 提案: どちらか一方で塞ぐ。(a) `commit` の載せ直しの失敗を `failed` にしない — `confirmedRef` の `visual.pathwise` を `false` に落として `saved` のまま返し、次の自動保存が丸ごと送る枝に落ちて載せ直しをもう一度試みる（JSDoc の自己回復を実際に成り立たせる）。(b) `failed` に残すなら `retryFailed("mode")` に `requestMode` と同じ門を置く（`dirty` なら `setPendingMode(target.mode)` で「保存して切り替える」に合流させ、載せ直し前に打鍵を保存する）。いずれの場合も `failed` の Alert は `status.retry.kind` で分岐し、`mode` / `conflict` / `revision` では「保存は完了しています。面を載せ直せませんでした」の趣旨にする。`spec/pages/index.md` P-12「保存失敗」行の「再試行が送り直すのは落ちた往復そのもの」に「載せ直しの再試行は未保存の内容を捨てない」を足す

#### Warnings

- **[W-001]** 面の scrub が SVG のアニメーション要素を素通しするため、`javascript:` を `href` に **後から流し込む** 断片が live DOM に載る（サーバーはこの要素を落とす）
  - 場所: `apps/web/app/components/note/NoteEditor/surfaces.tsx:276-343`（`UNSAFE_DROP_ELEMENTS` / `UNSAFE_UNWRAP_ELEMENTS` / `scrubForSurface`）
  - 理由: `<svg><a><animate attributeName="href" values="javascript:alert(1)"/><text>x</text></a></svg>`（`set` / `animateMotion` / `animateTransform` も同様）は `on*` も URL 属性も持たないので、`isAllowedUrl` の判定に一度も掛からない。`URL_ATTRIBUTES` の判定そのものは制御文字・大文字小文字・エンティティ・`data:` の各迂回を `urlPolicy.ts` の `stripControls` / `schemeOf` / `isAllowedDataUrl` で塞げていることを確認した（面と `HtmlProcessor` で同じ関数を呼び、面が落とす集合は保存の部分集合に収まっている）。この 1 経路だけは URL の判定ではなく **要素の許可** の問題で、サーバー側は `ALLOWED_SVG_ELEMENTS`（`adapters/html/allowList.ts:240`）に無いので unwrap するが、面は残す。未保存の本文が面へ入る経路（WYSIWYG の貼り付け・退避の復元）は実在し、保存後も WYSIWYG / HTML の面は載せ直さないので、貼った要素はサニタイズ済みの正本で置き換わらないまま画面に残る
  - 提案: `UNSAFE_DROP_ELEMENTS` に `animate` / `set` / `animateMotion` / `animateTransform`（`localName` は小文字化して比較）を足す。より堅くするなら `svg` 配下は `ALLOWED_SVG_ELEMENTS` に無い要素を unwrap する（保存側と同じ表を `@repo/core/adapters/html/allowList` から引く）。`spec/manual-tests/editing.md` の TC-17 系に「`<svg><a><animate attributeName=href values=javascript:…>` を貼っても面でクリックしても何も起きない」を 1 行足す

- **[W-002]** サーバー関数の JSDoc が、この PR で変わった契約・手順書と食い違っている
  - 場所: `apps/web/app/routes/notes/-action.tsx:112-124`（`moveNoteFn`）、`apps/web/app/routes/workspaces/$workspaceId/-action.tsx:130-133`（`renderWorkspaceNoteEditor`）
  - 理由: (a) `moveNoteFn` の「`expectedVersion` を転送境界で受け取らないのは `getNote` の DTO がノートの版を持たないため…`getNote` が版を返すようになったら」は、本 PR で `NoteDetailView.version`（`packages/core/src/application/note/view.ts:76`、`spec/usecases/note.md:115`）が入り、詳細島（`initialVersion`）も一覧の行（`NoteRowView.version`）も版を持ち回るようになった時点で前提が偽になっている。楽観ロックが「あるように見えて無い」状態を避ける、と JSDoc 自身が書いている以上、版を渡すか、渡さない理由を現在の事実で書き直す必要がある。(b) `renderWorkspaceNoteEditor` は「非メンバーが URL を直接開けば `NOTE_NOT_FOUND` に落ちる（TC-28 手順 3）」と引くが、`spec/manual-tests/editing.md` の TC-28 手順 3 は本 PR で「編集する権限がない旨だけが表示され…『見つかりません』にはならない」に書き換わっており、引用先が逆の挙動を述べている
  - 提案: (a) 詳細島と一覧の行が持つ版を `moveNoteSchema` に `expectedVersion` として載せて `moveNote` へ渡すか、少なくとも JSDoc を「版は届いているが移動は版を取らない（理由）」の形に直す。(b) 引用を「非メンバーは `getNote` が `NOTE_NOT_FOUND` を返す」だけにし、TC-28 への参照を外す（手順 3 は viewer の話である）

- **[W-003]** テストの JSDoc に修正の経緯が残っている
  - 場所: `apps/web/app/components/note/__tests__/schema.test.ts:101-106`（「While the two numbers were equal, ED-03's refusal came back as a transport shape violation instead」）
  - 理由: 「以前は同じ値で、そのとき壊れていた」という過去の状態の記述であり、現在の規則（転送上限はサニタイズ前の生 HTML に掛かり、ドメインの上限より緩い）だけを書けば十分（CLAUDE.md「Default to no comments … the WHY」、`doc-style` の言い切り）
  - 提案: 「The transport bound measures raw HTML and the domain's 800 KB measures the sanitized body, so the transport bound stays above the domain's」で止める
