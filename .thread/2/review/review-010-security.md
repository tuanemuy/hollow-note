- **主体の取り方**: `apps/web/app/routes/settings/-action.tsx` の 13 本の server function すべてが `requireSession()` を通し、`userId` / `subjectId` を要求本文から取らない。唯一の例外 `getDeletionStatusFn` は検証済み ticket の `operationId` だけを使い（要求本文の `operationId` を受け取る口が存在しない）、`getAccountDeletionStatus` は読み取りビュー `Pick<DistributedOperationStore,"findByOperationId">` 経由の 1 件返しで、列挙もスキャンも無い。`uploadAvatarFn` → `storeAvatar` は `input.subjectId !== userId` を弾き、`removeIdentityFn` → `removeIdentity` は自分の identity 一覧からしか対象を引かず、receipt 経路も `receipt.userId === userId` を検査してから成功に畳む（他人の receipt は `IDENTITY_NOT_FOUND` に収束）。
- **scope write の 2 本**: `assertWritable` / `assertActorWritable` は `storeAvatar` / `recalculateStorageUsage` / `createBlankNote` の全 scope write 入口で呼ばれ、cleanup 経路（`deleteFilesByOwner` / `deleteQuota`）は `assertOwner` を通る。呼び漏れは無い。
- **OAuth**: `state` は `secureTokenGenerator` 由来で `take` が atomic な単回消費、intent の分岐根拠は保存済み `OAuthFlowState.intent` のみ、パスの `:provider` は保存値との照合にしか使わない。PKCE は両アダプターとも `deriveCodeChallengeS256`（`base64url(sha256)`）+ `code_challenge_method=S256`。`redirectTo` は `SameOriginPolicy.isSameOriginPath`（`//`・`\`・C0/DEL を全部落とす）を通り、コールバック画面の `router.history.push` にはその値しか流れない。Google の `id_token` は `iss` / `aud` / `exp` / `sub` / `email` を検証し、`email_verified === true` でなければ `AccountLinkingPolicy` が自動リンクを拒否する（既存利用者が `pending` / `deleting` / `deleted` のときも拒否）。束縛 Cookie は照合が通ったときだけ破棄し、`clearBoundOAuthStateCookie` は一致しない Cookie を捨てない。
- **トークン**: セッション / 確認 / 再設定はすべてハッシュ保存 + `locateUser` によるシャード引きで、平文比較は無い。`resetPassword` は purpose / status / `authEpoch` / 利用者 status を全部 `AUTH_TOKEN_NOT_FOUND` に畳み、期限は `AuthToken.consume` が見て、単回消費は pending 行への条件付き更新で担保する。削除 ticket は HMAC-SHA-256 を `crypto.subtle.verify`（定数時間）で検証し、**署名検証の後にだけ**期限を見る。鍵は composition root 供給、版は平文前置でも鍵は出ない。
- **セッション**: 全 Cookie が `HttpOnly` / `SameSite=Lax` / `Path=/` / `Secure`（成果物で確認済み）。一括失効は `authEpoch` バンプで O(1)、現端末の存続は `refreshAuthEpoch` 1 行。`signOut` は GET を持たず（`spec/adr/030`）、`requireSession` は読み取り専用で無効 Cookie を消さない。
- **アップロード / 配信**: MIME はバイト署名（PNG / JPEG / WebP）から、サイズは実バイト長から決まり、申告値は使わない（`UploadValidationPolicy.ensureAcceptable`）。転送境界 8 MB → ドメイン 5 MB の二段で、本文サイズ上限は `scripts/listen.node.ts` の 12 MB（`Content-Length` 判定 + chunked のストリーム打ち切り → 413）が転送境界の手前で切る。`/storage/$` は `ObjectKey.create`（`..` / 先頭 `/` を拒否）+ `purposeOf(key) === "avatar"` の purpose ガードを持ち、`nosniff` / `Content-Security-Policy: sandbox; default-src 'none'` / `Cache-Control: private` / サニタイズ済み `filename` を返す。
- **情報漏洩**: `errorResponseMiddleware` は `system` / `unknown` のみログに出し、クライアントへは `redactForClient` で `code: null` / 固定文言に潰す。UI 文言は `renderErrorMessage` が **code 辞書 / kind 辞書からしか引かない**ので、サーバー由来の生 `message`（`Unknown OAuth provider: …` のような反射文字列を含む）が画面に出る経路は無い。`reservationOperationId` は生キー（メール / ハンドル / provider account id）を含むが、ログに出るのは `{ parentOperationId, kind }` だけで、`uniqueness.ts` / `updateProfile.ts` の該当箇所すべてでその規律が守られている。`ListIdentitiesView` にパスワードハッシュは無く、`AuthenticatedUserView` にメールアドレスは無い。`resendVerificationEmail` / `requestPasswordReset` は全経路で同一の空応答。
- **CSRF**: `app/start.ts` が `createCsrfMiddleware({ filter: handlerType === "serverFn" })` を明示再登録しており、`FormData` を受ける `uploadAvatarFn` もハンドラー到達前に同一オリジン照合を通る。
