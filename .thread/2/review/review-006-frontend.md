## Warnings

- **[W-001]** ネイティブ `<dialog>` の Esc による閉じを塞いでいないので、パスワード追加の送信中に Esc を押すと失敗文言が閉じたダイアログの中に出て、その場では利用者に届かない / 場所: `apps/web/app/components/settings/AddPasswordForm/index.tsx:69-73`（`<dialog … onClose={onClose}>` に `onCancel` が無い）+ `:52-64`（`useActionState` が失敗文言を自分の中に持つ）/ 理由: 追加はリスト増減なので送信と楽観的状態は親（`IdentityList/board.tsx`）が持っているが、**失敗の表示だけが子のダイアログ側に残っている**。「やめる」ボタンは `disabled={isPending}` で送信中の離脱を塞いでいるのに、Esc は塞いでいないため、送信中に Esc → `close` → `onClose` → 親の `setAdding(false)` でダイアログが display:none になり、その後に届いた `addPasswordFn` の失敗が不可視の要素に描かれる。楽観行も戻るので、画面上は「何も起きなかった」ように見える（親の `listError` は追加経路では設定されない）。CLAUDE.md が削除について言う「楽観的除去が leaf をアンマウントするので leaf 側のエラー UI は失われる」と同型の穴が、追加側で「ダイアログの閉じ」として残っている / 提案: `onCancel={(e) => { if (isPending) e.preventDefault(); }}` で送信中の Esc を塞ぐ（「やめる」の `disabled` と規律を揃える）か、追加の失敗も親の `listError` に載せてリスト側の常設 live region に出す。実害は限定的（ダイアログを開き直せば `error` state は残っているので文言は読める）なので Warning に留める。

## 確認した観点（所見なし）

- **三層規律 / 所有権**: リスト増減（`removeIdentity` / `addPasswordIdentity`）は `IdentityList/board.tsx` の親 island が `useOptimistic` ごと所有し、解除は leaf に無い。リストを変えない `ChangePasswordForm` / `SignOutOthersPanel` は葉が自分の server function と pending / エラーを持つ。P-21 の保存は `useActionState`、アイコン差し替えは `useTransition` + `useOptimistic`、P-25 の実行は `useActionState`。`canRemove` を楽観リストから引き直しているのも正しい（サーバーの `removable` は解除前の集合に対する判定）。
- **`router.invalidate()` 再整合**: 保存 / アイコン更新 / 解除 / パスワード追加 / パスワード変更 / 他端末サインアウト / リセット成功 / OAuth コールバック成功のすべてで呼ばれている。P-25 だけが意図的な非呼び出しで、理由（ローダーが `UNAUTHENTICATED` で落ちて進捗表示ごと消える）が JSDoc にある。
- **ローディングフォールバック**: `/settings/{profile,auth,usage}` は loader が未解決 promise を転送する per-fragment streaming で、`Suspense` + 専用スケルトン。`/settings/danger` はサーバー状態を読まないので loader を持たず、島を直接描く。route-level pending と混ざっていない。スケルトンは実 DOM のパネル構成・行数・ボタン寸法をおおむね写している。
- **`__root.tsx` の副作用 import**: `createServerFn` を含む全モジュール（`components/auth/*/action.ts`, `layout/AccountMenu/action.ts`, `note/CreateNoteButton/action.ts`, `routes/{auth,dev,settings}/-action`）が網羅されている。`presentation/auth.ts` と `routes/notes/-action.tsx` はルートファイル経由で登録済み。漏れなし。
- **入力バリデーション 2 点**: 転送境界は `validateSearch`（`reset-password` / `auth/callback.$provider` / `dev/oauth/authorize`）と `validator(validateInput(...))` のみ。業務不変条件（表示名 50 / 自己紹介 500 / ハンドル 3〜30 / UUID の `requestId` / 5 MB）は値オブジェクト・ポリシー側に残し、転送側は形と DoS 上限（`+1` 余裕・8 MB）だけ。`serverData`（`loadProfile` / `loadIdentities` / `loadUsageSnapshot`）に渡る `userId` はすべて `requireSession()` 由来で、要求本文からは取っていない。
- **見送り行の非表示**: `PAGE-p21-004`（公開プロフィール preview）、`PAGE-p24-002`（workspace 追加読込）、`PAGE-p25-004`（唯一 owner）のいずれも要素・placeholder ともに出ていない。P-20 は 4 タブ、P-22 は「再認証要求」なし、いずれも縮退どおり。
- **アクセシビリティ / 文言**: 文言はすべて `errorDisplay` の辞書経由（新規 30 コードは実在の `code` と一致することを突き合わせ済み）。ラベルは `useId` で関連付け、`aria-invalid` は該当欄のみ、live region は常設で余白だけ条件付き（`not-empty:` / `empty:hidden`）。焦点移動は「操作直後にパネルが差し替わる」3 箇所（P-04 の `Result`、P-05 の待機、P-25 の `DeletionProgress`）に限定され、P-25 は `key` で `accepted`/`running` を畳んでいるので進捗の段階が進んだだけでは焦点が飛ばない。日付は `Intl.DateTimeFormat` に `timeZone: "UTC"` を明示してハイドレーション不一致を回避（`IdentityBoard.formatDate` / `UsagePanel`）。`ResendVerificationForm` のカウンターは `aria-hidden` で毎秒の読み上げを抑止。`sessionStorage` 読み出しは `useEffect` 内なので SSR と食い違わない。
- **状態のモデル化**: `Phase` / `SaveState` / `SaveError` / `HandleHint` / `SubmitError` / `Outcome` がいずれも直和で、`switch` が網羅している。`passwordStrength` は純関数化して 3 画面で共有し、ドメインの `PlainPassword` と一致することを `passwordStrength.test.ts` が突き合わせている。`readStoredTicket` は `sessionStorage` の JSON を境界でデコードし、`userId` 一致まで見て他人の削除進捗を復元しない。`devOAuth` / `oauthStateBinding` / `deletionTicket` はフレームワーク非依存の純関数に切り出され、単体テストと配線テスト（`oauthStateBindingWiring.test.ts` が Cookie の実ヘッダーで順序を固定）が付いている。
- **デザイントークン**: `panelStyles.ts` / `formStyles.ts` の recipe 経由で、色・半径・寸法はすべて `styles/tokens.css` のトークン。生の色は既存踏襲のアバターのグラデーション 2 色のみ。
- **テストによる担保**: `vitest` の環境が `node` で DOM テスト基盤を持たないため、島の挙動はユニットテストではなくマニュアルテスト（AC-30）が受け持つ既存方針どおり。presentation の純粋部分（ticket 署名・期限、dev リダイレクトの同一オリジン、state 束縛と server function 内の順序）はテストで固定されている。
