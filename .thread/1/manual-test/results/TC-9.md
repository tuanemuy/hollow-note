# TC-9: 段階待機（THROTTLED）とロック（LOCKED）の状態分離

**結果**: PASS
**対応する受け入れ基準**: AC-9、AC-16（P-02）、AC-15（429）

## 使用アカウント（本テストで新規作成）

- `lockme@example.com` / `Passw0rd123` / 表示名 `Lock Me` — サインアップ + メール確認済み・Active。**本テストで LOCKED 状態にした（解除は 8月10日 19:11 頃）**
  - user-a をロックすると後続テストが実施できなくなるため、手順書の「新しいメールアドレスでサインアップ + メール確認まで済ませたテストユーザー（またはユーザー A）」のうち前者を選択した
- 復帰確認のみ `user-a@example.com` を使用（TC-8 で 1 回失敗記録あり）

## 確認ポイント

- ロック中の「パスワード再設定への導線」は文言のみ（「パスワードを再設定すると、待たずに使えるようになります。」）でリンクは無い。**P-04 は本スライス外の縮退のため失敗ではない**（手順書の注記どおり）。
- HTTP ステータスは資格情報エラーが 422、待機中・ロック中が 429 で分離されている。

## 観察（軽微・失敗とはしない）

- 待機アラート内の `aria-hidden` なライブカウンタ「（あと N 秒）」が、**表示直後の 1 秒間だけ実際の待機秒数より大きい値**を出す（例: 「約 1 秒お待ちください。（あと 17 秒）」「約 2 秒…（あと 87 秒）」）。`SignInForm`（`apps/web/app/components/auth/SignInForm/index.tsx`）の `now` がマウント時の `Date.now()` のまま据え置かれ、1 秒周期のインターバルが初回発火するまで更新されないため。1 秒後には正しい残秒数に補正され、権威的な文言「約 N 秒お待ちください。」は常に正しい値だったため PASS 判定を維持した。
