# EDGE-2: 使用済み・無効な確認リンク

**結果**: PASS
**目的**: 確認トークンの再利用・改竄が拒否されること（AC-17）

## 実行ログ

| # | 操作 | 期待結果 | 実際の結果 | 判定 |
|---|------|---------|-----------|------|
| 1 | TC-3 で使用済みの確認 URL（`/verify-email?token=MDE5ZmViMGEt….eMV4RlETJqr_PxOK03fpfmLhb8D3ZcAue1xnoWpcwg8`、user-a）をもう一度開く | `/notes` へ遷移せず、確認ページ上に使用済みである旨の状態が出る | URL は `/verify-email?token=…` のまま（`/notes` への遷移なし）。見出し「このメールアドレスは確認済みです」／本文「すでに確認が完了しています。そのままサインインしてください。」＋「サインインへ」リンク | PASS |

## 補足

- 使用済み（ALREADY_VERIFIED、POST 200）と無効 / 改竄（NOT_FOUND、POST 404）は画面文言が分かれるが、どちらも「`/notes` へは行かせない・セッションを発行しない」という要件は満たしている。使用済みトークンの再利用でユーザーが再アクティベートされることもない。
- 改竄トークン（実在する ID 部 + 偽署名）と完全に出鱈目なトークンが同一表示・同一ステータスに収斂しており、トークン ID の実在有無は判別できない。
