# TC-11: 他人のノートへのアクセス収斂（NOTE_NOT_FOUND → P-46）

**結果**: PASS
**対応する受け入れ基準**: AC-13、AC-19（P-46）

## 使用アカウント（本テストで新規作成）

- `user-b@example.com` / `Passw0rd123` / 表示名 `User B` — サインアップ + メール確認済み・Active・ノート 0 件（セッション `verify-b3`）
- 対象: ユーザー A のノート `/notes/019feb0e-e2a8-7703-b022-9a8f8745dafd`（TC-4 で作成）

## 実行ログ

| # | 操作 | 期待結果 | 実際の結果 | 判定 |
|---|------|---------|-----------|------|
| 1 | 別セッション（`verify-b3`）で `user-b@example.com` をサインアップ + 確認リンクを同一ウィンドウで開く | サインイン状態になる | `/notes` へ着地、「0 件のノート」「最初のノートを作る」の空状態 | PASS |

## 観察（失敗ではない）

- P-46 の NOT_FOUND バリアントには「再試行」ボタンが無く、導線は「ノート一覧へ」「トップへ」の 2 つ。`ErrorState` の実装（`apps/web/app/components/ui/ErrorState/index.tsx`）では「再試行」はサーバーエラーバリアント（`ServerErrorState`）に置かれており、見つからない場合に再試行を出さないのは意図的な設計。手順書の「安全な再試行とトップ / 一覧への導線」は P-46 全体の説明として読み、収斂性（手順2 と手順3 の同一性）と導線の動作を合格条件として判定した。
